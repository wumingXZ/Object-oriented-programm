## 〇、C 语言回顾：C 的类型系统

> **为什么要从 C 看起？** C++ 保留并扩展了 C 的类型系统。理解 C 的局限，你才能明白 C++ 为什么要引入 `bool`、`wchar_t`、`constexpr` 这些新类型和关键字——每一项改进都在解决 C 的历史遗留问题。
>
> 注意四个关键痛点，稍后在 C++ 特性中会逐一看到解决方案：

```c
// C 语言的基本类型
int    i = 42;        // 整数
double d = 3.14;      // 浮点
char   c = 'A';       // 字符
long   l = 100000L;   // 长整数
float  f = 2.718f;    // 单精度浮点

// C 的问题：
// 1. 类型大小依赖平台（int 在 16 位机器上是 2 字节，32 位是 4 字节）
// 2. 隐式转换容易出错（signed ↔ unsigned）
// 3. 没有真正的布尔类型（C99 才有 _Bool）
// 4. 常量只能用 #define 或 const 变量（const 变量不能用于数组大小）
```

> **C++ 的改进：** （1）用 `sizeof` 检查类型大小，不依赖假设；（2）用 `static_cast` 显式转换替代隐式转换；（3）`bool` 是真正的内置布尔类型；（4）`constexpr` 提供了真正的编译期常量。

## 一、基本内置类型

### 1.1 算术类型速查

| 类型 | 含义 | 最小尺寸 | 通常尺寸 |
|---|---|---|---|
| `bool` | 布尔 | — | 1 byte |
| `char` | 字符 | 1 byte | 1 byte |
| `wchar_t` | 宽字符 | — | 2/4 bytes |
| `char16_t` | Unicode (C++11) | — | 2 bytes |
| `char32_t` | Unicode (C++11) | — | 4 bytes |
| `short` | 短整数 | 2 bytes | 2 bytes |
| `int` | 整数 | 2 bytes | 4 bytes |
| `long` | 长整数 | 4 bytes | 4/8 bytes |
| `long long` | 长长整数 (C++11) | 8 bytes | 8 bytes |
| `float` | 单精度浮点 | — | 4 bytes |
| `double` | 双精度浮点 | — | 8 bytes |
| `long double` | 扩展精度 | — | 8/16 bytes |

> **上表中"最小尺寸"和"通常尺寸"的区别：** C++ 标准只规定了每种类型的最小尺寸（确保可移植性），但不强制具体字节数。"通常尺寸"取决于你的平台和编译器。在 x86-64 架构上，`int` 是 4 字节，但某些嵌入式平台上 `int` 仍可能是 2 字节。
>
> **为什么要用 `sizeof`？** 写可移植代码时，不要假设 `int` 就是 4 字节。用 `sizeof` 可以确认当前平台上各类型占用的真实字节数：

```cpp
cout << "bool:        " << sizeof(bool)         << " bytes" << endl;
cout << "char:        " << sizeof(char)         << " bytes" << endl;
cout << "wchar_t:     " << sizeof(wchar_t)      << " bytes" << endl;
cout << "short:       " << sizeof(short)        << " bytes" << endl;
cout << "int:         " << sizeof(int)          << " bytes" << endl;
cout << "long:        " << sizeof(long)         << " bytes" << endl;
cout << "long long:   " << sizeof(long long)    << " bytes" << endl;
cout << "float:       " << sizeof(float)        << " bytes" << endl;
cout << "double:      " << sizeof(double)       << " bytes" << endl;
cout << "long double: " << sizeof(long double)  << " bytes" << endl;
```

> 在上表中你会看到，同一平台上 `long` 和 `long long` 可能是相同的 8 字节，而 `int` 是 4 字节。这就是"最小尺寸"和"通常尺寸"不一致的活证据——标准规定 `int` 至少 2 字节，但主流平台都给了 4 字节。

### 1.2 有符号和无符号

> **为什么会有 signed 和 unsigned 的区分？** 在内存中，一个整数的二进制位是固定的（比如 `int` 占 4 字节 = 32 位）。如果把这 32 位全部用来表示正数（0 ~ 4,294,967,295），就是 unsigned；如果拿出一位表示正负号（−2,147,483,648 ~ 2,147,483,647），就是 signed。前者不能为负但正数范围大，后者正负数都能存但正数范围减半。
>
> 了解这个背景后，再看两个经典陷阱——它们曾导致无数生产环境 bug：

```cpp
// 默认 int 是有符号的
int a = -42;
unsigned int b = 42;

// ⚠️ 陷阱：有符号和无符号混用
unsigned u = 10;
int i = -42;
// 结果：先把 i 转为 unsigned → -42 变成 4294967254
// 然后：10 + 4294967254 = 4294967264

// ⚠️ 陷阱：无符号数的循环中注意
for (unsigned k = 10; k >= 0; --k) {
    // 这会导致无限循环！k 永远不会小于 0
    break;  // 演示用，实际不要写这种循环
}
```

> **第一个陷阱的根源：** 当 signed 和 unsigned 出现在同一个表达式中时，C++ 的"隐式转换规则"会把 signed 转为 unsigned。`-42` 转成 unsigned 就变成了 `2³² - 42` —— 一个非常大的正数。
>
> **第二个陷阱的根源：** `unsigned` 类型永远不小于 0。`k >= 0` 永远为 true，循环永远不会结束。
>
> **经验法则：不要在同一个表达式里混用 signed 和 unsigned 类型。** 如果必须用 unsigned（比如容器大小 `size_t`），循环条件避免使用 `k >= 0`——改用 `k > 0` 或 `for (auto i = v.size(); i > 0; --i)`。

### 1.3 字面量（Literals）

> **什么是字面量？** 字面量就是直接在代码里写死的值——`42`、`3.14`、`"Hello"` 都是字面量。理解字面量很重要，因为**不同的后缀决定了这个值的类型**，而类型选择错误会导致精度损失或意外的计算结果。
>
> 比如你写 `3.14`，编译器默认把它当作 `double`（8 字节的浮点精度）。如果你想要 `float`（4 字节）来节省内存，就必须加 `f` 后缀写成 `3.14f`。下面列出各种字面量的写法：

```cpp
// 整数字面量
int    dec = 42;      // 十进制
int    oct = 052;     // 八进制（前缀 0）
int    hex = 0x2A;    // 十六进制（前缀 0x）

// 浮点字面量
double d1 = 3.14;     // 默认 double
float  f1 = 3.14f;    // 后缀 f/F → float
long double ld = 3.14L; // 后缀 l/L → long double

// 字符和字符串
char   c  = 'A';      // 单引号 → 字符
const char* s = "Hello"; // 双引号 → 字符串（以 \0 结尾）

// C++11: 原始字符串（raw string literal）
const char* raw = R"(路径是 C:\Users\name\)";
```

> **常见的后缀速查：**
> - `u` / `U` → `unsigned`（如 `42u`）
> - `l` / `L` → `long`（如 `100000L`）
> - `ll` / `LL` → `long long`（如 `10000000000LL`）
> - `f` / `F` → `float`（如 `3.14f`）
> - `l` / `L` 用于浮点 → `long double`
>
> **C++14 新增的二进制字面量：** `0b00110101` 可以直观地表示二进制位模式，在位运算（补充 10）中非常实用。
>
> **原始字符串 `R"(...)"`** 解决了传统字符串中转义符过多的问题。正则表达式和 Windows 路径是它的典型使用场景——不需要写 `\\` 来表示反斜杠。

## 二、变量和初始化

### 2.1 C++11 的列表初始化

> **为什么 C++11 要新增花括号初始化？** 因为 C++98 的初始化方式存在一个严重缺陷——**窄化转换（narrowing conversion）**。当你用一个 `double` 初始化一个 `int` 变量时，编译器不会报错，只会静默截断小数部分。这种"静默丢失精度"是很多隐蔽 bug 的源头。C++11 的花括号初始化解决了这个问题。

```cpp
// 四种初始化方式
int a = 0;       // 传统赋值初始化
int b(0);        // 构造函数初始化
int c = {0};     // C++11 列表初始化（带等号）
int d{0};        // C++11 列表初始化（不带等号）

// 列表初始化的好处：窄化转换会报错
double pi = 3.14159;
// int e{pi};   // ❌ 编译错误！double → int 窄化
int e(pi);       // ✅ 但会静默截断为 3（危险！）

// 推荐：始终用花括号初始化
vector<int> v{1, 2, 3, 4, 5};
string s{"hello"};
```

> **初始化方式选择指南：**
> 1. **花括号初始化** `int x{0}` 是最安全的选择——它禁止窄化转换
> 2. **圆括号初始化** `int x(0)` 可以用于构造函数，但对内置类型不阻止窄化
> 3. **等号赋值** `int x = 0` 是 C 语言的遗留风格，简洁但同样允许窄化
>
> 不过有一个陷阱需要注意：`vector<int> v{2, 5}` 会创建包含元素 {2, 5} 的 vector，而不是创建有 5 个元素、每个都是 2 的 vector。花括号初始化的"初始化列表"语义优先于"构造函数"语义。

### 2.2 声明 vs 定义

> **为什么需要区分"声明"和"定义"？** 因为在大型项目中，一个变量或函数需要在多个 `.cpp` 文件中使用。每个 `.cpp` 文件编译时都需要知道这个变量的"名字和类型"（声明），但整个程序只能有一个地方"真正分配内存"（定义）。这就是 C++ 的 **ODR（单一定义规则，One Definition Rule）**——定义只能出现一次，声明可以出现多次。

```cpp
// 声明（declaration）：告诉编译器类型和名字，不分配空间
extern int global_var;  // extern 表示"定义在别处"

// 定义（definition）：分配存储空间
int global_var = 42;    // 这是定义（也是声明）
```

| | 声明 (Declaration) | 定义 (Definition) |
|---|---|---|
| 作用 | 引入名字 | 分配空间 |
| 关键字 | `extern` | 没有 `extern` 或有初始化 |
| 可出现次数 | 多次 | 一次（ODR：单一定义规则） |

> **ODR 违例的后果：** 如果你在多个文件中都定义了同一个全局变量，链接器会报"重定义"错误。这也是头文件中通常只放声明而不放定义的原因——头文件可能被多个 `.cpp` 文件包含，导致重复定义。

## 三、`const` 限定符

### 3.1 基本用法

> **`const` 解决了什么问题？** 在 C 语言中，常量要么用 `#define` 宏（没有类型检查，容易出问题），要么用 `const` 变量（但不保证编译期求值）。C++ 的 `const` 提供了**带类型的编译期常量**——既有类型安全检查，又能用于数组大小等需要编译期确定值的地方。
>
> 不过这里有一个微妙的行为需要理解：

```cpp
const int bufSize = 512;  // bufSize 是常量，不可修改
// bufSize = 256;         // ❌ 编译错误！

// const 变量默认只在当前文件可见
// 如果要跨文件共享，定义时加 extern：
// extern const int sharedConst = 100;

// const 可以用于编译期常量
int arr[bufSize];         // ✅ bufSize 是编译期常量
```

> **`const` 的跨文件可见性规则：** C++ 中，`const` 变量的作用域默认为"当前文件"，而不是全局可见。这是为了允许在头文件中定义 `const` 变量而不会导致多重定义错误。如果需要跨文件共享，必须显式加上 `extern`。

### 3.2 `const` 的引用

> **为什么需要 `const` 引用？** 函数参数传递是 `const` 引用的最主要场景。当你传一个大型对象（如 `string`）到函数时，传引用比传值高效（避免拷贝），但你不想在函数内部意外修改原始数据。`const T&` 就是"只读视图"——高效且安全。
>
> `const` 引用还有一个普通引用不具备的能力：**临时对象绑定**。

```cpp
int i = 42;

// 对 const 的引用（reference to const）
const int &r1 = i;       // 可以通过 r1 读 i，但不能通过 r1 改
const int &r2 = 42;      // ✅ const 引用可以绑定到字面量
const int &r3 = r1 * 2;  // ✅ const 引用可以绑定到表达式

// int &r4 = 42;         // ❌ 普通引用不能绑定到字面量

// 修改原变量，const 引用跟着变
i = 100;
```

> **为什么 `const T&` 可以绑定到字面量，而 `T&` 不行？** 普通引用意味着"我有权修改这个对象"，但字面量（如 `42`）没有内存地址，不存在可修改的对象。`const T&` 则只是"我只需要读它"，编译器会为字面量创建一个临时对象，让引用指向它——这保证了语义一致性。

### 3.3 顶层 `const` vs 底层 `const`

> **为什么要区分"顶层"和"底层"？** 指针有一个复杂之处：`const` 可以修饰指针本身（"这个指针变量不能再指向别处"），也可以修饰指针指向的对象（"不能通过这个指针修改对象"），或者两者同时。这两个概念完全不同，但在代码中仅凭 `const` 的位置来区分。理解"顶层"和"底层"能帮你读懂任何复杂的指针声明。

```cpp
// 顶层 const：指针本身是常量
int i = 42;
int *const p1 = &i;       // p1 是 const 指针（顶层 const）
*p1 = 100;                // ✅ 可以通过 p1 修改 i
// p1 = nullptr;          // ❌ 不能修改 p1 本身

// 底层 const：指向的对象是常量
const int *p2 = &i;       // p2 指向 const int（底层 const）
// *p2 = 200;             // ❌ 不能通过 p2 修改
p2 = nullptr;             // ✅ 可以修改 p2 本身

// 同时有顶层和底层 const
const int *const p3 = &i; // 指针和对象都是 const
```

| 术语 | 含义 | 示例 |
|---|---|---|
| 顶层 const | 对象本身是 const | `int *const p` |
| 底层 const | 指向/引用的对象是 const | `const int *p`, `const int &r` |

> **快速判断技巧：** 读声明时从右往左读。`int *const p` → "p is a const pointer to int"（顶层）。`const int *p` → "p is a pointer to const int"（底层）。`auto` 的类型推导规则（后文会讲）默认忽略顶层 const 但保留底层 const，这也是为什么区分两者在实际编码中很重要。

### 3.4 `constexpr` — 真正的编译期常量（C++11）

> **`const` 还不够吗？** 虽然 `const` 能定义常量，但它并不保证编译器在编译期就能计算出值——它只承诺"运行时不要修改"。当你需要真正的编译期常量（比如数组大小、模板非类型参数）时，需要 `constexpr`。它的核心特性是：**强制在编译期求值**。

```cpp
// constexpr 函数在编译期求值（如果参数是常量表达式）
constexpr int square(int x) { return x * x; }

// constexpr 可以用于数组大小
constexpr int SIZE = 100;

constexpr int mf = 20;            // 编译期常量
constexpr int limit = mf + 1;     // 编译期计算
constexpr int sq = square(5);     // 编译期函数求值

int arr1[SIZE];                   // ✅
int arr2[square(3)];              // ✅ 3*3 = 9
```

> **`const` vs `constexpr` 对比：**
>
> | | `const` | `constexpr` |
> |---|---|---|
> | 初始化时机 | 编译期或运行时 | 编译期 |
> | 修饰函数 | 不可以 | 可以（编译期求值） |
> | 修饰变量 | 保证不修改 | 保证编译期常量 |
> | 数组大小 | 取决于编译器实现 | 一定可以 |
> | 推荐度 | 一般情况 | 能编译期算的都用 `constexpr` |
>
> **为什么 `square(5)` 可以在编译期求值？** 因为参数 `5` 是编译期常量。如果参数在运行时才能确定（比如来自用户输入），`constexpr` 函数退化为普通函数，在运行时执行。这种"既能在编译期算，也能在运行时算"的双重能力，是 `constexpr` 的设计精髓。

## 四、类型别名和类型推导

### 4.1 类型别名（Type Alias）

> **为什么需要类型别名？** 三个原因：（1）给复杂类型起一个简短的别名，提高代码可读性（如 `StrVec` 比 `vector<string>` 短）；（2）封装具体类型，方便未来修改（只用改一处别名定义）；（3）C++11 的 `using` 别名甚至支持模板——这是 `typedef` 做不到的。

```cpp
// 传统方式：typedef
typedef double wages;       // wages 是 double 的同义词
typedef wages base, *p;    // base = double, p = double*

// C++11 方式：using 别名声明（更清晰）
using SI = int;             // SI 是 int 的别名
using StrVec = vector<string>;  // 模板别名

wages salary = 5000.5;
SI count = 10;

// 指针和 const 的别名陷阱
typedef char *pstring;
const pstring cstr = nullptr;  // cstr 是 char *const（顶层 const）
// 等价于：char *const cstr = nullptr;
// ⚠️ 不是：const char *cstr = nullptr;
```

> **指针别名陷阱详解：** 当 `pstring` 是 `char*` 的别名时，`const pstring` 被理解为"`pstring` 类型的 `const` 版本"——即 `char* const`（顶层 const，指针自身不可变）。这是**类型别名替换的逻辑**，不是简单的文本替换。初学者常误以为 `const pstring` 等于 `const char*`，但后者是底层 const（指向的内容不可变）。两者完全不同。

### 4.2 `auto` — 让编译器推导类型（C++11）

> **`auto` 解决的核心痛点：** 在 C++98 中，迭代器的类型声明冗长且难以书写——`vector<int>::iterator it = v.begin()`。一旦容器类型变化，所有迭代器声明都得改。`auto` 让编译器替你写类型，代码更简洁、更易维护。而且它和模板、泛型算法是天作之合——因为模板代码中你根本不知道变量的具体类型。

```cpp
// auto 从初始化表达式推导类型
auto i = 42;           // int
auto d = 3.14;         // double
auto s = string("hi"); // string

// auto 会忽略顶层 const 和引用
const int ci = 42;
auto a = ci;            // a 是 int（顶层 const 被忽略）
const auto b = ci;      // b 是 const int（显式加回 const）
auto &c = ci;           // c 是 const int&（引用保留底层 const）

// 最实用的场景：简化迭代器类型
vector<int> v{1, 2, 3, 4, 5};
for (auto it = v.begin(); it != v.end(); ++it) { }

// C++11: range-based for + auto
for (auto &x : v) {
    x *= 2;  // 修改元素值
}
```

> **`auto` 的四条推导规则：**
> 1. 忽略顶层 const：`const int` 被 `auto` 推导为 `int`
> 2. 忽略引用：`int &` 被 `auto` 推导为 `int`
> 3. 例外——`auto &` 保留底层 const：如果原对象带底层 const（如 `const int&`），`auto &` 推导为 `const int&`
> 4. 例外——`const auto` 显式加回顶层 const
>
> **使用建议：** 当类型在上下文中一目了然时，用 `auto`；当类型不明确时需要斟酌——`auto result = some_func()` 会让读者去查函数签名。`auto` 不等于"不写类型"，而是"让类型推导正确且简洁"。

### 4.3 `decltype` — 获取表达式的精确类型（C++11）

> **有了 `auto` 为什么还需要 `decltype`？** `auto` 适合推导变量的类型，但有两个场景它无能为力：（1）**函数返回类型**需要根据参数类型推导（如 `t + u` 的类型），但返回类型写在参数列表之前——C++11 用"尾置返回类型"解决这个问题；（2）**需要保留引用和 const 属性**时（`auto` 会去掉它们）。这两个场景正是 `decltype` 的用武之地。

```cpp
// decltype 用于无法确定返回类型的模板函数
template <typename T, typename U>
auto add(T t, U u) -> decltype(t + u) {  // 尾置返回类型
    return t + u;
}

int i = 42;
const int &r = i;

decltype(r) dr = i;     // dr 是 const int&（保留顶层 const 和引用）
// decltype(r) d2;      // ❌ 引用必须初始化

decltype(i) di;         // di 是 int（i 是普通变量）

auto result = add(3, 4.5);  // result 是 double
```

> **`auto` 和 `decltype` 的配合：** `add` 函数中 `auto` 只起占位作用（告诉编译器"返回类型在后面定义"），真正的类型推导由 `-> decltype(t + u)` 完成。C++14 简化了这个过程——`auto add(T t, U u) { return t + u; }` 即可，但仍不能保留引用和 const 属性。

| 特性 | `auto` | `decltype` |
|---|---|---|
| 推导依据 | 初始化表达式的值 | 表达式的声明类型 |
| 保留顶层 const? | 默认不保留 | 保留 |
| 保留引用? | 默认不保留 | 保留 |
| 典型用途 | 变量声明 | 返回类型推导、泛型编程 |

## 五、自定义简单数据结构

> **C++11 为 struct/class 带来了什么改进？** 两个关键变化提升了编程体验：（1）**类内初始值**——成员变量可以在声明处直接初始化，这样即使某些构造函数忘记初始化某个成员，它也有一个安全的默认值；（2）**列表初始化**——可以直接用花括号给所有成员依次赋值，不需单独写构造函数。

```cpp
// C++11: 可以在类内初始化成员变量
struct Sales_data {
    string bookNo;           // 书号
    unsigned units_sold = 0; // 销量（类内初始值，C++11）
    double revenue = 0.0;    // 收入（类内初始值，C++11）
};

Sales_data item1;  // 使用类内初始值
Sales_data item2{"978-7-121", 5, 99.9};  // C++11 列表初始化
```

> **类内初始值的实际价值：** 在 C++98 中，如果你定义了一个自定义构造函数但没有初始化所有成员，那些未初始化的成员包含垃圾值（可能导致难以调试的 bug）。C++11 的类内初始值确保——即使构造函数遗漏了某些成员，它们也有默认值。这是 C++ 向"更安全"迈出的重要一步。
