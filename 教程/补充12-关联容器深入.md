- `vector` — 连续存储，索引访问 O(1)，中间插入 O(n)

## 一、`set` — 不重复元素的集合

### 1.1 基本操作

> **`set` 的设计哲学：** 它解决了"如何高效地存储不重复元素"这个核心问题。如果你用 `vector` 来做这件事，每次插入前都要 `find` 一遍来判断是否重复——O(n) 的开销。`set` 基于红黑树，插入和查找都是 O(log n)。而且元素**自动排序**——遍历 `set` 时元素会按升序出现。

```cpp
// set：元素唯一、自动排序
set<int> s{3, 1, 4, 1, 5, 9, 2, 6, 5};

// 插入（插入重复元素会被忽略）
auto result = s.insert(4);  // 已存在
result = s.insert(7);       // 成功

// 查找元素
if (s.find(5) != s.end()) {
    // 找到 5
}

// 删除元素
s.erase(3);

// count: 元素是否存在（对 set 只有 0 或 1）
s.count(5);
s.count(100);
```

> **重要细节——`insert` 的返回值：** `set::insert` 返回 `pair<iterator, bool>`。`bool` 表示插入是否成功（元素是否已存在），`iterator` 指向已存在的元素（如果重复）或新插入的元素。这个返回值在实现"插入或更新"模式时非常有用。

### 1.2 `set` 的实际应用：去重和快速查找

> **两个经典场景演示了 `set` 的核心能力：**
> 1. **用迭代器范围构造：** `set<string> unique_words(words.begin(), words.end())`——把 `vector` 中的元素传给 `set`，自动去重+排序。这是最简洁的"去重"写法。
> 2. **快速成员检查：** `stop_words.find(w) == stop_words.end()`——O(log n) 检查一个词是否属于集合。O(n) 的线性搜索在处理大集合时不可接受。

```cpp
// 场景：统计文章中出现的所有不重复单词
vector<string> words{"the", "quick", "brown", "fox",
                      "jumps", "over", "the", "lazy", "dog"};

// set 自动去重 + 按字母排序
set<string> unique_words(words.begin(), words.end());

// 排除常用词（stop words）
set<string> stop_words{"the", "a", "an", "in", "on", "over"};
for (const auto &w : unique_words) {
    if (stop_words.find(w) == stop_words.end()) {
        // 不是 stop word
    }
}
```

> **`set` 的 `find` 和 `count` 都可以用来判断元素是否存在——区别是什么？** `find` 返回迭代器，你可以进一步操作找到的元素（如从另一个容器中获取对应的值）；`count` 对 `set` 来说只有 0 或 1（因为元素不重复），更适合简单的是/否判断。

## 二、`multiset` 和 `multimap` — 允许重复键

```cpp
// multiset：允许重复元素
multiset<int> ms{1, 1, 2, 3, 3, 3, 5, 8};
ms.count(3);  // 统计出现次数

// multimap：一个键可以对应多个值
// 场景：一个作者可以有多本书
multimap<string, string> authors;

authors.insert({"金庸", "射雕英雄传"});
authors.insert({"金庸", "天龙八部"});
authors.insert({"金庸", "笑傲江湖"});
authors.insert({"古龙", "多情剑客无情剑"});
authors.insert({"古龙", "楚留香传奇"});

// 查找某个作者的所有作品
auto range = authors.equal_range("金庸");  // 返回 pair<iter, iter>
for (auto it = range.first; it != range.second; ++it) {
    // it->second 是作品名
}
```

## 三、无序容器 `unordered_map` / `unordered_set`（C++11）

```cpp
// unordered_map：基于哈希表，O(1) 平均查找
unordered_map<string, int> word_count;

// 插入和访问
word_count["hello"] = 1;
word_count["world"] = 2;
word_count["hello"]++;  // hello → 2

// unordered_set：不重复、无序
unordered_set<int> us{3, 1, 4, 1, 5, 9, 2, 6, 5};

// 哈希表统计
word_count.bucket_count();
word_count.load_factor();
```

### `map` vs `unordered_map` 对比

| 特性 | `map` | `unordered_map` |
|---|---|---|
| 底层结构 | 红黑树（平衡二叉搜索树） | 哈希表（数组+链表） |
| 元素顺序 | 按键排序 | 无序 |
| 查找 | O(log n) | O(1) 平均，O(n) 最坏 |
| 插入 | O(log n) | O(1) 平均 |
| 内存占用 | 较少 | 较多（哈希桶） |
| 何时使用 | 需要有序遍历 | 只需快速查找，不关心顺序 |

**理解哈希表（unordered_map）：** 和无序容器的关键在于"哈希函数"——它把键（比如字符串）映射成一个整数（桶号），然后在对应的桶里查找。好的哈希函数让元素均匀分布，查找接近 O(1)；坏的哈希函数让元素挤在少数桶里，退化为 O(n)。标准库已经为 `int`、`string` 等内置类型提供了高质量的哈希函数，绝大多数场景直接使用即可。

## 四、容器适配器：`stack`、`queue`、`priority_queue`

这三个不是独立的容器，而是**适配器**——它们在底层容器（默认 `deque` 或 `vector`）之上，提供受限的接口。

> **设计思想：** 适配器模式是一种经典的软件设计模式——通过限制接口，使容器的行为符合特定数据结构的要求。例如栈只暴露 `push`/`pop`/`top`，而隐藏了 `insert`/`erase`/`[]` 等底层容器的全部功能。这种"限制"实际上是一种保护——降低了误用的可能，也使代码意图更加清晰。

<a id="41-stack--栈"></a>
### 4.1 `stack` — 栈

> **栈（后进先出，LIFO）的本质：** 最后放进去的东西最先被拿出来——就像一摞盘子。`stack` 适配器在底层容器（默认 `deque`）之上只暴露了 `push`、`pop`、`top` 三个核心操作，屏蔽了数组索引、插入、删除等无关操作。**这种限制是刻意的设计**——限制了接口就等于限制了误用的可能。

```cpp
stack<int> st;

// 入栈
st.push(10);
st.push(20);
st.push(30);

st.top();    // 栈顶
st.size();   // 大小

// 出栈（后进先出）
while (!st.empty()) {
    st.pop();
}

// 实际应用：括号匹配
string expr = "((a+b)*(c-d))";
stack<char> parens;
bool balanced = true;

for (char c : expr) {
    if (c == '(') parens.push(c);
    else if (c == ')') {
        if (parens.empty()) { balanced = false; break; }
        parens.pop();
    }
}
balanced = balanced && parens.empty();
```

> **注意：** `stack` 的 `pop()` 只删除元素不返回值——这是出于异常安全的考虑（如果返回值时拷贝失败，数据就丢了）。所以需要先用 `top()` 查看，再用 `pop()` 删除。
>
> **括号匹配算法的思路：** 遇到左括号入栈，遇到右括号弹栈。如果弹栈时栈为空（右括号多了）或最后栈不为空（左括号多了），则括号不匹配。这个算法看似简单，但它是编译器语法分析的起点——所有嵌套结构的解析都遵循类似思路。

### 4.2 `queue` — 队列

> **队列（先进先出，FIFO）** 就像排队买东西——先到的人先服务。`queue` 提供了 `push`（入队）、`pop`（出队）、`front`（队首）、`back`（队尾）操作。和 `stack` 一样，`pop()` 不返回值，需要先 `front()` 查看。

```cpp
queue<int> q;

// 入队
q.push(10);
q.push(20);
q.push(30);

q.front();  // 队首
q.back();   // 队尾

// 出队（先进先出）
while (!q.empty()) {
    q.pop();
}
```

> **队列的实际应用：** BFS（广度优先搜索）、任务调度、消息队列、缓冲池处理。在操作系统中，打印任务队列就是典型 FIFO——先提交的打印任务先被处理。

### 4.3 `priority_queue` — 优先队列

> **优先队列不是"先来先服务"，而是"优先级高的先服务"。** 它内部不是简单的线性结构，而是**堆（heap）**——一种能快速找到最大（或最小）元素的数据结构。默认是大顶堆（最大元素在 `top()`），每次 `pop()` 取出当前最大的元素。

```cpp
// 默认：大顶堆（最大元素在队首）
priority_queue<int> pq;

pq.push(30);
pq.push(10);
pq.push(50);
pq.push(20);
pq.push(40);

// 出队：50 40 30 20 10
while (!pq.empty()) {
    pq.pop();
}

// 小顶堆：使用 greater<> 比较器
priority_queue<int, vector<int>, greater<int>> min_pq;

min_pq.push(30);
min_pq.push(10);
min_pq.push(50);

// 出队：10 30 50
while (!min_pq.empty()) {
    min_pq.pop();
}
```

> **`priority_queue` 的三个模板参数：** `priority_queue<T, Container, Compare>`
> - `T` — 元素类型
> - `Container` — 底层容器（默认 `vector<T>`）
> - `Compare` — 比较器（默认 `less<T>` 即大顶堆；`greater<T>` 即小顶堆）
>
> **典型场景：** 任务调度（紧急任务先处理）、Dijkstra 最短路径算法（距离最短的节点先扩展）、数据流中找 Top K 元素。注意 `priority_queue` 不提供迭代器——你不能遍历它，只能逐个弹出。

| 适配器 | 默认底层容器 | 核心操作 | 特点 |
|---|---|---|---|
| `stack` | `deque` | `push`, `pop`, `top` | LIFO（后进先出） |
| `queue` | `deque` | `push`, `pop`, `front`, `back` | FIFO（先进先出） |
| `priority_queue` | `vector` | `push`, `pop`, `top` | 按优先级出队 |

## 五、迭代器失效问题

```cpp
// ⚠️ vector：插入/删除可能导致迭代器失效
vector<int> v{1, 2, 3, 4, 5};

// 错误示范：
// for (auto it = v.begin(); it != v.end(); ++it) {
//     if (*it % 2 == 0)
//         v.erase(it);  // ❌ it 失效了！++it 是未定义行为
// }

// 正确方式：使用 erase 返回的下一个有效迭代器
for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0) {
        it = v.erase(it);  // ✅ erase 返回下一个有效迭代器
    } else {
        ++it;
    }
}

// list 的迭代器在插入/删除时更稳定
list<int> lst{1, 2, 3, 4, 5};
auto it = lst.begin();
++it; ++it;  // 指向 3

lst.push_front(0);
lst.push_back(6);

// list 的迭代器不因 push_front/push_back 而失效
// *it 仍然指向 3
```

> **迭代器失效规则速记：**
> - `vector`/`string`：插入可能导致所有迭代器失效（可能扩容），删除导致被删元素之后的迭代器失效
> - `deque`：插入在两端外可能导致所有迭代器失效，删除类似
> - `list`/`forward_list`：插入不失效，删除仅被删元素的迭代器失效
> - `map`/`set`：插入不失效，删除仅被删元素的迭代器失效

## 六、`emplace` 系列操作（C++11）

```cpp
// emplace_back 直接在容器内构造对象，避免拷贝
vector<string> v;

// push_back：先构造临时对象，再拷贝/移动到容器
string s = "hello";
v.push_back(s);         // 拷贝

// emplace_back：直接传递构造函数参数
v.emplace_back("world"); // 直接在容器内构造 string("world")
v.emplace_back(5, '!');  // 直接在容器内构造 string(5, '!')

// map 的 emplace
map<string, int> scores;
scores.emplace("Alice", 85);    // 直接构造 pair
scores.emplace("Bob", 92);
```

> **何时用 `emplace`？** 当你要往容器里"创建"一个新对象时，用 `emplace` 比 `push`/`insert` 更高效——少了一次临时对象的构造和析构。

## 七、补充总结

### 核心要点

| 知识点 | 关键结论 |
|---|---|
| `set` | 不重复 + 自动排序，适合去重和集合运算 |
| `multimap` | 允许重复键，用 `equal_range` 遍历同一键的所有值 |
| `unordered_map` | 哈希表，O(1) 查找，不保证顺序 |
| 容器适配器 | `stack`(LIFO)、`queue`(FIFO)、`priority_queue`(按优先级) |
| 迭代器失效 | `vector` 扩容导致全失效，`list` 最稳定 |
| `emplace` | 原地构造，比 `push`/`insert` 高效 |

### 选择容器的决策树

```
需要按键快速查找？
├── 是 → 需要排序遍历？
│        ├── 是 → map / set
│        └── 否 → unordered_map / unordered_set
└── 否 → 需要什么操作？
         ├── 尾部增删 → vector
         ├── 任意位置增删 → list
         ├── 两端增删 → deque
         ├── LIFO → stack
         ├── FIFO → queue
         └── 按优先级 → priority_queue
```
