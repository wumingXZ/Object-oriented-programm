## 〇、C 语言回顾：表达式和控制流

> C 语言的运算符和控制流是 C++ 的基础，但 C++ 做了大量安全性和表达力上的增强。回顾 C 的局限，是为了理解 C++ 在此基础上改进了什么。

```c
// 算术运算
int a = 10, b = 3;
int sum = a + b, diff = a - b;
int prod = a * b, quot = a / b, rem = a % b;

// 控制流
if (a > 5) { }
for (int i = 0; i < 3; i++) { }

// C 的限制：
// 1. 没有 bool 类型（C99 之前）
// 2. 没有范围 for 循环
// 3. 没有 switch 的 fallthrough 标注（C++17 有 [[fallthrough]]）
// 4. 类型转换只能用 C 风格强制转换，不安全
```

> 后文中你会看到 C++ 如何逐个解决这些问题：C++ 的 `bool` 类型、范围 `for`（range-based for）、`[[fallthrough]]` 标注、以及 `static_cast` 等四种安全类型转换。

## 一、运算符深入

### 1.1 算术、关系和逻辑运算符

> 这些运算符你在第 01 周就已经用过，但有几个容易忽略的关键细节值得注意——尤其是**短路求值**和**取模的行为**，它们是很多隐蔽 bug 的来源。

```cpp
// 算术：+, -, *, /, %, - (一元负)
int a = 5, b = 2;
// 注意：% 只能用于整数类型
// (-m) / n 和 (-m) % n 的结果依赖于实现（C++11 规定向 0 截断）

// 逻辑与和逻辑或的短路求值
int *p = nullptr;
// 短路：p != nullptr 为 false，&& 右边不会执行
if (p != nullptr && *p == 42) { }
// 短路：左边为 true，|| 右边不会执行
if (true || /*expensive_check()*/) { }

// 关系运算符：<, <=, >, >=, ==, !=
boolalpha;  // 打印 true/false 而非 1/0
```

> **为什么要理解"短路求值"？** 这是 C++ 最重要的安全模式之一。在上面的例子中，`p != nullptr && *p == 42`——如果 `p` 是空指针，左侧为 false，右侧的 `*p` 根本不会执行，从而避免了空指针解引用。这种写法是"安全检查在前，操作在后"的标准模式。
>
> **同样地，`||` 的短路**：`if (user_input || expensive_check())`——如果 `user_input` 为 true，`expensive_check` 根本不会被调用。这既是优化，也可以用来控制执行流程。
>
> **取模 `%` 的行为（C++11 规定）：** 在 C++11 之前，`(-5) / 3` 的结果在不同编译器上可能是 `-1` 或 `-2`。C++11 统一规定：除法向 0 截断，即 `(-5) / 3 = -1`（舍弃小数部分），`(-5) % 3 = -2`（满足恒等式 `(a/b)*b + a%b == a`）。

### 1.2 赋值运算符

> **赋值运算符的求值特性：** 赋值表达式的值就是它赋的那个值。这意味着 `j = 42` 这个表达式的值是 `42`，所以 `i = j = 42` 才能工作。同时，这也意味着 `if (x = 42)` **不是**比较——它把 42 赋给 x，表达式值为 42（非零，视为 true），条件永远成立。这是 C/C++ 历史上最著名的 bug 模式之一。

```cpp
// 赋值运算符是右结合的
int i, j;
i = j = 42;   // j = 42, 然后 i = j

// 复合赋值运算符
i += 5;   // i = i + 5
i -= 3;   // i = i - 3
i *= 2;   // i = i * 2

// ⚠️ 常见陷阱：赋值 vs 比较
int x = 0;
// if (x = 42)  // 把 42 赋给 x，条件永远为 true！
//     cout << "这是 bug！" << endl;
// 正确写法：
if (x == 42) { }
```

> **如何避免赋值/比较混淆？** 有些开发者习惯写 `if (42 == x)` 来防笔误——如果少写一个等号变成 `if (42 = x)`，编译器会直接报错（因为不能给字面量赋值）。但多数意见认为这损害了可读性。现代编译器（如 GCC/Clang）在 `-Wall` 下会对 `if (x = 42)` 发出警告，这才是更干净的解决方案。

### 1.3 自增/自减运算符

> **前置和后置的语义区别：** 前置 `++i` 返回的是**加完后的值**（左值），后置 `i++` 返回的是**加之前的值**（右值）。这种区别不仅仅是语义上的——内置类型的前置递增通常比后置更高效（后置需要保存一个副本用于返回）。对于自定义类型的迭代器，这种性能差异会更明显。

```cpp
int i = 0;

// 前置 ++：先加后用
++i;       // i=1

// 后置 ++：先用后加
i++;       // 输出1, i=2

// ⚠️ 不要在同一个表达式里多次修改同一个变量
// cout << i << " " << ++i << endl;  // 未定义行为！

// 建议：自增/自减单独作为一条语句
++i;   // 清晰，无歧义
```

> **为什么"多次修改同一个变量"是未定义行为？** C++ 标准规定：在两个"顺序点"之间，一个变量最多只能被修改一次。`cout << i << " " << ++i` 中 `i` 被读取（用于输出）和修改（`++i`）的顺序是不确定的——编译器可能先求值 `++i` 也可能先求值 `i`。结果是不可预测的，不同编译器、不同优化级别都可能导致不同结果。
>
> **最佳实践：** 除了一条孤立的 `++i` 或 `i++` 语句外，不要再在其他表达式中使用自增/自减。换句话说，永远不要写 `foo(i++)` 或 `arr[++i] = x`，除非你完全清楚自己在做什么。

### 1.4 条件运算符 `?:`

> **为什么需要条件运算符？** 很多场合需要根据条件选择两个值之一——`if-else` 当然可以，但不如 `?:` 简洁。核心区别是：`?:` 是**表达式**（有值），可以放在赋值号的右边；`if-else` 是**语句**（没有值），不能出现在表达式能出现的地方。

```cpp
int grade = 75;

// 条件运算符 (cond ? true_expr : false_expr)
string result = (grade >= 60) ? "及格" : "不及格";

// 可以嵌套（但不要过度嵌套，影响可读性）
string level = (grade >= 90) ? "优秀"
             : (grade >= 80) ? "良好"
             : (grade >= 60) ? "及格"
             : "不及格";

// 条件运算符的优先级很低，做输出时要加括号
// cout << "成绩: " << (grade < 60 ? "不及格" : "通过") << endl;
```

> **优先级陷阱：** `<<` 的优先级高于 `?:`，所以 `cout << grade < 60 ? "不及格" : "通过"` 会被解析为 `(cout << grade) < 60 ? "不及格" : "通过"`——语法虽然正确，但行为完全出乎意料。**任何时候在输出中使用 `?:`，请加上括号。**

> **嵌套 `?:` 的替代方案：** 嵌套两三层还能接受，超过三层建议用 `if-else if` 链或 `switch`。可读性远比代码行数重要。

### 1.5 位运算符

> **位运算符是系统编程的核心工具——** 它们操作的是内存中的每一位，常用于权限管理、图形编程、设备驱动和性能敏感的算法。理解位运算的关键是记住这张真值表：

```
a & b: 同1出1（清零特定位时使用）
a | b: 有1出1（设置特定位时使用）
a ^ b: 不同出1（翻转特定位时使用）
~a:    逐位取反
```

```cpp
unsigned char bits = 0b00110101;  // C++14 二进制字面量

// ~ 按位取反
// << 左移, >> 右移
// & 按位与, | 按位或, ^ 按位异或

unsigned char mask = 0b00001111;

// 常见用法
unsigned long quiz1 = 0;
quiz1 |= 1UL << 27;     // 设置第27位
quiz1 &= ~(1UL << 27);  // 清除第27位
bool pass = quiz1 & (1UL << 27);  // 检查第27位
```

> **代码解释——三个标准位操作模式：**
> 1. **设置某位：** `quiz1 |= 1UL << 27` —— 用 `|` 把第 27 位置 1，其他位不受影响
> 2. **清除某位：** `quiz1 &= ~(1UL << 27)` —— 先构造一个"目标位为 0、其他位为 1"的掩码，再 `&`
> 3. **检查某位：** `quiz1 & (1UL << 27)` —— 只保留第 27 位的结果，其他位被清 0
>
> 这三个模式在嵌入式编程、标志位管理中无处不在。`unsigned long` 保证是 32 位或 64 位，`1UL` 保证不会因为符号位引发意外。

### 1.6 `sizeof` 运算符

> `sizeof` 是一个**编译期**运算符——它在编译时计算结果，不会在运行时带来任何开销。这是一个非常有用的特性：你可以用 `sizeof` 来计算静态数组的元素个数，甚至可以用它来做模板元编程的判断。

```cpp
// sizeof 对数组和指针的区别
int arr[10];
int *p = arr;
// sizeof(arr) 是整个数组的大小（40 bytes）
// sizeof(p)   是指针本身的大小（8 bytes）

// 数组元素个数
constexpr size_t sz = sizeof(arr) / sizeof(*arr);
```

> **为什么 `sizeof(arr)` 和 `sizeof(p)` 不同？** 数组名 `arr` 在大多数场合会自动退化为指针，但在 `sizeof` 中它是特例——`sizeof` 计算的是**数组的整体大小**（`10 × 4 = 40` 字节）。而指针 `p` 保存的是地址，`sizeof(p)` 只是指针本身占用的内存（64 位系统上为 8 字节）。这个差异可以用来安全地计算数组元素个数——静态数组的"以 `sizeof` 取大小"是可靠的，但数组作为函数参数传递后 `sizeof` 就不再用处——因为参数退化为指针了。

### 1.7 类型转换

> **为什么要区分这么多种类型转换？** C 风格的类型转换 `(type)expr` 什么都能做——你能用它把 `int*` 转为 `double*`，也能去掉 `const`，甚至能把函数指针转成整数。这种"万能"恰恰是危险所在：你很难在代码里搜索到它，而且一旦转换出错，调试极其困难。C++ 的四种 named cast 各司其职，让转换的**意图**和**边界**一目了然。

```cpp
// 隐式转换
int ival = 3.541 + 3;  // 3.541 → 3, then 3+3=6

// C++ 强制类型转换（推荐！比 C 风格更安全、更明确）
double d = 3.14;
int i1 = static_cast<int>(d);     // 常规转换（编译期检查）

// const_cast：去掉/加上 const
const char *cs = "hello";
char *s = const_cast<char*>(cs);  // 去掉 const（⚠️ 不要修改原数据！）

// reinterpret_cast：位模式的重新解释（危险，少用）
long addr = reinterpret_cast<long>(s);

// dynamic_cast 用于运行时类型检查（见补充17 - RTTI）
```

| 转换类型 | 用途 | 安全性 |
|---|---|---|
| `static_cast` | 常规类型转换（数值、void* 等） | 编译期检查 |
| `const_cast` | 去掉/添加 const/volatile | ⚠️ 注意不要修改原 const 对象 |
| `reinterpret_cast` | 位模式重新解释 | ❌ 非常危险，少用 |
| `dynamic_cast` | 多态类型的运行时转换 | 运行时检查（有开销） |
| C 风格 `(type)` | 以上所有 + 更多 | ❌ 不推荐——太宽泛，难排查 |

> **实际使用建议：** 绝大多数场景只需要 `static_cast`。`const_cast` 只在调用老旧的 C 风格 API 时偶尔需要。`reinterpret_cast` 应该只在底层系统编程（如共享内存、硬件寄存器访问）中使用，且要做好充分的文档注释。**永远不要用 C 风格的类型转换——** 在代码库中禁止 C 风格转换是很多团队的编码规范。

## 二、控制流语句深入

### 2.1 `switch` 语句

> **`switch` vs `if-else`：何时用哪个？** 当你有多个分支要基于同一个整型表达式判断时，`switch` 通常比 `if-else if` 链更高效（编译器可以生成跳转表）也更可读。但如果分支条件涉及范围判断（如 `grade >= 90`）或复杂的逻辑组合，`if-else` 更灵活。

```cpp
// switch 语句：比多个 if-else 更清晰
char grade = 'B';

switch (grade) {
    case 'A':
        // 优秀
        break;   // ⚠️ 不要忘记 break！否则会 fall through
    case 'B':
        // 良好
        break;
    case 'C':
        // 及格
        break;
    case 'D':
        // 需要努力
        break;
    default:
        // 无效的成绩
        break;
}

// 故意的 fall through（多个 case 共享代码）
char ch = 'a';
unsigned vowelCnt = 0;
switch (ch) {
    case 'a': case 'e': case 'i': case 'o': case 'u':
    case 'A': case 'E': case 'I': case 'O': case 'U':
        ++vowelCnt;
        break;
}

// C++17: [[fallthrough]] 标注故意的 fall through
// switch (x) {
//     case 1:
//         do_something();
//         [[fallthrough]];  // 明确告诉编译器：这是故意的
//     case 2:
//         ...
// }
```

> **为什么 `switch` 会设计成"fall through"（穿透）？** 这源于 C 语言的历史——`case` 本质上是跳转标签，执行会"流入"下一个标签。虽然这带来了 bug 风险（忘记 break），但对于多个 case 共享同一段代码的场景（如上文的元音统计），fall through 反而非常优雅。C++17 的 `[[fallthrough]]` 标注让开发者可以明确说"这是故意的"——编译器看到这个标注就不会产生"miss break"警告。

> **变量声明在 `case` 中的陷阱：** `case` 是跳转标签，变量初始化可能被跳过。如果需要在一个 `case` 中定义变量，必须用花括号括起来：
> ```cpp
> case 1: {
>     int x = 42;  // 花括号限定作用域，防止跳过
>     break;
> }
> ```
>
> **switch 检查清单：**
> - `case` 标签必须是整数常量表达式（不能用字符串、变量）
> - 每个 `case` 后面通常要有 `break`
> - 可以在最后一个 `case` 或 `default` 省略 `break`
> - 变量定义需要放在 `{ }` 块中

### 2.2 范围 `for` 循环（C++11）

> **范围 `for` 消除了传统循环的三大痛点：** 不需要管理索引，不需要写迭代器，不需要检查边界。它是遍历容器最安全、最简洁的方式——适用范围包括所有支持 `begin()`/`end()` 的容器和数组。

```cpp
vector<int> v{1, 2, 3, 4, 5};

// 范围 for：读（不修改）
for (auto x : v) { }

// 范围 for：写（修改原容器中的元素）
for (auto &x : v) {
    x *= 2;
}

// 对 string 使用范围 for
string s = "Hello";
for (auto c : s) { }

// ⚠️ 范围 for 中不能修改容器大小（不能 push_back / erase）
// for (auto x : v) {
//     v.push_back(x);  // ❌ 未定义行为！
// }
```

> **`auto` vs `auto &` vs `const auto &` 的选择：**
> - `for (auto x : v)` —— 每次迭代拷贝一个元素。适用于元素类型很小（如 `int`）且只读的场景。对大对象（如 `string`）效率低。
> - `for (auto &x : v)` —— 不拷贝，直接引用原元素。适用于修改元素，或元素类型较大不想拷贝。
> - `for (const auto &x : v)` —— 不拷贝，只读引用。适用于大对象只读遍历——最安全的"只读"模式。
>
> **为什么不能修改容器大小？** 范围 `for` 在循环开始前保存了 `end()` 迭代器。如果在循环中 `push_back`，容器可能扩容——原来保存的 `end()` 迭代器失效了。之后访问它就变成了未定义行为。

### 2.3 `do while` 循环

> **`do while` 和 `while` 的根本区别：** `while` 是"先判断，后执行"——可能一次都不执行。`do while` 是"先执行，后判断"——至少执行一次。这一区别在需要"先尝试再做决定"的场景中至关重要。

```cpp
// do while：至少执行一次循环体
string password;
int attempts = 0;

do {
    // 模拟输入
    password = (attempts == 0) ? "wrong" : "correct";
    ++attempts;
} while (password != "correct" && attempts < 3);
```

> **典型场景：** 用户输入校验、菜单循环、游戏循环。这些场景的共同点是——你需要在执行操作后再判断是否需要继续。注意 `do while` 的条件后面必须有一个分号 `;`，这和 `while` 不同。

### 2.4 `break`、`continue` 和 `goto`

```cpp
// break：跳出最近的循环或 switch
for (int i = 0; i < 10; ++i) {
    if (i == 5) break;      // 提前退出循环
}

// continue：跳过本次迭代的剩余部分
for (int i = 0; i < 10; ++i) {
    if (i % 2 == 0) continue; // 跳过偶数
}

// goto：无条件跳转（⚠️ 少用，只在跳出深层嵌套时有价值）
int matrix[3][3] = {{1, 2, 3}, {4, 5, 6}, {7, 8, 9}};
bool found = false;

for (int i = 0; i < 3; ++i) {
    for (int j = 0; j < 3; ++j) {
        if (matrix[i][j] == 5) {
            found = true;
            goto found_it;  // 直接跳出双重循环
        }
    }
}
found_it:
// found = true
```

## 三、运算符优先级速查

| 优先级 | 运算符 | 结合性 |
|---|---|---|
| 1 (最高) | `::` | 左 |
| 2 | `.` `->` `()` `[]` `++`(后) `--`(后) | 左 |
| 3 | `!` `~` `++`(前) `--`(前) `+`(一元) `-`(一元) `*`(解引用) `&`(取地址) `sizeof` `new` `delete` | **右** |

## 四、补充总结

### 核心要点

| 知识点 | 关键结论 |
|---|---|
| 短路求值 | `&&` 和 `||` 左侧为 false/true 时跳过右侧 |
| `switch` | 别忘 `break`；`case` 标签必须是常量；用 `{}` 包局部变量 |
| 范围 `for` | `for (auto &x : container)` — 修改用引用，只读用值或 const 引用 |
| `do while` | 至少执行一次；条件后面要有 `;` |
| 类型转换 | 用 `static_cast` 代替 C 风格转换 |
| 优先级 | 不确定时加括号——代码的可读性比简洁更重要 |

- **第06周** 的 `new`/`delete` 是运算符，遵循这里讲的优先级
- **第07周** 的操作符重载将重新定义本章中的运算符行为
