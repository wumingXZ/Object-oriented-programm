## 〇、C 语言回顾：`malloc` 和 `free`

```c
// C: 手动管理内存，极易出错
int *p = (int*)malloc(sizeof(int) * 100);
if (!p) { /* 检查是否分配成功 */ }

for (int i = 0; i < 100; i++)
    p[i] = i;

free(p);                 // 忘记 free → 内存泄漏
// p = NULL;             // 忘记置空 → 悬垂指针

// C 的问题：
// 1. malloc 需要手动计算大小 + 强制转换
// 2. 构造函数不会自动调用
// 3. 异常发生时无法释放（没有 RAII）
// 4. 所有权不明确——谁负责 free？
```

## 一、为什么需要智能指针？

C++ 引入 **RAII**（Resource Acquisition Is Initialization）原则：资源在构造函数中获取，在析构函数中释放。智能指针是 RAII 在动态内存管理上的体现。

```cpp
// 一个会抛出异常的函数
void might_throw() {
    throw runtime_error("出错了!");
}

// ❌ 原始指针：异常时泄漏
void raw_pointer_bad() {
    int *p = new int[100];
    might_throw();   // 如果这里抛异常...
    delete[] p;      // 这行永远不会执行！→ 内存泄漏
}

// ✅ 智能指针：异常安全
void smart_pointer_good() {
    auto sp = make_unique<int[]>(100);  // 等价于 new int[100]
    might_throw();  // 即使抛异常...
    // sp 的析构函数会自动调用 delete[] → 不泄漏！
}
```

## 二、`shared_ptr` — 共享所有权

### 2.1 基本用法

```cpp
// 推荐：用 make_shared 创建（一次内存分配，更高效）
auto sp1 = make_shared<string>("Hello");

// shared_ptr 支持拷贝——共享所有权
auto sp2 = sp1;          // sp2 和 sp1 指向同一个对象
auto sp3 = sp1;          // 引用计数 = 3

// 使用方式和普通指针一样
*sp1;
sp2->size();

// 引用计数
sp1.use_count();

// 检查是否唯一拥有
sp1.unique();
// 所有 sp1/sp2/sp3 离开作用域 → 引用计数减为 0 → 自动 delete
```

### 2.2 作为函数参数和返回值

```cpp
// 返回 shared_ptr（引用计数+1 再返回）
shared_ptr<vector<int>> make_vec() {
    return make_shared<vector<int>>(vector<int>{1, 2, 3});
}

// 按值传递 shared_ptr（引用计数+1）
void print_vec(shared_ptr<vector<int>> p) {
    // p 离开作用域，引用计数-1
}

// ⚠️ 什么时候用引用传递？
// 如果不涉及所有权，用 const shared_ptr<T>& 或更好的：const T&
void read_only(const shared_ptr<vector<int>> &p) {
    // 引用计数不增加
}

auto sp = make_vec();
print_vec(sp);
read_only(sp);
```

### 2.3 `shared_ptr` 和自定义删除器

```cpp
// 模拟一个需要特殊清理的资源
struct Connection {
    int id;
    Connection(int i) : id(i) { }
    void close() { }
};

// 自定义删除器：关闭连接而非 delete
auto deleter = [](Connection *c) {
    c->close();     // 先关闭
    delete c;       // 再释放
};

shared_ptr<Connection> conn(new Connection(42), deleter);
// 离开作用域时自动调用 deleter
```

## 三、`unique_ptr` — 独占所有权

### 3.1 基本用法

```cpp
// 推荐：用 make_unique 创建（C++14）
auto up = make_unique<int>(42);

// unique_ptr 独占所有权 → 不能拷贝
// auto up2 = up;     // ❌ 编译错误！

// 可以移动（转移所有权）
auto up2 = move(up);  // up2 接管所有权，up 变为 nullptr

if (!up) {
    // up 现在是 nullptr
}

// 重置（释放当前对象，接管新对象）
up2.reset(new int(100));

// 放弃所有权（返回裸指针，调用者负责 delete）
int *raw = up2.release();  // up2 变为 nullptr
delete raw;  // 手动释放
```

### 3.2 `unique_ptr` 管理数组

```cpp
// unique_ptr 有数组特化版本
auto arr = make_unique<int[]>(5);  // int[5]

for (int i = 0; i < 5; ++i) {
    arr[i] = i * 10;
}

// 注意：shared_ptr 管理数组需要自定义删除器（C++17 之前）
// shared_ptr<int[]> arr2(new int[5]);  // C++17
```

### 3.3 `unique_ptr` vs `shared_ptr` 选择指南

| 场景 | 推荐 |
|---|---|
| 只有一个拥有者 | `unique_ptr`（更轻量） |
| 多个共享拥有者 | `shared_ptr` |
| 需要观察但不拥有 | `weak_ptr` |
| 函数返回动态分配的对象 | `unique_ptr`（可隐式转为 `shared_ptr`） |
| 工厂函数 | `unique_ptr` |

## 四、`weak_ptr` — 不控制生命周期的观察者

### 4.1 解决 `shared_ptr` 循环引用

```cpp
// 场景：双向引用导致循环——永远无法释放！
struct Node {
    string name;
    shared_ptr<Node> next;    // 强引用
    weak_ptr<Node> prev;      // 弱引用（不增加引用计数）
    ~Node() { /* 释放 */ }
};

auto n1 = make_shared<Node>();
n1->name = "节点1";

auto n2 = make_shared<Node>();
n2->name = "节点2";

// 建立双向链表
n1->next = n2;    // n1 → n2（shared_ptr，引用计数+1）
n2->prev = n1;    // n2 → n1（weak_ptr，引用计数不增加！）

// 如果 prev 也是 shared_ptr：
// n1 和 n2 互相持有 → 引用计数永远不会归零 → 内存泄漏！

// n1 和 n2 都能正常销毁 ✓
```

### 4.2 使用 `weak_ptr`

```cpp
auto sp = make_shared<int>(42);
weak_ptr<int> wp = sp;  // wp 不增加引用计数

// weak_ptr 不能直接解引用——必须 lock()
if (auto locked = wp.lock()) {  // lock() 返回 shared_ptr
    // locked 离开作用域，引用计数-1
}

// 原 shared_ptr 被销毁后，weak_ptr 过期
sp.reset();  // 释放 sp
wp.expired();  // true
wp.lock();     // 返回 nullptr
```

## 五、智能指针使用原则（来自 C++ Primer）

```cpp
// ✅ DO：遵循以下模式
void correct_usage() {
    // 1. 优先用 make_shared / make_unique
    auto sp = make_shared<int>(42);

    // 2. 用 weak_ptr 打破循环引用
    // 3. 函数返回 unique_ptr 表示转移所有权
    // 4. 不需要所有权时传 const T& 或 T*
}

// ❌ DON'T：避免以下操作
void wrong_usage() {
    // 1. 不要用同一个裸指针初始化多个 shared_ptr
    //    auto p = new int;
    //    shared_ptr<int> sp1(p), sp2(p);  // ❌ 双重释放！

    // 2. 不要用 shared_ptr 的 get() 初始化另一个 shared_ptr
    //    auto sp3 = shared_ptr<int>(sp1.get());  // ❌

    // 3. 不要 delete shared_ptr::get() 返回的指针

    // 4. 不要用智能指针管理栈上的对象
    //    int x = 42;
    //    shared_ptr<int> sp(&x);  // ❌ 不能 delete 栈对象！
}
```

## 六、补充总结

### 三种智能指针速查

| 类型 | 所有权 | 拷贝 | 典型用途 |
|---|---|---|---|
| `unique_ptr` | 独占 | ❌ (只能移动) | 工厂函数返回、容器元素 |
| `shared_ptr` | 共享 | ✅ (引用计数) | 多个所有者、异步场景 |
| `weak_ptr` | 无 | ✅ | 缓存、观察者、打破循环引用 |

### 核心原则

> **C++ Core Guidelines:**
> - 永远不要显式调用 `new` 和 `delete`（用 `make_unique`/`make_shared`）
> - 用 `unique_ptr` 作为默认选择
> - 只在确实需要共享所有权时才用 `shared_ptr`
> - 用 `weak_ptr` 打破循环引用
