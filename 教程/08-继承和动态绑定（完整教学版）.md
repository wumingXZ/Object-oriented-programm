## 一、面向对象编程的核心思想

C++ 面向对象编程基于三大基石：

| 概念 | 含义 | 对应章节 |
|---|---|---|
| **数据抽象** | 将接口与实现分离 | 第七章（类） |
| **继承** | 定义相似类型之间的关系 | 本章 |
| **动态绑定** | 忽略类型差异，统一使用对象 | 本章 |

> **来自 C++ Primer 第 15 章**：通过继承，我们能够定义类来建模相似类型之间的关系；通过动态绑定，我们能够使用这些类型的对象，同时忽略它们的具体差异。

### 什么是继承？

假设你要写三个类：`Dog`（狗）、`Cat`（猫）、`Bird`（鸟）。它们都有名字 `name`、都会吃东西 `eat()`、都会睡觉 `sleep()`。如果不使用继承，你需要在每个类里重复写这些——三份几乎一样的代码。

继承的解决方案：**把公共的部分提取到一个"基类"中，让其他类"继承"它。**

```
         ┌─────────────┐
         │   Animal    │  ← 基类：包含 name, eat(), sleep()
         │  (公共部分)   │
         └──────┬──────┘
       ┌────────┼────────┐
       ▼        ▼        ▼
    ┌─────┐ ┌─────┐ ┌─────┐
    │ Dog │ │ Cat │ │Bird │  ← 派生类：自动拥有 Animal 的一切
    └─────┘ └─────┘ └─────┘   只需写自己独有的部分（如 speak()）
```

**核心思想**：派生类**自动获得**基类的所有数据成员和成员函数（构造函数、析构函数、赋值运算符除外），然后可以：
- **添加**新的成员（如 `Dog` 添加 `fetch()`）
- **重写**（override）基类的虚函数，提供自己的版本（如 `Dog` 重写 `speak()` 返回 `"汪汪!"`）

**C++ 中的继承语法**：

```cpp
class 派生类名 : public 基类名 {
    // 新增的成员
    // 重写的虚函数
};
```

`public` 表示**公有继承**，是最常用的继承方式（实践中几乎总是用它）。它表达的是 **IS-A（是一个）** 关系：`Dog` IS-A `Animal`——狗**是**一种动物。因此任何需要 `Animal` 的地方，都可以用 `Dog` 代替。

> **继承了什么，没继承什么？**
>
> | 成员类型 | 是否被继承 | 说明 |
> |---------|-----------|------|
> | 普通成员函数 | ✅ 继承 | 派生类可以直接调用 |
> | 数据成员 | ✅ 继承 | 派生类对象中包含基类的数据 |
> | 构造函数 | ❌ 不继承 | 每个类必须定义自己的构造函数 |
> | 析构函数 | ❌ 不继承 | 但派生类析构时会自动调用基类析构 |
> | 赋值运算符 | ❌ 不继承 | 每个类需要自己的 `operator=` |
> | `friend` 声明 | ❌ 不继承 | 友元关系不传递 |

### 运行示例：感受多态

下面用一个完整的例子展示继承的基本语法——注意 `Dog` 和 `Cat` 继承了 `Animal` 的一切，只需要重写 `speak()`：

```cpp
class Animal {
public:
    virtual string speak() const { return "???"; }  // ① virtual：允许派生类重写
    virtual ~Animal() {}                             // ② 虚析构函数：安全删除
};

class Dog : public Animal {                   // ③ public 继承：Dog IS-A Animal
public:
    string speak() const override { return "汪汪!"; }  // ④ override：显式重写
};

class Cat : public Animal {
public:
    string speak() const override { return "喵喵!"; }
};

vector<unique_ptr<Animal>> zoo;
zoo.push_back(make_unique<Dog>());
zoo.push_back(make_unique<Cat>());
zoo.push_back(make_unique<Dog>());
// a->speak() 动态绑定！  // ⑤ 通过基类指针调用，运行时决定调用哪个 speak()
```

> **逐点解释上面的 5 个关键标记：**
>
> **① `virtual`——启用动态绑定的唯一关键字。** `speak()` 前加 `virtual`，意味着"调用者通过基类指针/引用调用这个函数时，会运行**实际对象类型**的版本，而不是指针声明类型的版本"。如果不加 `virtual`，`p->speak()` 永远调用 `Animal::speak()`，即使用 `p` 指向一个 `Dog`。换句话说：**不加 `virtual` 的函数使用编译时类型（静态绑定），加了 `virtual` 的使用运行时类型（动态绑定）。**
>
> **② `virtual ~Animal()`——保护资源不被泄漏。** 当你用 `delete animalPtr` 删除一个实际指向 `Dog` 的 `Animal*` 指针时，如果 `~Animal()` 不是虚函数，**只有 `~Animal()` 会运行**，`Dog` 独有的资源（如果有）就泄漏了。加 `virtual` 后，调用链是 `~Dog()` → `~Animal()`，所有资源正确释放。**规则：只要你预期这个类会被继承，析构函数就应该声明为 `virtual`——即使函数体是空的。**
>
> **③ `public` 继承——表示 IS-A 关系。** `Dog` 公有继承 `Animal` 意味着：任何需要 `Animal` 的地方都可以用 `Dog` 代替。`Dog` 继承了 `Animal` 的全部公开接口（`speak()`），外部代码可以像使用 `Animal` 一样使用 `Dog`。私有继承和受保护继承很少使用——实践中几乎总是公有继承。
>
> **④ `override`——零成本的编译期安全检查。** `speak() const override` 告诉编译器："我**意图**重写基类的虚函数"。如果你把函数名拼错了（比如 `speek()`），或者参数类型写错了，编译器会报错。`override` 不是替代 `virtual`——基类**仍然需要** `virtual` 来启用动态绑定。派生类用 `override`（也可以同时写 `virtual`，但 `override` 本身已经包含了"这是虚函数"的语义，所以只用 `override` 就够了）。
>
> **⑤ 动态绑定的关键条件。** 只有**通过基类的指针或引用**调用 `virtual` 函数时，才会触发动态绑定。如果直接通过对象调用（`dog.speak()`），总是静态绑定——因为编译器知道对象的精确类型。记住：**指针/引用 + virtual = 动态绑定。缺一不可。**

## 二、问题引入：学生成绩管理系统

### 2.1 需求变更

- 研究生除了完成家庭作业和考试外，还需要写一篇**论文（thesis）**
- 研究生的最终成绩 = **min(课程成绩, 论文成绩)**

### 2.2 设计与运行示例

> **设计思路**：我们有两个非常相似的类型——`Core`（本科生）和 `Grad`（研究生）。它们共享大部分数据（姓名、期中、期末、作业）和行为（读入数据），只在成绩计算上有区别。与其写两个独立的类，不如让 `Grad` **继承** `Core`：`Grad` 自动拥有 `Core` 的全部成员，只需要**重写**那些行为不同的函数。

```cpp
class Core {
public:
    Core() : midterm(0), final(0) {}
    Core(istream& is) { read(is); }

    virtual ~Core() {}  // 基类必备：虚析构函数

    string name() const { return n; }  // 非虚函数：所有学生取名字方式相同

    virtual double grade() const {     // 虚函数：本科生和研究生计算方式不同
        if (homework.empty())
            throw runtime_error("no homework");
        return 0.2 * midterm + 0.4 * final + 0.4 * average(homework);
    }

    virtual istream& read(istream& is) {  // 虚函数：读入方式也不同
        is >> n >> midterm >> final;
        read_hw(is);
        return is;
    }

protected:  // 派生类需要访问，但外部不需要
    double midterm, final;
    vector<double> homework;
    istream& read_common(istream& is) {
        is >> n >> midterm >> final;
        return is;
    }

private:  // 只有 Core 自己需要
    string n;
    void read_hw(istream& is) { /* ... */ }
    double average(const vector<double>& v) const { /* ... */ }
};

class Grad : public Core {
public:
    Grad() : thesis(0) {}
    Grad(istream& is) { read(is); }

    double grade() const override {      // 重写：用 override 而非 virtual
        return min(Core::grade(), thesis);  // 调用基类的课程成绩计算
    }

    istream& read(istream& is) override {  // 重写：多读了 thesis
        read_common(is);  // 复用基类的公共读入逻辑
        is >> thesis;
        double x;
        homework.clear();
        while (is >> x) homework.push_back(x);
        is.clear();
        return is;
    }

private:
    double thesis;  // Grad 独有的数据
};
```

> **为什么 `grade()` 和 `read()` 要声明为 `virtual`？**
> 因为主程序通过 `Student_info` 包装类（内部持有 `Core*` 指针）来操作学生。当调用 `cp->grade()` 时：
> - 如果 `cp` 实际指向 `Core`，应该调用 `Core::grade()`
> - 如果 `cp` 实际指向 `Grad`，应该调用 `Grad::grade()`
> 
> 没有 `virtual`，编译器只看指针的声明类型（`Core*`），永远调用 `Core::grade()`——研究生的论文成绩就被忽略了。加上 `virtual`，运行时根据实际对象类型决定调用哪个函数。
>
> **为什么 `name()` 不加 `virtual`？**
> 因为所有学生取名字的方式都一样——直接返回 `n`。不需要重写。`virtual` 有微小的运行时开销（查虚函数表），只在需要多态行为的函数上才加。
>
> **`protected` vs `private` 的决策：**
> - `midterm`, `final`, `homework`, `read_common()` 放在 `protected`——`Grad` 需要读写这些数据，但外部代码不应该接触
> - `n` 放在 `private`——`Grad` 通过 `name()` 读取名字就够了，不需要直接访问 `n`
> - `read_hw()` 放在 `private`——这是 `Core` 内部的辅助函数，`Grad` 的 `read()` 自己实现了作业读入逻辑

<a id="三保护标签-protected"></a>
## 三、保护标签 `protected`

> `protected` 是介于 `public` 和 `private` 之间的第三种访问级别。它的存在理由很简单：基类有些成员**不应该暴露给外部用户**，但**派生类需要直接访问**。

```cpp
class Base {
public:
    int pub = 1;      // 所有人可访问

protected:
    int prot = 2;     // 自己和派生类可访问

private:
    int priv = 3;     // 只有自己能访问
};

class Derived : public Base {
public:
    void access() {
        pub;   // ✅ 公有成员：派生类可以访问
        prot;  // ✅ 受保护成员：派生类可以访问
        priv;  // ❌ 私有成员：派生类也不能访问！
    }
};

Derived d;
d.pub;   // ✅ 外部可以访问
d.prot;  // ❌ 受保护成员：外部不能访问
d.priv;  // ❌ 私有成员：外部不能访问
```

**三种访问级别对比**：

| 访问级别 | 类自身 | 派生类 | 外部用户 |
|---|---|---|---|
| `public` | ✓ | ✓ | ✓ |
| `protected` | ✓ | ✓ | ✗ |
| `private` | ✓ | ✗ | ✗ |

> **实践经验**：数据成员通常放在 `protected` 或 `private` 中——很少是 `public`。如果希望派生类能直接读写数据，用 `protected`；如果希望派生类也必须通过成员函数访问（更好的封装），用 `private` + 受保护的访问器函数。

<a id="四虚函数与动态绑定--核心机制"></a>
## 四、虚函数与动态绑定 — 核心机制

> 这是理解 C++ 多态的**最关键一节**。请特别注意调用方式（对象/指针/引用）和函数类型（虚/非虚）的组合如何影响结果。

### 4.1 运行示例：静态绑定 vs 动态绑定

```cpp
class Base {
public:
    virtual void vfunc() const { cout << "Base::vfunc()" << endl; }
    void ordinary() const { cout << "Base::ordinary()" << endl; }
};

class Derived : public Base {
public:
    void vfunc() const override { cout << "Derived::vfunc()" << endl; }
    void ordinary() const { cout << "Derived::ordinary()" << endl; }
};

Derived d;
Base* p = &d;   // 基类指针 → 派生类对象
Base& r = d;    // 基类引用 → 派生类对象

// 通过对象调用（永远是静态绑定——编译器知道确切类型）
d.vfunc();       // Derived::vfunc()
d.ordinary();    // Derived::ordinary()

// 通过指针调用
p->vfunc();      // Derived::vfunc() — 虚函数 + 指针 = 动态绑定 ✅
p->ordinary();   // Base::ordinary()  — 非虚函数永远是静态绑定！

// 通过引用调用
r.vfunc();       // Derived::vfunc() — 虚函数 + 引用 = 动态绑定 ✅
r.ordinary();    // Base::ordinary()  — 非虚函数永远是静态绑定！
```

**核心规则**：

| 调用方式 | 绑定时机 | 条件 |
|---|---|---|
| 通过**对象**调用 | 编译时（静态） | 任何函数 |
| 通过**指针**调用虚函数 | 运行时（动态） | 函数必须是 `virtual` |
| 通过**引用**调用虚函数 | 运行时（动态） | 函数必须是 `virtual` |
| 通过指针/引用调用**非虚函数** | 编译时（静态） | 不管实际类型是什么 |

> **为什么需要动态绑定？** 因为很多场景下，编译时不知道对象的精确类型。比如一个 `vector<Core*>` 里混合存放了 `Core` 和 `Grad` 对象，遍历时对每个元素调用 `grade()`，编译器无法提前知道每个指针实际指向什么——只有运行时通过虚函数表才能找到正确的函数。实际上，`virtual` 的原理就是编译器为每个对象添加一个隐藏指针（vptr），指向该类型的虚函数表（vtable），运行时通过查表找到正确的函数地址。

### 4.2 对象切片（Object Slicing）

```cpp
class Base {
public:
    virtual void info() const {
        cout << "Base (size=" << sizeof(*this) << ")" << endl;
    }
    int baseData[2] = {1, 2};
};

class Derived : public Base {
public:
    void info() const override {
        cout << "Derived (size=" << sizeof(*this) << ")" << endl;
    }
    int extraData[4] = {3, 4, 5, 6};  // 派生类比基类多出来的数据
};

// ❌ 按值传递：切片！
void printByValue(Base b) {  // b 是 Base 类型的局部变量
    b.info();                // 永远调用 Base::info()
}

// ✅ 按引用传递：保留完整类型
void printByRef(const Base& b) {  // b 引用实际对象，不拷贝
    b.info();                      // 虚函数 —— 动态绑定！
}

Derived d;
printByValue(d);  // 切片：d 的 Base 部分被拷贝到参数 b，Derived 部分丢失
printByRef(d);    // 完整：b 只是 d 的别名，Derived 部分保留
```

> **对象切片产生的原因**：按值传参时，形参是基类类型的**新对象**。编译器从实参的基类部分拷贝构造这个新对象，派生类独有的数据成员**被切掉**。解决方案：始终用**指针或引用**传递多态类型。
>
> **容器也是如此**：`vector<Core>` 存储的是 `Core` **对象**——放进去的 `Grad` 会被切片。正确的容器是 `vector<Core*>` 或 `vector<unique_ptr<Core>>`。

<a id="五使用继承解决学生成绩问题完整程序"></a>
## 五、使用继承解决学生成绩问题（完整程序）

> 下面是将前几节的概念整合成一个完整可工作的继承体系。注意代码中标注了 **访问控制的设计理由**——哪些放 public、哪些放 protected、哪些放 private，每个都有原因。

```cpp
// ================ 基类 Core ================
class Core {
public:
    Core() : midterm(0), final(0) {}
    Core(istream& is) { read(is); }
    virtual ~Core() = default;  // 虚析构：基类必备。= default 比 {} 更明确

    string name() const { return n; }    // 非虚：所有子类实现相同

    virtual double grade() const {       // 虚：子类可能重写
        if (homework.empty())
            throw runtime_error("student has done no homework");
        return 0.2 * midterm + 0.4 * final + 0.4 * average(homework);
    }

    virtual istream& read(istream& is) { // 虚：子类可能重写
        is >> n >> midterm >> final;
        read_hw(is);
        return is;
    }

protected:  // 派生类需要直接读写这些成员
    istream& read_common(istream& is) {  // 公共的姓名+成绩读入逻辑
        is >> n >> midterm >> final;
        return is;
    }
    double midterm, final;
    vector<double> homework;

private:  // 实现细节，派生类不需要直接接触
    string n;
    void read_hw(istream& is) { /* 读入作业成绩 */ }
    static double average(const vector<double>& v) { /* 计算平均分 */ }
};

// ================ 派生类 Grad ================
class Grad : public Core {
public:
    Grad() : thesis(0) {}
    Grad(istream& is) { read(is); }

    double grade() const override {         // 重写：加上论文约束
        return min(Core::grade(), thesis);  // 显式调用基类版本
    }

    istream& read(istream& is) override {   // 重写：额外读入论文
        read_common(is);                    // 复用基类的公共逻辑
        is >> thesis;
        double x;
        homework.clear();
        while (is >> x) homework.push_back(x);
        is.clear();
        return is;
    }

private:
    double thesis;  // Grad 独有的数据成员
};
```

> **几个关键设计决策的再确认**：
>
> 1. **基类中的 `virtual` 是必须的吗？** 是的。`virtual` 是动态绑定的开关——必须在基类中声明。一旦基类声明为 `virtual`，派生类中自动也是虚函数（不管写不写 `virtual` 关键字）。但**推荐派生类用 `override` 代替 `virtual`**——更安全，有编译检查。
>
> 2. **基类普通函数能声明成 `virtual` 吗？** 可以，但需要权衡。`virtual` 有微小的运行时开销（每个对象多一个 vptr 指针 + 每次调用多一次间接跳转）。只在**确实需要多态行为**的函数上使用 `virtual`。`name()` 就不需要——所有学生取名字的方式都一样。
>
> 3. **`protected` 和 `private` 怎么选？** 一个简单判断：如果派生类需要直接访问，用 `protected`；如果派生类通过基类提供的 public/protected 函数就够用，用 `private`（更好的封装）。数据和函数可以混合使用不同的访问级别——从封装性角度看，数据成员 `private` + 受保护的访问器函数是最佳实践。

<a id="六虚析构函数"></a>
## 六、虚析构函数

> **这是 C++ 继承中最容易出错的细节之一。** 问题场景：你有一个基类指针，实际指向派生类对象，然后你 `delete` 它。

### 问题演示

```cpp
// ❌ 错误：基类析构函数不是虚函数
class BadBase {
public:
    ~BadBase() { /* 只释放基类资源 */ }
};

class BadDerived : public BadBase {
    int* data;
public:
    BadDerived() : data(new int[100]) {}
    ~BadDerived() { delete[] data; }  // 这个永远不会被调用！
};

BadBase* p = new BadDerived();
delete p;  // 只调用 ~BadBase()！~BadDerived() 被跳过！
           // data 指向的 100 个 int 泄漏了。这是未定义行为。
```

```cpp
// ✅ 正确：基类析构函数是虚函数
class GoodBase {
public:
    virtual ~GoodBase() {}  // 虚析构函数——即使函数体是空的
};

class GoodDerived : public GoodBase {
    int* data;
public:
    GoodDerived() : data(new int[100]) {}
    ~GoodDerived() override { delete[] data; }  // 会被正确调用
};

GoodBase* p = new GoodDerived();
delete p;  // 调用链：~GoodDerived() → ~GoodBase()
           // 所有资源正确释放 ✅
```

### 规则总结

| 问题 | 答案 |
|------|------|
| **什么时候需要虚析构函数？** | 当类被设计为基类，且可能通过基类指针 `delete` 派生类对象时 |
| **怎么判断一个类会不会被用作基类？** | 如果类中**有任何 `virtual` 函数**，那它大概率会被用作基类 → 需要虚析构 |
| **不写虚析构会怎样？** | 通过基类指针 `delete` 派生对象时，派生类的析构函数不会被调用 → 资源泄漏 + 未定义行为 |
| **`virtual ~Base() = default;` 和 `virtual ~Base() {}` 有什么区别？** | `= default` 更明确表达"使用编译器生成的默认实现"，而且是 C++11 推荐写法。功能上等价 |
| **派生类的析构函数需要写 `override` 吗？** | 推荐写。`~Derived() override { ... }` 让编译器帮你检查基类析构是不是确实是虚的 |
| **`final` 类需要虚析构吗？** | 不需要——`final` 类不能被继承，也就不会出现"通过基类指针删除派生对象"的情况 |

### 虚函数表的底层原理

```
每个有虚函数的类有一个虚函数表（vtable），每个对象有一个虚函数表指针（vptr）。
当调用 p->grade() 时：
  1. 通过 p 找到对象的 vptr
  2. 通过 vptr 找到 vtable
  3. 在 vtable 中查找 grade() 的实际地址
  4. 跳转到该地址执行

如果 ~Base() 不是虚函数，它不在 vtable 中。
delete p 时编译器直接调用 ~Base()——不管 p 实际指向什么。
```

<a id="七纯虚函数和抽象类"></a>
## 七、纯虚函数和抽象类

> **纯虚函数** = 基类只声明接口，不提供实现。**抽象类** = 包含至少一个纯虚函数的类。抽象类**不能实例化**。

```cpp
// 抽象基类：定义"形状"的公共接口
class Shape {
public:
    virtual double area() const = 0;       // = 0 表示"纯虚函数"
    virtual double perimeter() const = 0;  // 派生类必须实现
    virtual ~Shape() = default;            // 抽象类也要虚析构！
};

// 具体类：实现了所有纯虚函数
class Circle : public Shape {
    double r;
public:
    Circle(double radius) : r(radius) {}
    double area() const override { return M_PI * r * r; }
    double perimeter() const override { return 2 * M_PI * r; }
};

class Rectangle : public Shape {
    double w, h;
public:
    Rectangle(double width, double height) : w(width), h(height) {}
    double area() const override { return w * h; }
    double perimeter() const override { return 2 * (w + h); }
};

// Shape s;           // ❌ 编译错误！抽象类不能实例化
Circle c(5);          // ✅ 具体类可以实例化
Rectangle r(3, 4);    // ✅

// 但可以通过基类指针/引用来操作
Shape* shapes[] = {&c, &r};
for (auto s : shapes) {
    s->area();        // 动态绑定：Circle 调用 Circle::area()
}                     //          Rectangle 调用 Rectangle::area()
```

> **`= 0` 的语法含义**：把函数指针在虚函数表中的位置**置为零**——告诉编译器"这个函数没有实现"。但这不意味着纯虚函数不能有函数体——你可以在类外定义它：
> ```cpp
> double Shape::area() const { return 0; }  // 默认实现
> ```
> 派生类仍然必须重写（因为 `= 0` 的约束还在），但可以在自己的实现中调用 `Shape::area()` 来复用默认逻辑。
>
> **为什么抽象类也需要虚析构函数？** 因为你会通过 `Shape*` 指针来操作 `Circle` 和 `Rectangle`。如果将来有人 `delete shapePtr`，没有虚析构就会泄漏派生类的资源。这个规则和普通基类完全一样。

<a id="八override和final关键字c11"></a>
## 八、`override` 和 `final` 关键字（C++11）

> 这两个关键字是**零成本的安全网**——只在编译期生效，不影响运行时性能。

```cpp
class Animal {
public:
    virtual void eat() const { /* ... */ }
    virtual void sleep() const { /* ... */ }
    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    // override: "我意图重写基类的虚函数，请编译器帮我检查"
    void eat() const override { /* Dog 的吃法 */ }

    // final: "我不允许子类继续重写这个函数"
    void sleep() const final { /* Dog 的睡法 */ }

    // void eet() const override { }
    //         ^^^^ 编译错误！Animal 里没有叫 eet() 的虚函数
};

class Puppy : public Dog {
public:
    void eat() const override { /* 可以——eat 没有被标记为 final */ }

    // void sleep() const override { }
    // 编译错误！Dog::sleep() 被标记为 final，禁止重写
};

// final 也可以用于整个类
class Bulldog final : public Dog { /* ... */ };
// class MiniBulldog : public Bulldog { };  // ❌ 错误！Bulldog 是 final
```

| 关键字 | 用于函数 | 用于类 |
|--------|---------|--------|
| `override` | 表示重写基类虚函数，编译器校验 | —（不可用于类） |
| `final` | 禁止派生类重写此函数 | 禁止此类被继承 |

> **`override` vs `virtual` 的使用规则**：
> - **基类**：必须用 `virtual` 声明虚函数（`override` 只在重写时使用）
> - **派生类**：推荐只用 `override`，不写 `virtual`（`override` 已经暗示这是虚函数，重复 `virtual` 是多余的）
> - 如果你同时写了 `virtual ... override`，虽然合法，但不如只用 `override` 简洁
>
> **`final` 的性能优势**：编译器知道 `final` 函数不会被重写，可以把通过指针/引用的虚函数调用**去虚拟化**（devirtualize）——直接调用具体函数，省去查虚函数表的开销。

## 九、访问控制与继承总结

| 继承方式 | 基类成员 | 在派生类中 | 在派生类的派生类中 | 类外函数 |
|---|---|---|---|---|
| **公有继承** | public | public ✓ | public ✓ | ✓ |
| | protected | protected ✓ | protected ✓ | ✗ |
| | private | ✗ | ✗ | ✗ |
| **私有继承** | public | private ✓ | ✗ | ✗ |
| | protected | private ✓ | ✗ | ✗ |
| | private | ✗ | ✗ | ✗ |

> **实践中几乎总是使用公有继承**。私有继承是"用基类来实现"（HAS-A），而非"是基类的一种"（IS-A）——这种需求通常用组合更好。

## 十、课程总结

| 知识点 | 关键要点 |
|---|---|
| **继承** | `class Grad : public Core`；派生类拥有基类的所有成员（构造/析构/赋值除外） |
| **`protected`** | 派生类可访问，外部不可访问 |
| **构造顺序** | 基类 → 派生类成员初始化 → 派生类构造函数体 |
| **虚函数 `virtual`** | 通过指针/引用实现动态绑定；必须基类声明 `virtual`；派生类用 `override` |
| **多态** | 基类指针/引用可以指向派生类对象 |
| **虚析构函数** | 基类**必须**定义虚析构函数；否则通过基类指针 `delete` 派生对象是未定义行为 |
| **纯虚函数** | `= 0`；类成为抽象类，不能实例化；派生类必须实现才能成为具体类 |
| **`override`** | 显式标记重写，编译时校验签名匹配；零成本 |
| **`final`** | 阻止虚函数被继续重写；或阻止类被继承；可帮助编译器去虚拟化 |
