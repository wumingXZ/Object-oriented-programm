## 〇、C 语言回顾：动态内存管理的痛点

> C 语言中，每个需要动态数组的场景都要写几乎相同的代码——只是元素类型不同。而且 **malloc/free 不负责初始化/清理对象**，你必须手动处理。这就是模板类要解决的第一个问题。

```c
// C 语言：为每种类型各写一遍
typedef struct { int* data; int size; int capacity; } IntVec;
typedef struct { double* data; int size; int capacity; } DoubleVec;
typedef struct { char* data; int size; int capacity; } CharVec;
// ... 无穷无尽！

void intvec_push(IntVec* v, int val) {
    if (v->size == v->capacity) {
        v->capacity *= 2;
        v->data = realloc(v->data, v->capacity * sizeof(int));  // 容易忘记
    }
    v->data[v->size++] = val;
}
// 每种类型都要重复几乎相同的代码！
```

> **C 方式的三个核心痛点**：
>
> ① **代码膨胀**：`int`、`double`、`char`、`Student`……每种类型都要定义一套相似的函数。没有泛型机制。
>
> ② **realloc 隐患**：`realloc` 会复制内存（用 `memcpy`），但**只对内置类型安全**。如果元素是 C++ 对象（有构造函数/析构函数），`memcpy` 不会调用拷贝构造函数——这是未定义行为。
>
> ③ **没有自动扩容**：每个 push 操作都要检查容量，如果忘记写扩容逻辑就导致缓冲区溢出。
>
> C++ 的模板类同时解决了这些问题：**写一次，用于所有类型；用 new/delete 代替 malloc/free 确保构造函数/析构函数被调用；封装自动扩容逻辑在内部。**

## 一、模板类基础：`Vec<T>` 的设计

### 1.1 从使用者的角度看 `Vec`

> 在开始写代码之前，先明确我们要实现什么。`Vec<T>` 是一个简化的 `std::vector<T>`——它存储任意类型的动态数组，支持 `push_back` 自动扩容、通过 `[]` 访问元素、以及安全的拷贝行为。

```cpp
// Vec<int> vi;        // 一个 int 的动态数组
// Vec<string> vs;     // 一个 string 的动态数组
// vi.push_back(42);   // 添加一个 int
// vs.push_back("hi"); // 添加一个 string

// 接下来我们实现简化的 Vec

template <class T>
class Vec {
public:
    // ===== 类型定义（标准容器约定）=====
    typedef T* iterator;
    typedef const T* const_iterator;
    typedef size_t size_type;
    typedef T value_type;
    typedef T& reference;
    typedef const T& const_reference;

    // ===== 构造函数 =====
    Vec() { create(); }
    explicit Vec(size_type n, const T& val = T()) { create(n, val); }
    Vec(const Vec& v) { create(v.begin(), v.end()); }  // 复制构造函数

    // ===== 析构函数 =====
    ~Vec() { uncreate(); }

    // ===== 赋值运算符 =====
    Vec& operator=(const Vec& rhs) {
        if (&rhs != this) {  // 检查自我赋值！
            uncreate();
            create(rhs.begin(), rhs.end());
        }
        return *this;
    }

    // ===== 访问 =====
    size_type size() const { return avail - data; }
    T& operator[](size_type i) { return data[i]; }
    const T& operator[](size_type i) const { return data[i]; }

    // ===== 迭代器 =====
    iterator begin() { return data; }
    const_iterator begin() const { return data; }
    iterator end() { return avail; }
    const_iterator end() const { return avail; }

    // ===== 动态增长 =====
    void push_back(const T& val) {
        if (avail == limit) grow();  // 空间不够 → 扩容
        unchecked_append(val);
    }

private:
    iterator data;   // 指向第一个元素
    iterator avail;  // 指向最后一个元素的下一个位置
    iterator limit;  // 指向分配内存的末尾

    // 内存管理辅助函数
    void create() { data = avail = limit = nullptr; }

    void create(size_type n, const T& val) {
        data = new T[n];
        avail = limit = data + n;
        for (size_type i = 0; i < n; ++i)
            data[i] = val;
    }

    void create(const_iterator b, const_iterator e) {
        size_type n = e - b;
        data = new T[n];
        avail = limit = data + n;
        copy(b, e, data);
    }

    void uncreate() {
        if (data) {
            delete[] data;  // 释放内存
        }
        data = avail = limit = nullptr;
    }

    void grow() {
        size_type new_size = max(size_type(2 * (limit - data)), size_type(1));
        iterator new_data = new T[new_size];
        iterator new_avail = copy(data, avail, new_data);

        uncreate();  // 释放旧内存
        data = new_data;
        avail = new_avail;
        limit = data + new_size;
    }

    void unchecked_append(const T& val) {
        *avail++ = val;  // 在当前位置构造，然后移动指针
    }
};

// ===== 使用 Vec =====
Vec<int> vi;
vi.push_back(10);
vi.push_back(20);
vi.push_back(30);
vi.push_back(40);

vi[1] = 99;

Vec<string> vs;
vs.push_back("Hello");
vs.push_back("World");
vs.push_back("!");
```

> **逐点解释上述模板类的关键设计**：
>
> **① `template <class T>` — 类型参数化。** 这里的 `T` 是一个"类型占位符"。编译器不是看到 `Vec` 的定义就生成代码——它会等看到用户写 `Vec<int>` 或 `Vec<string>` 时，才把 `T` 替换为具体的类型，生成一份真正的类代码。这个过程叫做**模板实例化（template instantiation）**。这也解释了为什么模板类的完整定义必须放在头文件中——编译器在实例化时**必须看到完整的类定义**。
>
> **② 三个指针的设计：`data` / `avail` / `limit`**。这不是随意的三个指针。每个有精确的职责：
>
> ```
>  [10] [20] [30] [  ] [  ] [  ]
>   ^          ^            ^
>  data      avail         limit
>   |          |            |
>   已存元素   已存+空闲区   分配的末尾
> ```
> - `data` → `avail`：已构造的元素
> - `avail` → `limit`：已分配但未使用的空闲空间
> - `limit`：分配内存的终点
>
> **③ `push_back` 的分摊常数时间——为什么指数增长？** `grow()` 中每次扩容翻倍（`new_size = 2 * old_size`）。假设初始容量 1，总共插入 n 个元素，扩容次数是 O(log n)，每次扩容的拷贝量为 O(1)、O(2)、O(4)……总和为 O(n)。所以 **n 次 push_back 的总时间是 O(n)，平均每次 O(1)**（分摊常数）。如果每次固定增加 1 个位置（而不是翻倍），那每次插入都要 O(n) 拷贝，总时间 O(n²)。

`★ Insight ─────────────────────────────────────`
模板类定义中的 `T` 是**类型占位符**。编译器不会为模板生成代码——只有当用户创建 `Vec<int>` 这样的**实例化**时，编译器才用 `int` 替换 `T`，生成一份真实的类代码。这就是为什么模板类的完整定义必须放在头文件中：编译器需要看到完整定义才能实例化。
`─────────────────────────────────────────────────`

## 二、`new` 和 `delete` — C++ 的动态内存

> 从 C 的 `malloc/free` 过渡到 C++ 的 `new/delete`，表面上看只是语法不同，但**本质上的区别巨大**。`new` 做了两件事：分配内存 + 调用构造函数。`malloc` 只做了一件事：分配内存。这种区别决定了 C++ 中必须用 `new`/`delete`，而不是继续用 C 的 `malloc`/`free`。

```cpp
class Person {
    string name;
    int age;
public:
    Person(const string& n, int a) : name(n), age(a) {}
    ~Person() {}
    void greet() const {}
};

// C++ 方式：new 分配内存 + 调用构造函数
Person* p1 = new Person("Alice", 25);
p1->greet();

// 带初始值的 new
int* pi = new int(42);  // 分配并初始化为42
delete pi;

// 数组的 new[] 和 delete[]
int* arr = new int[5]{1, 2, 3, 4, 5};
delete[] arr;  // 注意 delete[]，不是 delete！

// delete 调用析构函数
delete p1;  // 调用 ~Person()，然后释放内存
```

> **`new`/`delete` vs `malloc`/`free` 的本质区别**：
>
> ① **构造函数 vs 无初始化**：`new Person("Alice", 25)` 在分配内存后，立即调用 `Person` 的构造函数初始化 `name` 和 `age`。`malloc(sizeof(Person))` 只分配内存——那块内存中的 `name` 是未构造状态（不能使用）。对未构造的内存调用任何成员函数都是未定义行为。
>
> ② **析构函数 vs 无清理**：`delete p` 首先调用 `~Person()`（确保 `name` 这个 string 能正常释放自己的内部资源），然后才释放 `Person` 占用的内存。`free(p)` 直接释放内存——`name`（一个 `std::string`）内部的动态内存没有被释放，造成**资源泄漏**。
>
> ③ **运算符 vs 库函数**：`new` 和 `delete` 是 C++ 语言的运算符，编译器知道它们的语义。`malloc` 和 `free` 是 C 标准库的函数，只是一个普通调用。

| | `new` / `delete` | `malloc` / `free` |
|---|---|---|
| 来源 | C++ 运算符 | C 标准库函数 |
| 调用构造函数 | ✅ | ❌ |
| 调用析构函数 | ✅ | ❌ |
| 返回类型 | 类型安全指针 | `void*`（需要强转） |
| 数组形式 | `new T[n]` / `delete[] p` | `malloc(n * sizeof(T))` / `free(p)` |
| 失败行为 | 抛 `bad_alloc` 异常 | 返回 `NULL` |
| 配对错误 | `new[]` 配 `delete[]`，否则未定义行为 | 不分 |

> **常见严重错误**：
>
> - ❌ `new int` 配 `free(p)`：不会调用析构函数（虽然基本类型无所谓，但对类类型是灾难）
> - ❌ `new Person[n]` 配 `delete p`（忘了 `[]`）：只有第一个元素会被析构，后续 n-1 个元素的资源泄漏
> - ❌ `malloc(sizeof(Person))` 然后用 `p->greet()`：`string` 成员未构造，调用任何操作都是未定义行为

## 三、拷贝控制 — 三个关键操作

### 3.1 为什么需要拷贝控制？

> 如果一个类管理着动态分配的资源（如 `Vec<T>` 内部用 `new[]` 分配的内存），**默认的"浅拷贝"会导致灾难**。下面用一个简单的例子来演示浅拷贝的危害。

```cpp
class SimpleString {
    char* data;
    size_t len;
public:
    SimpleString(const char* s)
        : len(strlen(s)), data(new char[len + 1]) {
        strcpy(data, s);
        cout << "构造: \"" << data << "\"" << endl;
    }

    // ===== 拷贝控制三件套 =====

    // 1. 析构函数
    ~SimpleString() {
        cout << "析构: \"" << data << "\"" << endl;
        delete[] data;
    }

    // 2. 复制构造函数
    SimpleString(const SimpleString& other)
        : len(other.len), data(new char[other.len + 1]) {
        strcpy(data, other.data);
        cout << "复制构造: \"" << data << "\"" << endl;
    }

    // 3. 赋值运算符
    SimpleString& operator=(const SimpleString& rhs) {
        cout << "赋值: \"" << data << "\" ← \"" << rhs.data << "\"" << endl;
        if (this != &rhs) {  // 防止自我赋值！
            delete[] data;              // 释放旧资源
            len = rhs.len;
            data = new char[len + 1];  // 分配新资源
            copy(data, rhs.data);     // 复制数据
        }
        return *this;
    }

    const char* c_str() const { return data; }
};

// 使用示例
SimpleString s1("Hello");           // 构造
SimpleString s2 = s1;                // 复制构造
SimpleString s3("World");            // 构造
s3 = s1;                             // 赋值
```

> **如果不写三件套，默认的拷贝行为会怎样？**
>
> 编译器自动生成的拷贝构造和赋值运算符做的是**逐成员拷贝（memberwise copy）**——对于指针，就是拷贝**指针的值**（地址）而不是指针指向的数据。
>
> ```
> SimpleString s1("Hello");   // s1.data → [Hello]
> SimpleString s2 = s1;       // 默认: s2.data → 也指向 [Hello]（同一个地址！）
>                              // 深拷贝: s2.data → [Hello]（新的一块内存）
> ```
>
> **浅拷贝的三个致命后果**：
>
> ① **双重释放（double free）**：当 s1 和 s2 都析构时，两人都 `delete[]` 同一块内存——第二次 delete 是未定义行为（崩溃或数据损坏）。
>
> ② **悬挂指针**：如果先析构 s1，s2.data 就变成了悬空指针（dangling pointer）——指向已经被释放的内存。任何对 s2 的使用都是未定义行为。
>
> ③ **修改联动**：如果 s1.data[0] = 'X'，s2 的字符串也变了——因为它们指向同一块内存。这通常不是想要的行为。

### 3.2 三法则（Rule of Three）

> **核心原则**：如果一个类需要**析构函数**（意味着它管理着某种资源），那它**几乎一定需要复制构造函数和赋值运算符**。这就是著名的"三法则"（Rule of Three）。

```cpp
class Counter {
    int* count;  // 动态分配的共享计数器

public:
    Counter() : count(new int(0)) {
        cout << "构造: count=" << *count << endl;
    }

    // 三件套
    ~Counter() {
        cout << "析构: count=" << *count << endl;
        delete count;
    }

    Counter(const Counter& other)
        : count(new int(*other.count)) {  // 深拷贝！
        cout << "复制构造: count=" << *count << endl;
    }

    Counter& operator=(const Counter& rhs) {
        if (this != &rhs) {
            *count = *rhs.count;  // 深拷贝值（不复制指针）
        }
        cout << "赋值: count=" << *count << endl;
        return *this;
    }

    void inc() { ++(*count); }
    int get() const { return *count; }
};

// 使用示例
Counter c1;
c1.inc(); c1.inc();

Counter c2 = c1;  // 复制构造
c2.inc();
// c1 和 c2 各自独立（深拷贝）
```

> **三法则的直觉理解**：
>
> | 操作 | 做什么 | 为什么需要自定义 |
> |------|--------|-----------------|
> | **析构函数** `~T()` | 释放资源（`delete[]` 等） | 默认析构不释放动态分配的内存 |
> | **复制构造函数** `T(const T&)` | 从已有对象创建新对象 | 默认只拷贝指针（浅拷贝），需要深拷贝 |
> | **赋值运算符** `operator=` | 把已有对象替换为另一个的拷贝 | 需要释放旧资源 + 深拷贝新资源 + 防止自我赋值 |
>
> **如何判断是否需要三件套？** 一个简单的测试标准：**类的数据成员中是否有指针成员或动态分配的资源？** 如果有，几乎一定需要三件套。如果只有 `int`、`double`、`string`、`vector` 等（这些类型自己管理好了资源），默认生成的拷贝控制就够用了。

`★ Insight ─────────────────────────────────────`
如果不用深拷贝，默认的浅拷贝会让两个 `Counter` 对象的 `count` 指针指向**同一块内存**。一个对象析构后，另一个对象的 `count` 就成了**悬空指针**（dangling pointer）。这就是为什么管理资源的类必须三件套齐全。
`─────────────────────────────────────────────────`

## 四、`explicit` 关键字

> `explicit` 用于**单参数构造函数**（或者有多参数但都有默认值的情况）。它阻止编译器"自动"将参数类型转换为类类型——这种转换叫**隐式类型转换**。虽然方便，但经常导致意外行为。

```cpp
class VecInt {
    int* data;
    size_t sz;
public:
    explicit VecInt(size_t n) : sz(n), data(new int[n]()) {}
    ~VecInt() { delete[] data; }
    size_t size() const { return sz; }
};

void process(const VecInt& v) {}

// 使用示例
VecInt v1(10);   // ✅ 显式调用构造函数
// VecInt v2 = 10;  // ❌ 编译错误！explicit 阻止了隐式转换

process(VecInt(5));  // ✅ 显式创建临时对象
// process(5);       // ❌ 编译错误！不会隐式把 5 转为 VecInt
```

> **如果不加 `explicit` 会怎样？**
>
> ```cpp
> // 假设没有 explicit:
> VecInt v2 = 10;   // 合法的！编译器"聪明地"把 10 转为 VecInt(10)
> process(5);       // 合法的！编译器创建了一个临时的 VecInt(5) 传给函数
> ```
>
> 乍看方便，但极其容易引发**意外转换**——写 `v2 = 10` 本意可能是把值设为 10，但 `VecInt` 的构造函数把 10 解释为元素个数。这种歧义很容易引入难以发现的 bug。
>
> **`explicit` 的使用规则**：
>
> ① 用于**单参数构造函数**（包括有多参数但只有一个没有默认值的情况）。
>
> ② **`Vec(size_type n, const T& val = T())` 也需要 `explicit`**——虽然有两个参数，但第二个参数有默认值，所以 `Vec v = 5` 还是能隐式转换。加了 `explicit` 后只能写 `Vec v(5)` 或 `Vec v = Vec(5)`。
>
> ③ **拷贝构造函数不能是 `explicit`**（否则按值传递对象会失败）。但这一点编译器通常自动满足——拷贝构造函数的参数是同类对象的引用，不是"转型构造函数"。
>
> ④ **从 C++11 开始，`explicit` 也可以用于类型转换操作符**（见下章的应用）。

## 五、完整示例：自定义动态数组

> 下面的代码整合了前四节的所有概念：模板类、new/delete、三法则、explicit。注意每个函数为什么存在——不是"模板的样板代码"，而是**必须写的**，否则浅拷贝会带来 bug。

```cpp
template <class T>
class Vec {
public:
    typedef T* iterator;
    typedef const T* const_iterator;
    typedef size_t size_type;

    Vec() : data(nullptr), avail(nullptr), limit(nullptr) {}

    explicit Vec(size_type n, const T& val = T()) {
        data = new T[n];
        avail = limit = data + n;
        for (size_type i = 0; i < n; ++i) data[i] = val;
    }

    Vec(const Vec& v) {
        size_type n = v.size();
        data = new T[n];
        avail = limit = data + n;
        copy(v.data, v.avail, data);
    }

    ~Vec() { delete[] data; }

    Vec& operator=(const Vec& rhs) {
        if (this != &rhs) {
            delete[] data;
            size_type n = rhs.size();
            data = new T[n];
            avail = limit = data + n;
            copy(rhs.data, rhs.avail, data);
        }
        return *this;
    }

    size_type size() const { return avail - data; }
    T& operator[](size_type i) { return data[i]; }
    const T& operator[](size_type i) const { return data[i]; }

    iterator begin() { return data; }
    const_iterator begin() const { return data; }
    iterator end() { return avail; }
    const_iterator end() const { return avail; }

    void push_back(const T& val) {
        if (avail == limit) grow();
        *avail++ = val;
    }

private:
    iterator data;
    iterator avail;
    iterator limit;

    void grow() {
        size_type new_size = max(2 * size(), size_type(1));
        iterator new_data = new T[new_size];
        iterator new_avail = copy(data, avail, new_data);
        delete[] data;
        data = new_data;
        avail = new_avail;
        limit = data + new_size;
    }
};

// 使用示例：学生成绩管理
struct Student {
    string name;
    double score;
};

ostream& operator<<(ostream& os, const Student& s) {
    return os << s.name << "(" << s.score << ")";
}

Vec<int> numbers;
for (int i = 1; i <= 5; ++i)
    numbers.push_back(i * 10);

Vec<Student> class2024;
class2024.push_back({"Alice", 85.5});
class2024.push_back({"Bob", 72.0});
class2024.push_back({"Charlie", 93.5});

// 拷贝测试
Vec<int> numbers2 = numbers;  // 复制构造
numbers2[0] = 999;
// numbers[0] 未受影响（深拷贝）
```

> **上述完整示例中，模板类的每个关键函数及其必要性**：
>
> | 函数 | 必要性 | 不写会怎样？ |
> |------|--------|------------|
> | 构造函数 `Vec()` | 初始化为空状态 | data 是垃圾指针，`size()` 和 `push_back()` 调用就是未定义行为 |
> | 构造函数 `Vec(n, val)` | 创建指定大小+初始值的容器 | 只能先默认构造再逐个 push_back，低效且无法初始化容量 |
> | **复制构造函数** `Vec(const Vec&)` | 深拷贝——创建独立副本 | 浅拷贝导致两个 Vec 指向同一块内存 → 双重释放 |
> | **析构函数** `~Vec()` | 释放 `new[]` 分配的内存 | 内存泄漏——应用程序占用的内存只增不减 |
> | **赋值运算符** `operator=` | 释放旧资源 + 深拷贝新数据 | 浅拷贝 → 双重释放 + 旧内存泄漏 |
> | `push_back()` | 动态追加元素 | Vec 就是固定数组了，失去动态容器的价值 |
> | `grow()` | 扩容（翻倍策略） | 容量固定，push_back 在满时崩溃 |
>
> 注意标粗的三行——这就是**三法则**：三者缺一不可，因为任何一个的错误都会导致内存管理失控。

<a id="六总结"></a>
## 六、总结

| 知识点 | 说明 | 类比 C 语言 |
|---|---|---|
| **模板类** | `template<class T> class Vec { ... }` | 为每种类型重写一套代码 |
| **`new` / `delete`** | 动态分配 + 构造/析构 | `malloc` / `free`（不调构造/析构） |
| **析构函数** `~T()` | 对象销毁时自动释放资源 | 手动写 `cleanup()` 函数 |
| **复制构造函数** | `T(const T&)` — 深拷贝 | 手写 `clone()` 函数 |
| **赋值运算符** | `operator=(const T&)` — 注意自我赋值 | 手写 `copy_from()` 函数 |
| **三法则** | 需要析构 → 也需要复制构造 + 赋值 | （只能靠自己遵守纪律） |
| **`explicit`** | 阻止隐式类型转换 | （不存在此机制） |

### 动态内存管理速查

```
创建单个对象: p = new T(args);    delete p;
创建数组:     p = new T[n];       delete[] p;
类中管理内存: 必须提供析构、复制构造、赋值（三法则）
防止隐式转换: explicit 构造函数
防止自我赋值: if (this != &rhs) { ... }
```
