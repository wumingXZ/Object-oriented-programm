## 〇、C 语言回顾：我们以前是怎么管理数据的？

学过 C 语言的同学一定记得：

```c
// C 语言方式：固定大小数组，手动管理
#define MAX_STUDENTS 100
struct Student {
    char name[50];
    int scores[10];
    int score_count;
};
struct Student class_roster[MAX_STUDENTS];  // 预分配100个位置
int student_count = 0;

// 添加学生时：
strcpy(class_roster[student_count].name, "Alice");
class_roster[student_count].scores[0] = 95;
class_roster[student_count].score_count = 1;
student_count++;

// 删除中间的学生？（需要手动移动后面所有元素！）
for (int i = index; i < student_count - 1; i++) {
    class_roster[i] = class_roster[i+1];  // 逐元素复制
}
student_count--;
```

> C 语言管理数据的方式有三个无法回避的痛点：
>
> ① **固定大小** — `MAX_STUDENTS` 要么设太大浪费内存，要么设太小不够用。运行时如果学生超过 100 人，要么程序崩溃，要么需要手动 `realloc` 重新分配并拷贝所有数据。
>
> ② **手动管理** — 插入和删除都要自己写循环移动后续元素。删除中间一个学生，后面所有学生都要往前复制。这不仅是代码繁琐的问题——当数据量很大时，O(n) 的元素移动代价非常可观。
>
> ③ **容易出错** — 忘记更新 `student_count`、数组索引越界、用 `strcpy` 可能截断字符串、忘记检查返回值……每一处都是潜在的 bug。
>
> C++ 的容器（`vector`、`list`、`map` 等）从根本上解决了这些问题：自动管理内存、动态增长、提供统一的元素访问接口。

## 一、从 `vector` 到迭代器

### 1.1 两种遍历方式：索引 vs 迭代器

> 当我们用 `vector` 存储数据后，第一个需求就是**遍历**所有元素。C++ 提供了两种方式。
>
> 方式一（索引）来自 C 语言的习惯——用 `v[i]` 通过下标访问。但这有几个问题：
> - 如果将来把 `vector` 换成 `list`，`list` 不支持 `v[i]`（为什么？因为 `list` 是链表，节点不是连续存储，无法在 O(1) 时间内算出第 i 个元素的位置），代码必须重写
> - 索引方式**耦合**了容器的内部结构，要求容器必须支持随机访问
>
> 方式二（迭代器）是 C++ 的通用解决方案——**迭代器解耦了"遍历"和"容器类型"**。不管底层是连续存储的 `vector`，还是链表 `list`，遍历的代码几乎一模一样。这就是为什么 C++ 标准库的所有算法（`sort`、`find`、`copy` 等）都接受迭代器作为参数，而不是直接接受容器。

```cpp
vector<string> names = {"Alice", "Bob", "Charlie", "Diana"};

// 方式1：索引（来自 C 语言习惯）
for (vector<string>::size_type i = 0; i < names.size(); ++i) {
    cout << names[i] << endl;
}

// 方式2：迭代器（C++ 新方式，更通用）
for (vector<string>::const_iterator it = names.begin();
     it != names.end(); ++it) {
    cout << *it << endl;  // *it 解引用，类似 C 的 *ptr
}

// 方式3：auto + 迭代器（C++11 简化）
for (auto it = names.begin(); it != names.end(); ++it) {
    cout << it->c_str() << " (长度=" << it->size() << ")" << endl;
}

// ★ 迭代器和 C 指针的类比 ★
int arr[] = {10, 20, 30, 40};
int* p = arr;  // C 指针 → 指向数组开头
while (p != arr + 4) {  // arr+4 是"尾后"位置
    cout << *p << " ";  // *p 解引用
    ++p;                // 移动到下一个
}
```

> 需要特别理解的关键点：
>
> ① **`const_iterator` vs `iterator`** — `const_iterator` 是只读版本，通过 `*it` 只能读取不能修改。这是一个**最小权限原则**的应用：如果你只需要读数据，用 const 版本让编译器和读者都清楚意图。
>
> ② **`begin()` vs `end()`** — `begin()` 指向第一个元素，`end()` 指向**最后一个元素的下一个位置**（尾后位置）。这是一个半开区间 `[begin, end)`。为什么这样设计？因为当容器为空时，`begin() == end()`，循环条件自然不成立，不需要单独判断空容器的情况。这个设计模式贯穿整个 C++ 标准库。
>
> ③ **为什么用 `it != names.end()` 而不是 `it < names.end()`？** — 因为不是所有迭代器都支持 `<`（需要随机访问能力），但**所有迭代器都支持 `!=`**。写成 `!=` 是跨容器最通用的写法，换用 `list` 也不需要改。
>
> ④ **为什么用 `++it` 而不是 `it++`？** — 前置 `++` 直接返回自身（引用），后置 `++` 需要保存旧值的副本再自增再返回副本。对迭代器来说，前置 `++` 效率更高（虽然对现代编译器差异很小）——这是一个优良的编程习惯。

`★ Insight ─────────────────────────────────────`
**迭代器就是 C 指针的泛化**。如果你理解 `int* p = arr; *p; ++p`，你就理解了迭代器的核心思想：
- `arr` → `v.begin()`（指向第一个元素）
- `arr + n` → `v.end()`（指向最后一个元素的**下一个**位置）
- `*p` → `*it`（解引用）
- `++p` → `++it`（移动到下一个）

区别在于：迭代器是**类型安全**的（`vector<int>::iterator` 不能赋给 `vector<string>::iterator`），并且适用于所有容器。
`─────────────────────────────────────────────────`

> 迭代器的最大价值在于 **容器无关性**。同一段遍历代码，换一个容器类型不需要重写。例如：
>
> ```cpp
> template <typename Container>
> void print_all(const Container& c) {
>     for (auto it = c.begin(); it != c.end(); ++it) {
>         cout << *it << " ";
>     }
> }
> ```
>
> 这个泛型函数能用于 `vector`、`list`、`deque`、`set` 等所有标准容器。而如果用索引方式就做不到——因为不是所有容器都支持 `c[i]`。

## 二、实际问题：将学生分类

### 2.1 场景描述

期末考试后，需要把学生分为两类：**及格**（≥60分）和**不及格**（<60分）。

回顾我们在第一周写的成绩计算程序，现在要扩展它来处理**多个学生的成绩分类**。

### 2.2 方案一：创建两个 vector（简单但低效）

> 最直观的思路：遍历所有学生，按是否及格分到两个新 vector 中。最后用 `pass` 替换原容器。
>
> 这种做法**代码简单、不易出错**，但代价是内存翻倍——每个学生的数据同时存在于原容器和新容器中（直到 `students = pass` 赋值后原数据才释放）。对几百个学生微不足道，但对几十万条记录就不可接受了。

```cpp
struct Student_info {
    string name;
    double final_grade;
};

bool fgrade(const Student_info& s) {
    return s.final_grade < 60;  // 不及格
}

// 方案1：创建一个新的 pass vector（需要双倍内存）
vector<Student_info> extract_fails_v1(vector<Student_info>& students) {
    vector<Student_info> pass, fail;

    for (auto i = 0; i < students.size(); ++i) {
        if (fgrade(students[i]))
            fail.push_back(students[i]);
        else
            pass.push_back(students[i]);
    }
    students = pass;  // 用 pass 替换原容器
    return fail;
}
```

> 方案一的主要问题：
>
> ① **内存浪费** — `pass` 和 `fail` 同时存在于内存中，加上原先的 `students`，短时间内有三个 vector 包含数据。且 `students = pass` 是一次 O(n) 深拷贝（虽然可以用移动语义优化）。
>
> ② **类型耦合** — 参数是 `vector<Student_info>&`，如果需求变化要切换到 `list`，这个函数必须重写（因为用到了 `students[i]` 索引访问）。

### 2.3 方案二：原地删除（节约内存但 vector 效率低）

> 方案二的思路是：**在原容器中直接删除不及格的学生**，把被删除的元素复制到 `fail` 中返回。
>
> 核心是 `erase(it)` 的用法。这里有一个关键点：`erase(it)` 会返回**被删除元素的下一个元素的迭代器**。所以删除后不应该再执行 `++it`（否则会跳过下一个元素），而是直接使用 `erase` 返回的新迭代器继续循环。

```cpp
// 方案2：使用 erase() 原地删除
vector<Student_info> extract_fails_v2(vector<Student_info>& students) {
    vector<Student_info> fail;

    for (auto it = students.begin(); it != students.end(); ) {
        if (fgrade(*it)) {
            fail.push_back(*it);
            it = students.erase(it);  // erase 返回下一个有效迭代器
        } else {
            ++it;
        }
    }
    return fail;
}
```

> **❓ 为什么循环的 `++it` 不写在 `for` 头部？**
>
> 因为我们不是每次都前进——只有**不需要删除时**才 `++it`；**删除时 `erase` 已经返回了下一个有效位置**，不需要再前进。如果写成普通的 `for (...; ...; ++it)`，删除一个元素后又会执行一次 `++it`，导致跳过一个元素。
>
> ⚠️ **迭代器失效（Iterator Invalidation）** — 这是 C++ 容器操作中最重要的概念之一。对 `vector` 调用 `erase(it)` 后，被删除位置**及之后的所有迭代器都失效了**（因为 vector 内部要移动后续元素填补空缺）。唯一有效的迭代器就是 `erase` 返回的那个。所以必须写 `it = students.erase(it)`，不能写 `students.erase(it); it++;`。
>
> 两种方案的取舍总结：
>
> | 维度 | 方案一（新建 vector） | 方案二（原地 erase） |
> |---|---|---|
> | 内存开销 | 高（短时间三份数据） | 低（仅额外保存 fail） |
> | 代码复杂度 | 低（标准遍历 + 分支） | 中（需要理解 erase 返回模式） |
> | 执行速度 | 总体 O(n)，但复制次数多 | 删除时 O(n) 元素移动 |
> | 容器通用性 | 低（依赖索引 `[]`） | 高（使用迭代器，list 也可用） |

## 三、`list` — 高效插入和删除

> 方案二有一个隐藏的性能问题：即使我们用了迭代器，`vector::erase` 仍然是 O(n) 的！因为 vector 是连续存储的，删除中间元素后，后面的所有元素必须往前移动填补空缺。
>
> 当数据量很大且删除操作频繁时，这个 O(n) 的累计代价不可忽略。`list`（双向链表）就是为了解决这个问题而设计的——链表的插入和删除只修改相邻节点的指针，不涉及批量移动元素，**时间复杂度是 O(1)**。

`list` 是**双向链表**。每个元素独立分配，通过指针连接。插入和删除是 O(1)。

```cpp
struct Student_info {
    string name;
    double final_grade;
};
bool fgrade(const Student_info& s) { return s.final_grade < 60; }

// 使用 list：代码几乎一样，但删除效率高得多！
list<Student_info> extract_fails(list<Student_info>& students) {
    list<Student_info> fail;

    for (auto it = students.begin(); it != students.end(); ) {
        if (fgrade(*it)) {
            fail.push_back(*it);
            it = students.erase(it);  // O(1) 删除！
        } else {
            ++it;
        }
    }
    return fail;
}
```

> 这段代码看起来和 `vector` 版本几乎一模一样——这正是迭代器的威力：**遍历和操作代码不随容器类型变化**。但内部的执行机制完全不同：
>
> ① **`list::erase` 是 O(1)** — 只需要修改被删除节点前后两个节点的指针，不涉及元素移动。无论容器中有 100 个元素还是 100 万个元素，删除时间相同。
>
> ② **迭代器失效范围更小** — `list` 的迭代器在被 `erase` 后，**只有被删除的那个迭代器失效**。其他迭代器（包括指向被删除元素前后的迭代器）仍然有效。这比 vector 的"全部失效"温和得多。
>
> ③ 但 **`list` 不支持随机访问** — 不能写 `students.begin() + 5`（编译错误），也不能用 `students[i]`。链表无法在 O(1) 时间内"跳转"到第 i 个元素。
>
> ④ **代码看起来一样，真正决定性能的是容器类型的声明**——选择 `list` 还是 `vector`，不是在算法实现时决定的，而是在 `list<Student_info>` vs `vector<Student_info>` 这一行决定的。

### `vector` vs `list` 对比

| 特性 | `vector` | `list` |
|---|---|---|
| 底层结构 | 连续数组（动态） | 双向链表 |
| 随机访问 `v[i]` | ✅ O(1) | ❌ 不支持 |
| 尾部插入/删除 | ✅ O(1)（均摊） | ✅ O(1) |
| 中间插入/删除 | ❌ O(n) | ✅ O(1) |
| 内存占用 | 紧凑（无额外指针） | 每个元素多了两个指针 |
| 遍历速度 | 快（缓存友好） | 慢（指针跳转） |
| 排序 | `std::sort()` | `list::sort()`（成员函数） |

> **经验法则**：默认用 `vector`。只有当需要在中间频繁插入/删除时才考虑 `list`。
>
> 为什么默认用 `vector`？
> - 现代 CPU 对连续内存有缓存预取优化，`vector` 的遍历速度可能比 `list` 快一个数量级
> - `vector` 的随机访问能力在很多算法中是刚需（例如 `std::sort` 依赖随机访问迭代器）
> - 大多数程序的实际瓶颈并非中间插入/删除，而是遍历和查找

## 四、`map` — 关联容器

### 4.1 从 C 的角度理解 map

> 假设我们需要一个"姓名→成绩"的映射：给定一个学生姓名，快速查到他的成绩。在 C 语言中只能这样做：

```c
// C 语言：做"名字→成绩"的映射？
// 只能用两个并行的数组，手动搜索……
char names[100][50];
int scores[100];
// 查 Alice 的成绩：遍历整个数组找匹配的名字 → O(n)
```

> C 语言的这种实现有三个问题：
>
> ① **查找是 O(n) 的** — 要找到 "Alice" 的成绩，必须遍历整个 `names` 数组，用 `strcmp` 逐一比对。一万人就要比一万次。如果还要按名字排序来优化（二分查找），自己实现的代码量陡增。
>
> ② **保持同步非常脆弱** — 删除一个学生要从两个数组中同时删除，否则数据错位。这是隐式的耦合关系，编译器不会帮你检查。
>
> ③ **不够直观** — "Alice 得了 85 分"这样一个简单的自然语言描述，在代码中需要一个循环来查找。

C++ 的 `map` 直接提供了键值映射，内部使用红黑树，查找 O(log n)。

### 4.2 实际场景：学生成绩查询系统

> `map<K, V>` 是一个**关联容器**，存储的是**键值对** `pair<const K, V>`。你可以把 `map` 想象成一个"超级数组"——普通数组的索引必须是整数，而 `map` 的索引（键）可以是字符串、自定义类型等任意可比较类型（需要支持 `<` 运算符）。
>
> 使用 `map` 时最关键的注意点是 **`[]` 运算符的副作用**：如果键不存在，`m[k]` 会**自动创建一个默认值**。这很方便，但如果你只是想**查询**键是否存在，应该用 `m.find(k)`，否则会意外插入一个空元素。

```cpp
// 姓名 → 成绩的映射
map<string, double> gradebook;

// 插入成绩
gradebook["Alice"]   = 85.5;
gradebook["Bob"]     = 72.0;
gradebook["Charlie"] = 93.5;
gradebook["Diana"]   = 58.0;

// 也可以用 insert
gradebook.insert({"Eve", 88.0});

// 查询
auto it = gradebook.find("Bob");
if (it != gradebook.end()) {
    cout << it->second << "分" << endl;
}

// 遍历所有学生（自动按 key 排序）
for (const auto& entry : gradebook) {
    cout << entry.first << ": " << entry.second << endl;
}
```

> 对 `map` 关键行为的逐点解析：
>
> ① **`gradebook["Alice"] = 85.5` 实际上做了两步** — 先检查 "Alice" 是否存在：不存在则插入 `pair<string, double>("Alice", 0.0)`（`double` 默认值为 `0.0`），然后赋值 `85.5`。如果 Alice 已存在，直接覆盖原值。所以 `[]` 的语义是**"存在就更新，不存在就插入"**。
>
> ② **`insert` 和 `[]` 的行为不同** — `gradebook.insert({"Eve", 88.0})` 如果 "Eve" 已存在，**什么都不做**（不会覆盖）。所以"不存在才插入"用 `insert`，"存在也要更新"用 `[]`。这是一个容易忽略的细节。
>
> ③ **`find` 返回的是迭代器，不是 `bool`** — 为什么？因为我们需要区分"未找到"和"找到了，值为 XXX"两种状态。`find` 返回的迭代器指向整个键值对，通过 `it->first` 访问键，`it->second` 访问值。如果未找到，返回 `m.end()`。
>
> ④ **遍历时的 `const auto&`** — `map` 的键是 `const` 的（不能修改键，因为修改键会破坏内部排序），值可以修改。用 `const auto&` 避免拷贝 `pair`（每个 `pair` 包含一个 `string` 和一个 `double`，拷贝代价不低）。如果只需读数据，`const auto&` 是最优选择。

### 4.3 `map` 常用方法

| 方法 | 说明 |
|---|---|
| `m[k] = v` | 插入或更新键值对（k 不存在则插入） |
| `m.insert({k, v})` | 插入（k 已存在则不覆盖） |
| `m.emplace(k, v)` | 原地构造插入（C++11，最高效） |
| `m.at(k)` | 访问元素（k 不存在则抛出异常） |
| `m.find(k)` | 查找，返回迭代器（未找到返回 `end()`） |
| `m.erase(k)` | 删除键 k |
| `m.size()` | 键值对个数 |
| `m.clear()` | 清空 |

> **`at()` vs `[]` 的安全对比**：
>
> | 方式 | 键不存在时 | 适用场景 |
> |---|---|---|
> | `m[k]` | 静默创建默认值 | 需要"不存在就插入"时 |
> | `m.at(k)` | 抛出 `out_of_range` 异常 | 确定键应该存在，尽早暴露错误 |
>
> 如果你在写一个"肯定存在的键"的查询（例如刚插入的值），用 `at()` 更安全——能帮你尽早捕获逻辑错误。

## 五、实际场景：统计词频

> 这是容器和迭代器综合应用的好例子。我们来统计一段文本中每个单词的出现次数。
>
> 核心思路：用 `map<string, int>` 建立"单词 → 计数"的映射。每次遇到一个单词，对应的计数加 1。最巧妙的地方在于 **`++word_count[word]`** 这一行——如果 `word` 是第一次出现，`[]` 自动创建键值对并将 `int` 初始化为 `0`，然后 `++` 将其变为 `1`；如果已经出现过，`[]` 返回值的引用直接自增。一行代码同时完成了"插入"和"更新"两种逻辑。

```cpp
string text = "the quick brown fox jumps over the lazy dog "
              "the fox is quick and the dog is lazy";

map<string, int> word_count;
istringstream iss(text);
string word;

// 统计每个单词的出现次数
while (iss >> word) {
    // 转小写（简化处理）
    for (auto& c : word) c = tolower(c);
    ++word_count[word];  // 不存在则自动插入并初始化为0
}

// 找出出现次数最多的词
auto max_it = max_element(word_count.begin(), word_count.end(),
    [](const auto& a, const auto& b) {
        return a.second < b.second;
    });
```

> 逐点解析：
>
> ① **`istringstream` 自动按空白字符分割** — `iss >> word` 每次读取一个被空格、制表符、换行分隔的单词。这是 C++ 中最简单的字符串分割方式，不需要自己写 `split`。
>
> ② **`for (auto& c : word)` 中 `&` 的作用** — 如果不加 `&`，`c` 是 `char` 的副本，修改副本不会影响原字符串。加上 `&` 后 `c` 是引用，修改 `c` 就是修改 `word` 中的字符。这是范围 for 循环中一个常见的陷阱——忘记 `&` 导致修改没有生效。
>
> ③ **`++word_count[word]` 的魔法** — 完整展开后相当于：
>    ```cpp
>    // 编译器实际生成的大致逻辑：
>    auto& count = word_count[word];  // 不存在则插入 (word, 0)，返回 int&
>    ++count;                         // 自增
>    ```
>    这比手写 `if (存在) count++ else 插入1` 要简洁得多，且性能相当（因为 `[]` 的查找已经做了）。
>
> ④ **`max_element` 为什么需要 Lambda？** — `max_element` 需要知道比较规则。默认按 `pair` 的 `first`（即单词的字符串）比较，但我们想按 `second`（即出现次数）比较。所以传入 Lambda 指定规则 `return a.second < b.second`。这是 Lambda 在算法中的典型应用——为通用算法提供自定义的比较逻辑。

## 六、迭代器操作速查

> 下表总结了迭代器的核心操作以及与 C 指针的类比。建议先理解 C 指针的关系，再迁移到迭代器就容易了。

| 操作 | 说明 | 类比 C 指针 |
|---|---|---|
| `*it` | 解引用，获取元素 | `*p` |
| `it->member` | 访问成员 | `p->member` |
| `++it` | 移动到下一个 | `++p` |
| `--it` | 移动到上一个（双向） | `--p` |
| `it1 == it2` | 比较是否指向同一位置 | `p1 == p2` |
| `it1 != it2` | 比较是否指向不同位置 | `p1 != p2` |
| `it + n` | 移动 n 步（随机访问） | `p + n` |

> ⚠️ **并非所有迭代器都支持所有操作**：
> - `list` 的迭代器不支持 `it + n`（需要随机访问能力）
> - `forward_list` 的迭代器不支持 `--it`（只允许单向移动）
> - 只有 `vector`、`deque`、`string`、`array` 的迭代器才支持 `it + n`
>
> 这就是为什么在第四章中我们会系统地学习**迭代器分类**——不同类别的迭代器支持不同等级的操作，算法根据自身需求声明所需的最低迭代器类别。

## 七、第三周总结

| 知识点 | 说明 | C 语言对应 |
|---|---|---|
| `vector<T>` | 动态数组 | 手动 `malloc/realloc` + 数组 |
| `list<T>` | 双向链表 | 手写链表 `struct node { ... node* next; }` |
| `map<K, V>` | 键值映射，自动排序 | 两个并行数组 + 自己实现查找 |
| **迭代器** | 统一的元素遍历接口 | 指针（但更安全、更通用） |
| `erase(it)` | 删除迭代器指向的元素 | 手动移动后续元素 |
| `push_back(e)` | 在末尾添加元素 | `arr[count++] = e`（可能越界！） |

> **课后练习**：用 `map<string, vector<int>>` 实现一个"学生-多门课程成绩"管理系统：每位学生可以有多门课的成绩，支持按姓名查询、添加成绩、计算平均分。
