<a id="一命名空间-namespace"></a>
## 一、命名空间 `namespace`

### 1.1 为什么需要命名空间？

```cpp
// 问题：不同库定义了同名的类和函数
namespace Audio {
    class File {
    public:
        void open() { }
    };
}

namespace Video {
    class File {
    public:
        void open() { }
    };
}

// 通过命名空间区分同名的类
Audio::File audioFile;
Video::File videoFile;

audioFile.open();
videoFile.open();
```

### 1.2 命名空间的基本用法

> **命名空间的三个重要特性：** （1）**可以嵌套**——通过嵌套实现层次化组织（`MyLib::Detail::helper`）；（2）**可以分段定义**——同一个命名空间的成员可以分布在多个文件中，方便团队协作；（3）**可以起别名**——长名字可以缩短为简写。

```cpp
// 定义命名空间
namespace MyLib {
    int version = 1;
    void greet() { }

    // 命名空间可以嵌套
    namespace Detail {
        void helper() { }
    }
}

// 命名空间可以分开定义（同一个命名空间可以在多处打开）
namespace MyLib {
    void farewell() { }
}

// using 声明：引入单个名字
using MyLib::greet;

// 完整限定名访问
MyLib::farewell();
MyLib::Detail::helper();

// 命名空间别名
namespace MLD = MyLib::Detail;
MLD::helper();
```

> **代码组织的常用策略：** 头文件中声明命名空间中的函数（不需要 `using`），`.cpp` 文件中使用 `using` 声明引入需要用到的名字。嵌套命名空间常用于区分公共接口和内部实现——把实现细节放在嵌套的 `Detail` 或 `Internal` 命名空间中，对外部使用者隐藏。

### 1.3 `using` 声明 vs `using` 指示

> **"精确引入"vs"批量引入"——这是命名空间使用中最关键的决策。** 两者的区别本质上是"你知道你要用什么"和"你不知道你要用什么"。`using` 声明是精确的、克制的；`using` 指示是批量引入、容易冲突的。

```cpp
// using 声明：引入单个名字（推荐）
using std::cout;
using std::endl;

// ❌ using 指示：引入整个命名空间（不推荐在头文件）
// using namespace std;  // 污染全局命名空间！
```

| | `using` 声明 | `using` 指示 |
|---|---|---|
| 语法 | `using std::cout;` | `using namespace std;` |
| 作用 | 引入单个名字 | 引入整个命名空间 |
| 冲突风险 | 低（显式指定） | 高（大量名字涌入） |
| 推荐场景 | `.cpp` 文件和 `.h` 文件均可 | **仅限 `.cpp` 文件** |

> **为什么头文件中禁止 `using namespace std;`？** 假设你写了一个头文件 `myheader.h`，里面写了 `using namespace std;`。用户 A 在自己的 `.cpp` 中 `#include "myheader.h"`——所有标准库的名字（`string`、`vector`、`cout` 等）突然涌入了全局命名空间。如果用户 A 定义了一个叫 `vector` 的类，和 `std::vector` 冲突，调试起来非常痛苦。**头文件应该最小化引入的名字——你不需要替你头文件的使用者做决定。**
>
> **建议：** 在 `.cpp` 文件中可以写 `using namespace std;`（你完全控制该文件），但头文件中永远用 `std::` 前缀或 `using` 声明。课程作业中使用 `using namespace std;` 是教学惯例，但实际项目中需要遵守这条规则。

### 1.4 无名命名空间 — 文件私有的替代品

> **为什么需要"文件私有"的机制？** 当你在一个 `.cpp` 文件中定义一些辅助函数（只想在该文件内部使用，不想暴露给其他文件），你需要一个"文件作用域"。C 语言用 `static` 关键字做到这一点（`static void helper() { ... }`），C++ 提供了更优雅的替代方案——无名命名空间。

```cpp
// 无名命名空间：名字仅在当前文件可见（取代 C 的 static）
namespace {
    int internal_counter = 0;  // 仅在当前翻译单元可见
    void internal_func() { }
}

internal_func();
internal_counter++;
```

> **无名命名空间的工作原理：** 每个编译单元（即每个 `.cpp` 文件及其包含的头文件）都有自己独立的无名命名空间。无名命名空间中的名字在编译单元内部可以直接访问（不需要 `namespace::` 前缀），但其他编译单元无法看到它们。这实际上等价于 `static` 关键字的效果，但更灵活——`static` 只能作用于变量和函数，而无名命名空间可以包含任何声明（类型定义、类等）。
>
> **`static` vs 无名命名空间：** C++ 标准明确推荐在新代码中使用无名命名空间代替 `static`。`static` 用于文件作用域在 C++ 中已被标记为"deprecated"（废弃）。

## 二、异常处理进阶

### 2.1 标准异常类层次

C++ 标准库定义了一套异常类继承体系：

```
exception
├── logic_error
│   ├── invalid_argument
│   ├── out_of_range
│   ├── length_error
│   └── domain_error
├── runtime_error
│   ├── overflow_error
│   ├── underflow_error
│   └── range_error
└── bad_alloc
    └── bad_cast (等)
```

```cpp
// 不安全的除法和越界检查
int safe_divide(int a, int b) {
    if (b == 0)
        throw invalid_argument("除数不能为零!");
    return a / b;
}

int safe_get(const vector<int> &v, size_t idx) {
    if (idx >= v.size())
        throw out_of_range("索引越界");
    return v[idx];
}

// 按异常类型分别捕获
try {
    safe_divide(10, 2);
    // safe_divide(10, 0);  // 抛出 invalid_argument
} catch (const invalid_argument &e) {
    // 参数错误
} catch (const out_of_range &e) {
    // 越界错误
} catch (const exception &e) {
    // 其他异常
}

// 越界捕获
vector<int> v{1, 2, 3};
try {
    safe_get(v, 5);
} catch (const out_of_range &e) {
    // 捕获到越界
}
```

### 2.2 `catch` 的匹配规则

```cpp
try {
    throw runtime_error("一个运行时错误");
}
// catch 块从上到下匹配，找到第一个兼容的就停止
catch (const runtime_error &e) {     // 先匹配更具体的
    // runtime_error
}
catch (const exception &e) {         // 后匹配更宽泛的
    // exception
}
// catch (...) { ... }               // 捕获所有异常（放在最后）

// ⚠️ 注意：catch 的顺序很重要！派生类要放在基类前面
// catch (const exception &e) 在前 → runtime_error 永远不会被后面的 catch 捕获
```

### 2.3 构造函数中的 `try` 块

> **为什么构造函数需要特殊的 `try` 块？** 普通成员函数中，`try-catch` 可以包裹整个函数体。但构造函数不同——它有一个"初始化列表"，在进入函数体之前就已经执行了。如果初始化列表（如 `data_(new int[size])`）抛出了异常，函数体内的 `try` 块是捕获不到的。构造函数的 `try` 块可以包裹**包括初始化列表在内的整个构造过程**。

```cpp
class Resource {
    string name_;
    int *data_;
public:
    // 构造函数 try 块：捕获初始化列表中的异常
    Resource(const string &name, int size)
        try : name_(name), data_(new int[size]) {
            if (size <= 0)
                throw invalid_argument("size 必须 > 0");
        } catch (...) {
            // 初始化列表中的异常会在这里被捕获
            throw;  // 构造函数 try 块会自动重新抛出
        }

    ~Resource() {
        delete[] data_;
    }
};

try {
    Resource r1("R1", 100);
    Resource r2("R2", -5);   // 抛出异常
} catch (const exception &e) {
    // main 捕获
}
```

> **关键注意事项：**
> 1. 构造函数 `try` 块中，`catch` 块必须重新抛出异常（或抛出新异常）——构造函数必须让调用者知道构造失败了
> 2. 即使你在 `catch` 块中处理了异常，对象仍然被视为"构造失败"——析构函数**不会**被调用（因为对象从未完成构造）
> 3. 构造函数 `try` 块很少使用——大多数情况下，在函数体内用 `try-catch` 包裹初始化逻辑或用函数处理有风险的初始化就足够了

### 2.4 `noexcept` — 承诺不抛异常

```cpp
// noexcept：承诺不抛异常（编译器可以优化，标准库容器会检查）
void safe_func() noexcept {
    // 这个函数承诺不抛异常
}

void might_throw() {
    // 这个函数可能抛异常
}

// noexcept 可以作为运算符检查表达式
noexcept(safe_func());        // true
noexcept(might_throw());      // false

// 移动操作应该标记 noexcept（否则 vector 扩容会用拷贝）
noexcept(string(move(*(new string()))));

// 条件 noexcept
auto lambda = []() noexcept(true) { /* 不抛异常 */ };
noexcept(lambda());
```

## 三、自定义异常类

```cpp
// 自定义异常：继承自标准异常类
class DatabaseException : public runtime_error {
public:
    explicit DatabaseException(const string &msg)
        : runtime_error("数据库错误: " + msg) {}
};

class ConnectionException : public DatabaseException {
    string host_;
public:
    ConnectionException(const string &host, const string &msg)
        : DatabaseException(msg), host_(host) {}

    const string &host() const { return host_; }
};

try {
    throw ConnectionException("db.example.com", "连接超时");
} catch (const ConnectionException &e) {
    // e.what()
    // e.host()
} catch (const DatabaseException &e) {
    // e.what()
} catch (const exception &e) {
    // 未知错误
}
```

## 四、补充总结

### 命名空间速查

| 特性 | 语法 | 用途 |
|---|---|---|
| 定义 | `namespace N { ... }` | 创建命名空间 |
| 使用单个名字 | `using N::f;` | 精确引入 |
| 使用整个空间 | `using namespace N;` | 批量引入（仅 .cpp 文件） |
| 别名 | `namespace N2 = N1;` | 简化长名字 |
| 嵌套 | `namespace A::B { ... }` | 层次化（C++17: `namespace A::B { }`) |
| 匿名 | `namespace { ... }` | 文件私有 |

### 异常处理速查

| 知识点 | 关键结论 |
|---|---|
| 捕获顺序 | 派生类在前，基类在后 |
| `catch (...)` | 捕获所有异常，放在最后 |
| `exception::what()` | 获取错误信息 |
| 构造函数 try | 捕获初始化列表中的异常 |
| `noexcept` | 承诺不抛异常；移动操作必须标记 |
| 自定义异常 | 继承自 `exception` / `runtime_error` / `logic_error` |
| 不抛就析构 | 永远不要从析构函数中抛出异常！ |
