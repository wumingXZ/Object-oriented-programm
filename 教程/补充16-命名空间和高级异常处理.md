<a id="一命名空间-namespace"></a>
## 一、命名空间 `namespace`

### 1.1 为什么需要命名空间？

```cpp
// 问题：不同库定义了同名的类和函数
namespace Audio {
    class File {
    public:
        void open() { }
    };
}

namespace Video {
    class File {
    public:
        void open() { }
    };
}

// 通过命名空间区分同名的类
Audio::File audioFile;
Video::File videoFile;

audioFile.open();
videoFile.open();
```

### 1.2 命名空间的基本用法

```cpp
// 定义命名空间
namespace MyLib {
    int version = 1;
    void greet() { }

    // 命名空间可以嵌套
    namespace Detail {
        void helper() { }
    }
}

// 命名空间可以分开定义（同一个命名空间可以在多处打开）
namespace MyLib {
    void farewell() { }
}

// using 声明：引入单个名字
using MyLib::greet;

// 完整限定名访问
MyLib::farewell();
MyLib::Detail::helper();

// 命名空间别名
namespace MLD = MyLib::Detail;
MLD::helper();
```

### 1.3 `using` 声明 vs `using` 指示

```cpp
// using 声明：引入单个名字（推荐）
using std::cout;
using std::endl;

// ❌ using 指示：引入整个命名空间（不推荐在头文件）
// using namespace std;  // 污染全局命名空间！
```

| | `using` 声明 | `using` 指示 |
|---|---|---|
| 语法 | `using std::cout;` | `using namespace std;` |
| 作用 | 引入单个名字 | 引入整个命名空间 |
| 冲突风险 | 低（显式指定） | 高（大量名字涌入） |
| 推荐场景 | `.cpp` 文件和 `.h` 文件均可 | **仅限 `.cpp` 文件** |

> **铁律：永远不要在头文件中使用 `using namespace std;` 或 `using` 指示！** 这会让所有包含该头文件的 `.cpp` 文件都被强制污染。

### 1.4 无名命名空间 — 文件私有的替代品

```cpp
// 无名命名空间：名字仅在当前文件可见（取代 C 的 static）
namespace {
    int internal_counter = 0;  // 仅在当前翻译单元可见
    void internal_func() { }
}

internal_func();
internal_counter++;
```

> C++ 推荐用无名命名空间代替 C 的 `static` 来定义文件私有的变量和函数。

## 二、异常处理进阶

### 2.1 标准异常类层次

C++ 标准库定义了一套异常类继承体系：

```
exception
├── logic_error
│   ├── invalid_argument
│   ├── out_of_range
│   ├── length_error
│   └── domain_error
├── runtime_error
│   ├── overflow_error
│   ├── underflow_error
│   └── range_error
└── bad_alloc
    └── bad_cast (等)
```

```cpp
// 不安全的除法和越界检查
int safe_divide(int a, int b) {
    if (b == 0)
        throw invalid_argument("除数不能为零!");
    return a / b;
}

int safe_get(const vector<int> &v, size_t idx) {
    if (idx >= v.size())
        throw out_of_range("索引越界");
    return v[idx];
}

// 按异常类型分别捕获
try {
    safe_divide(10, 2);
    // safe_divide(10, 0);  // 抛出 invalid_argument
} catch (const invalid_argument &e) {
    // 参数错误
} catch (const out_of_range &e) {
    // 越界错误
} catch (const exception &e) {
    // 其他异常
}

// 越界捕获
vector<int> v{1, 2, 3};
try {
    safe_get(v, 5);
} catch (const out_of_range &e) {
    // 捕获到越界
}
```

### 2.2 `catch` 的匹配规则

```cpp
try {
    throw runtime_error("一个运行时错误");
}
// catch 块从上到下匹配，找到第一个兼容的就停止
catch (const runtime_error &e) {     // 先匹配更具体的
    // runtime_error
}
catch (const exception &e) {         // 后匹配更宽泛的
    // exception
}
// catch (...) { ... }               // 捕获所有异常（放在最后）

// ⚠️ 注意：catch 的顺序很重要！派生类要放在基类前面
// catch (const exception &e) 在前 → runtime_error 永远不会被后面的 catch 捕获
```

### 2.3 构造函数中的 `try` 块

```cpp
class Resource {
    string name_;
    int *data_;
public:
    // 构造函数 try 块：捕获初始化列表中的异常
    Resource(const string &name, int size)
        try : name_(name), data_(new int[size]) {
            if (size <= 0)
                throw invalid_argument("size 必须 > 0");
        } catch (...) {
            // 初始化列表中的异常会在这里被捕获
            throw;  // 构造函数 try 块会自动重新抛出
        }

    ~Resource() {
        delete[] data_;
    }
};

try {
    Resource r1("R1", 100);
    Resource r2("R2", -5);   // 抛出异常
} catch (const exception &e) {
    // main 捕获
}
```

### 2.4 `noexcept` — 承诺不抛异常

```cpp
// noexcept：承诺不抛异常（编译器可以优化，标准库容器会检查）
void safe_func() noexcept {
    // 这个函数承诺不抛异常
}

void might_throw() {
    // 这个函数可能抛异常
}

// noexcept 可以作为运算符检查表达式
noexcept(safe_func());        // true
noexcept(might_throw());      // false

// 移动操作应该标记 noexcept（否则 vector 扩容会用拷贝）
noexcept(string(move(*(new string()))));

// 条件 noexcept
auto lambda = []() noexcept(true) { /* 不抛异常 */ };
noexcept(lambda());
```

## 三、自定义异常类

```cpp
// 自定义异常：继承自标准异常类
class DatabaseException : public runtime_error {
public:
    explicit DatabaseException(const string &msg)
        : runtime_error("数据库错误: " + msg) {}
};

class ConnectionException : public DatabaseException {
    string host_;
public:
    ConnectionException(const string &host, const string &msg)
        : DatabaseException(msg), host_(host) {}

    const string &host() const { return host_; }
};

try {
    throw ConnectionException("db.example.com", "连接超时");
} catch (const ConnectionException &e) {
    // e.what()
    // e.host()
} catch (const DatabaseException &e) {
    // e.what()
} catch (const exception &e) {
    // 未知错误
}
```

## 四、补充总结

### 命名空间速查

| 特性 | 语法 | 用途 |
|---|---|---|
| 定义 | `namespace N { ... }` | 创建命名空间 |
| 使用单个名字 | `using N::f;` | 精确引入 |
| 使用整个空间 | `using namespace N;` | 批量引入（仅 .cpp 文件） |
| 别名 | `namespace N2 = N1;` | 简化长名字 |
| 嵌套 | `namespace A::B { ... }` | 层次化（C++17: `namespace A::B { }`) |
| 匿名 | `namespace { ... }` | 文件私有 |

### 异常处理速查

| 知识点 | 关键结论 |
|---|---|
| 捕获顺序 | 派生类在前，基类在后 |
| `catch (...)` | 捕获所有异常，放在最后 |
| `exception::what()` | 获取错误信息 |
| 构造函数 try | 捕获初始化列表中的异常 |
| `noexcept` | 承诺不抛异常；移动操作必须标记 |
| 自定义异常 | 继承自 `exception` / `runtime_error` / `logic_error` |
| 不抛就析构 | 永远不要从析构函数中抛出异常！ |
