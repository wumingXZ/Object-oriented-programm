## 〇、C 语言回顾：文件操作

> C 语言的文件操作函数是 C++ IO 库设计的最好反例——看懂 C 的痛点，你就能理解 C++ 为 IO 做的每一项改进。

```c
FILE *fp = fopen("data.txt", "w");
if (fp == NULL) { /* 错误处理 */ }

fprintf(fp, "Hello, file!\n");
fclose(fp);

fp = fopen("data.txt", "r");
char buf[100];
fgets(buf, sizeof(buf), fp);
fclose(fp);

// C 的问题：
// 1. FILE* 是裸指针，容易忘记 fclose（资源泄漏）
// 2. 格式化字符串 printf/scanf 不是类型安全的
// 3. 错误处理依赖于全局 errno
// 4. 没有 string 类型，字符串操作繁琐
```

> **C++ 如何解决这些问题？** （1）用 RAII 管理文件流——析构函数自动关闭文件，无需手动 `fclose()`；（2）`<<` 和 `>>` 运算符是类型安全的——编译器会检查类型而非依赖格式化字符串；（3）用流状态（`good()`/`fail()`/`bad()`）代替全局 `errno`；（4）`string` 类直接支持 IO 操作，不需要数组和缓冲区管理。

## 一、IO 类层次结构

> **IO 类体系的继承结构是 C++ 多态的一个绝佳实例：** 所有 IO 类共享一个基类接口，所以你可以用 `ifstream` 的地方也可以用 `istringstream`——只要"从某个地方读数据"就行。这也意味着你为 `ostream` 写的输出函数（重载 `<<`），天然适用于 `ofstream`（写入文件）和 `ostringstream`（写入字符串）。

C++ 的 IO 库基于继承体系：

```
ios_base
  └── ios
       ├── istream  (cin)
       │    └── ifstream
       ├── ostream  (cout, cerr, clog)
       │    └── ofstream
       └── iostream
            ├── fstream
            └── stringstream (istringstream, ostringstream)
```

| 头文件 | 核心类 | 用途 |
|---|---|---|
| `<iostream>` | `istream`, `ostream`, `iostream` | 控制台 IO |
| `<fstream>` | `ifstream`, `ofstream`, `fstream` | 文件 IO |
| `<sstream>` | `istringstream`, `ostringstream`, `stringstream` | 字符串 IO |

> **三个头文件，三个 IO 目标：** 屏幕（控制台）、文件、字符串。你只需要学会一套 `<<` / `>>` 语法，就能操作这三个 IO 目标。这正是"一致性接口"的设计力量。

## 二、文件输入输出 `<fstream>`

### 2.1 写入文件

> **`ofstream` 的核心设计理念：** "和 `cout` 一样用"。你不需要学习一套新的 API——打开文件、用 `<<` 写入、关闭文件，就这么简单。这种一致性是 C++ 流库最大的优点。

```cpp
// ofstream 用于写文件
ofstream outFile("output.txt");

if (!outFile) {
    // 无法打开文件
}

// 向文件写入（用法和 cout 完全一样！）
outFile << "=== 学生成绩单 ===" << endl;
outFile << "姓名: 张三" << endl;
outFile << "期中: 85, 期末: 90" << endl;
outFile << "最终成绩: 88.5" << endl;

outFile.close();  // 显式关闭（析构时也会自动关闭）
```

> **是否需要主动 `close()`？** 不需要——`outFile` 离开作用域时，析构函数会自动关闭文件并释放资源（这是 RAII 的核心思想）。但主动 `close()` 有两个好处：（1）尽早释放文件句柄，避免资源占用过长；（2）可以检查 `close()` 是否成功（虽然大多数代码忽略这个检查）。

### 2.2 读取文件

> **文件读取的两种策略：**
> - **逐行 `getline`**：适合按行组织的文本（如 CSV、日志、配置文件）。每行是一个完整的语义单元。
> - **逐词 `>>`**：适合按空白符分隔的数据（如名字、数字）。`>>` 自动跳过空格和换行。
>
> 选择哪种取决于你的数据格式——如果每行的含义取决于行号，用 `getline`；如果数据只是"一堆数字"，用 `>>`。

```cpp
// 先确保有文件可读
ofstream("sample.txt") << "第一行: Hello\n第二行: World\n第三行: C++";

// ifstream 用于读文件
ifstream inFile("sample.txt");

if (!inFile) {
    // 无法打开文件
}

// 方式1：逐行读取
string line;
while (getline(inFile, line)) {
    // 处理每一行
}

// 方式2：逐词读取（重置文件指针）
inFile.clear();             // 清除 EOF 状态
inFile.seekg(0, ios::beg);  // 回到文件开头

string word;
while (inFile >> word) {
    // 处理每个词
}

inFile.close();
```

> **为什么读取后要 `clear()` 才能 `seekg`？** 当你用 `getline` 读到文件末尾时，流会设置 `eofbit`（结束标志）。在这个状态下，流拒绝任何后续的读取操作——包括 `seekg`。`clear()` 清除所有错误状态标志，然后 `seekg` 才能将读取位置复位到开头。

### 2.3 文件打开模式

> **理解默认行为：** `ofstream("test.txt")` 默认使用 `out | trunc` 模式——意味着文件存在的话，内容会被**清空**后重新写入。如果不想清空而是要追加内容，必须显式指定 `ios::app`。忘记这一点是文件 IO 中最常见的错误之一。

```cpp
// 常用打开模式
// ios::in      — 读模式（ifstream 默认）
// ios::out     — 写模式（ofstream 默认）
// ios::app     — 追加模式（每次写入都在文件末尾）
// ios::ate     — 打开后定位到文件尾
// ios::trunc   — 截断文件（ofstream 默认）
// ios::binary  — 二进制模式

// 写模式 + 截断（默认）
ofstream f1("test.txt");
f1 << "第一次写入\n";
f1.close();

// 追加模式
ofstream f2("test.txt", ios::app);
f2 << "追加的内容\n";
f2.close();
```

> **常见组合速查：**
>
> | 场景 | 代码 | 说明 |
> |---|---|---|
> | 写入新内容（覆盖旧文件） | `ofstream f("f.txt");` | 默认 `out | trunc` |
> | 追加到文件末尾 | `ofstream f("f.txt", ios::app);` | 不清空，在尾部写 |
> | 读取文件 | `ifstream f("f.txt");` | 默认 `in` |
> | 读写已有文件 | `fstream f("f.txt");` | 默认 `in | out` |
> | 二进制模式 | `ofstream f("f.bin", ios::binary);` | 不转换换行符 |

### 2.4 实战：读取学生成绩文件

```cpp
// 结构体：存储一行学生数据
struct Student {
    string name;
    double midterm;
    double final;
    vector<double> homework;
};

// 创建示例输入文件
{
    ofstream f("students.txt");
    f << "Alice 85 90 95 88 92 90 87\n";
    f << "Bob 72 75 80 78 85\n";
    f << "Charlie 93 95 98 90 92\n";
}

ifstream in("students.txt");
if (!in) {
    // 无法打开文件
}

vector<Student> students;
string line;

while (getline(in, line)) {
    istringstream record(line);
    Student s;
    record >> s.name >> s.midterm >> s.final;

    // 读取所有作业成绩
    double score;
    while (record >> score) {
        s.homework.push_back(score);
    }

    students.push_back(s);
}
```

## 三、字符串流 `<sstream>`

### 3.1 `istringstream` — 从字符串读数据

> **为什么需要从字符串读数据？** 这是"解析"操作的核心——当你的程序从文件读取一行数据后，通常需要把这一行字符串拆分成多个有意义的字段（如名字、分数）。`istringstream` 就是做这件事的工具：它把 `string` 包装成"流"，让你可以使用 `>>` 运算符一个一个地提取字段。

```cpp
string data = "Alice 85 90 95 88 92";

// istringstream 把 string 当输入流用
istringstream iss(data);

string name;
iss >> name;  // 读名字

vector<int> scores;
int score;
while (iss >> score) {
    scores.push_back(score);
}
```

> **与文件 IO 结合：** 最常见的模式是 `getline` 读行 → `istringstream` 解析行。这让你能逐行处理文件，同时灵活地解析每行的多个字段。注意这里的 `while (iss >> score)` 利用了"流可以隐式转为 bool"的特性——当 `iss` 读完所有整数后，再次 `>>` 会失败，循环正常结束。

### 3.2 `ostringstream` — 往字符串写数据

> **`ostringstream` 解决的核心问题：** 当你想把多个不同类型的数据拼接成一个字符串时，传统的做法是 "+" 拼接——但这涉及多次字符串拷贝，效率低且代码难看。`ostringstream` 让你可以像写 `cout` 一样格式化数据，最后通过 `.str()` 一次性获取结果字符串。

```cpp
// ostringstream 把 string 当输出流用
ostringstream oss;

// 格式化输出到字符串
oss << "=== 成绩报告 ===" << endl;
oss << fixed << setprecision(2);
oss << "平均分: " << 88.567 << endl;
oss << "最高分: " << 98.0 << endl;
oss << "最低分: " << 72.5 << endl;

// 获取最终的字符串
string report = oss.str();

// 通用转换函数（C++11）
int i = 42;
double d = 3.14;
string si = to_string(i);
string sd = to_string(d);

// 字符串转数字（C++11）
int i2 = stoi("42");
double d2 = stod("3.14");
```

> **`ostringstream` vs `to_string`：** 如果只是简单地把一个数字转成字符串，`to_string(i)` 更简洁。但如果你需要控制格式（如小数位数、填充字符），则必须用 `ostringstream` + `<iomanip>` 的格式化工具。
>
> **C++ `stoi`/`stod` vs C 的 `atoi`/`atof`：**
> - `stoi("42abc")` 返回 42（解析到非数字字符为止）——C++ 的 `from_chars` 是更好的选择
> - `atoi("abc")` 返回 0（静默失败，无法区分"输入是0"和"输入无效"）
> - `stoi` 在输入无效时会抛出 `invalid_argument` 异常——错误能被明确捕获

### 3.3 综合示例：解析 CSV 格式

```cpp
string csv_data = "张三,85,90,88\n李四,72,75,80\n王五,93,95,98";

istringstream iss(csv_data);
string line;

while (getline(iss, line)) {
    istringstream lineStream(line);
    string field;
    vector<string> fields;

    // 以逗号为分隔符
    while (getline(lineStream, field, ',')) {
        fields.push_back(field);
    }
}
```

## 四、IO 状态管理

### 4.1 流的条件状态

> **为什么 IO 操作可能失败？** 输入无效（如输入"abc"给一个 `int` 变量）、文件损坏、磁盘满、网络断开——这些都会导致流进入错误状态。C++ 的流状态设计让你可以检测并恢复这些错误，而不是让程序崩溃或产生错误数据。

```cpp
// 模拟用户输入：把 cin 替换为 istringstream 来演示
istringstream input("abc\n42");  // 第一次输入无效，第二次有效
int number;

// 检查输入是否成功
while (!(input >> number)) {
    input.clear();  // 清除错误状态
    input.ignore(numeric_limits<streamsize>::max(), '\n');  // 丢弃输入缓冲
}
```

> **这段代码解释——标准输入校验模式：**
> 1. `input >> number` 尝试读取一个整数——如果失败，流设置 `failbit`
> 2. `!(input >> number)` 为 true——进入循环
> 3. `input.clear()` 清除错误状态——这样流才能继续读取
> 4. `input.ignore(...)` 跳过当前行的剩余内容（包括换行符）——防止相同错误数据被反复读取
> 5. 再次尝试读取——直到读取成功或文件结束
>
> 这个模式是处理用户输入的通用方案——即使在 `cin` 上也完全适用。

### 4.2 流状态标志

| 状态 | 含义 | 检测方法 |
|---|---|---|
| `goodbit` | 无错误 | `cin.good()` |
| `eofbit` | 到达文件尾 | `cin.eof()` |
| `failbit` | IO 操作失败（可恢复） | `cin.fail()` |
| `badbit` | 流已崩溃（不可恢复） | `cin.bad()` |

```cpp
// 演示各种状态
istringstream iss("42");

int x;
iss >> x;
// good(), eof(), fail(), bad() 检查流状态

// 再读一次——应该失败（没有更多数据）
iss >> x;

// 流可以隐式转为 bool——方便做条件判断
if (iss) {
    // 流状态良好
} else {
    // 流状态不佳
}
```

## 五、`flush` / `ends` / `unitbuf` — 缓冲区管理

> **为什么需要缓冲区？** 每次 IO 操作都直接调用操作系统内核（系统调用）是非常昂贵的。C++ 的 IO 库在内存中维护一个缓冲区——积累到一定量或遇到换行符时才真正写入输出设备（如屏幕、文件）。这种"攒一批再写"的策略大大提升了性能。
>
> 但有些场景需要**立即写入**——程序崩溃时日志需要被写到磁盘，提示语需要立即显示在屏幕上。下面这些操作控制着刷新时机：

```cpp
// endl：换行 + 刷新
// flush：只刷新，不换行
// ends：插入 \0 + 刷新（stringstream 场景使用）

// unitbuf：每次输出后自动刷新
cout << unitbuf;      // 开启自动刷新
cout << "A" << "B" << "C";
cout << nounitbuf;    // 恢复默认缓冲
```

> **何时用哪种？**
> - `endl` 最常用——换行且刷新（但频繁使用会降低性能，因为刷新是昂贵的操作）
> - `"\n"` 更高效——纯换行不刷新（日志文件中推荐使用）
> - `flush` 用于进度显示——进度条需要逐字符输出时不换行但要刷新
> - `unitbuf` 用于调试——`cerr` 默认就是 `unitbuf`（所以错误信息总是立即显示）
>
> **性能提示：** 非交互场景下（如写日志文件），用 `"\n"` 代替 `endl` 可以显著提升写入速度，因为避免了不必要的刷新操作。

## 六、补充总结

### 核心要点

| 知识点 | 关键结论 |
|---|---|
| 文件 IO | `ifstream`/`ofstream` 用法和 `cin`/`cout` 一样 |
| 字符串流 | `istringstream` 用来解析字符串，`ostringstream` 用来构建字符串 |
| 打开模式 | `ios::app` 追加，`ios::trunc` 截断，`ios::binary` 二进制 |
| 状态检查 | 流可隐式转 `bool`——直接 `if (cin)` 用于判断 |
| `endl` vs `\n` | `endl` = `\n` + `flush`；不需要立即刷新时用 `\n` 性能更好 |
| 数字转换 | C++11: `to_string()` / `stoi()` / `stod()` |

- **第03周** 讲的容器操作可以结合文件 IO 做数据持久化
- **第05周** 的类可以重载 `>>` 和 `<<` 操作符（见第07周），直接读写自定义类型
- 字符串流是实现"字符串到对象"的反序列化的核心工具
