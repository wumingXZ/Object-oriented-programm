## 一、C++ 的第一个程序：Hello World

> 这是 C++ 中最简单的完整程序——虽然只有一行有效代码，却包含了每个 C++ 程序都必需的骨架。下面逐点拆解每一部分的含义，这是理解后续所有 C++ 代码的基础。

```cpp
// 你的第一个 C++ 程序
std::cout << "Hello, world!" << std::endl;
```

> **这个程序涉及了四个关键机制，每个都有独特的作用：**
>
> **① `#include <iostream>` — 引入标准输入输出库。** `std::cout` 和 `std::endl` 都定义在这个头文件中。没有这行，编译器会说 `cout was not declared in this scope`。可以这样理解：你要用电饭煲（`cout`），就必须先把它从仓库（`iostream`）搬出来。`#include` 的本质是将头文件的内容**原封不动地插入**到当前文件中——这是编译前的文件合并操作。
>
> **② `std::cout` — 标准输出流对象。** `cout` 是 C++ 标准库预置的一个全局对象，关联到终端屏幕。你向它写入数据，数据就会显示在屏幕上。类似的，`std::cin` 关联到键盘输入。
>
> **③ `<<` — 输出操作符。** 它的原始含义是"位左移"。通过**操作符重载**，标准库赋予了它"向流中写入数据"的新含义。`std::cout << "Hello"` 的意思是把 `"Hello"` 这个字符串**插入**到 `cout` 这个输出流中。`<<` 的尖角指向"流"的方向——数据从右流向左。
>
> **④ `std::endl` — 换行并刷新缓冲区。** `endl` 做两件事：(1) 输出换行符 `\n`；(2) **刷新缓冲区**（flush），确保内容立即出现在屏幕上，而不是在缓冲区里积攒。**调试时发现输出迟迟没有显示，最常见的原因就是缺少 `endl` 或 `flush`。** 如果程序崩溃了，缓冲区的数据会丢失。
>
> **`return 0;` 可以不写吗？** 在 `main` 函数中可以省略——C++ 编译器会自动在末尾补一个 `return 0;`。`0` 表示"程序正常结束"，非零值表示"出现错误"（具体含义由操作系统解释）。但显式写出更清晰，是良好习惯。

### 逐行解析

| 代码元素 | 含义 |
|---|---|
| `#include <iostream>` | 包含标准输入输出流库 |
| `int main()` | 主函数——每个 C++ 程序必须有，是程序的入口 |
| `std::cout` | 标准输出流对象 |
| `<<` | 输出操作符（左结合） |
| `std::endl` | 结束当前输出行并刷新缓冲区 |
| `return 0;` | 向操作系统返回状态码 |

> **`int main()` 为什么返回 `int`？** `main` 的返回值是给操作系统看的。程序执行后，操作系统可以获取这个返回值来判断程序是否成功结束。这就是"退出码"（exit code）的来源——Shell 中用 `echo $?`（Linux/Mac）或 `echo %ERRORLEVEL%`（Windows）查看。

### 操作符 `<<` 的链式调用

> `<<` 有一个重要特性：**它会返回左边的流对象本身**，让你可以连续追加数据。这叫作"链式调用"（chaining），是 C++ 流操作中最常用的写法。

```cpp
std::cout << "Hello, " << "world!" << std::endl;
(std::cout << "Hello, ") << "world!" << std::endl;
// 每一次 << 都返回左边的 ostream 对象，因此可以继续链式调用
```

> **为什么能链式调用？** 因为 `<<` 的返回值就是左边的 `ostream` 对象。`(std::cout << "Hello, ")` 执行后返回 `std::cout` 自身，然后作为下一个 `<<` 的左操作数。记住：`<<` 是**左结合**的，所以上面两行完全等价——编译器将第一行自动解析为 `( (std::cout << "Hello, ") << "world!" ) << std::endl;`。
>
> 链式调用不是 `<<` 独有的——任何返回 `*this` 的成员函数都能实现链式调用，后续章节中你自己写的类也可以这样做。

## 二、名字空间 `std::`

> C++ 标准库定义了成百上千的名字——`cout`、`cin`、`string`、`vector`、`sort`……如果全放在全局作用域，你很容易**名字冲突**（比如自己也写了一个叫 `sort` 的函数）。**名字空间**（namespace）用于解决这个问题：把所有标准库名字放进 `std` 这个"房间"里，用 `std::` 前缀指明"去 `std` 房间查找这个名"。

```cpp
// 方式1：使用 using 声明（推荐，精确控制）
using std::cout;
using std::endl;

// 方式2：直接使用全限定名
// 方式3：using namespace std;（不推荐在头文件中使用）

cout << "无需 std:: 前缀了!" << endl;
```

> **三种使用方式的选择指南：**
>
> | 方式 | 示例 | 适用场景 | 注意事项 |
> |---|---|---|---|
> | **全限定名** | `std::cout << x;` | 头文件、追求清晰的小代码片段 | 最安全，但书写繁琐 |
> | **using 声明** | `using std::cout;` | `.cpp` 文件中 | 精确控制，只引入需要的名字，**推荐使用** |
> | **using 指令** | `using namespace std;` | 教学示例、小型 `.cpp` 文件 | 引入整个名字空间，**头文件中绝对禁止** |
>
> **为什么头文件中绝对不能写 `using namespace std;`？** 头文件会被其他文件 `#include`。如果头文件写了 `using namespace std;`，所有包含它的文件都会**被迫**引入整个 `std` 名字空间——名字冲突的风险被扩散到整个项目。这个原则适用于所有名字空间，不只有 `std`。
>
> **`::`** 是**作用域操作符**（scope operator）。`std::cout` 的含义是：在名字空间 `std` 的范围内查找 `cout`。这就像用"国家::城市::街道"来精确定位。

## 三、字符串类型 `std::string`

> C 语言的字符串用 `char[]` 字符数组配合 `strcpy`、`strlen` 等函数处理——操作繁琐，且容易缓冲区溢出。C++ 的 `std::string` 是一个**完整的类类型**，封装了存储、拷贝、长度查询、连接等操作，**自动管理内存**，比 C 字符串安全得多。在学习 `string` 时，请注意它和 C 风格字符串的关系与区别。

### 3.1 基本使用：读入名字并打招呼

```cpp
string name;         // 定义一个 string 变量
cin >> name;         // 从标准输入读入（遇到空白停止）
cout << "Hello, " << name << "!" << endl;
```

> **`cin >> name` 的读取规则：跳过前导空白，遇到下一个空白停止。**
>
> 所以如果输入 `Alice Wang`，`name` 只会得到 `"Alice"`，而 `"Wang"` 会留在输入流中等待下一次读取。这是初学者最常见的"第一个坑"。如果确实需要读入包含空格的一整行，用 `getline(cin, name)`。但本章暂时使用单词语入。

### 3.2 字符串的连接

```cpp
string greeting = "Hello, " + string("world") + "!";
cout << greeting << endl;
cout << "字符串长度: " << greeting.size() << endl;
```

> **`string` 用 `+` 连接字符串，这是 C 字符串做不到的。** 但注意一个关键限制：
>
> **`+` 的左右两侧至少有一侧是 `std::string` 类型**，才能触发 `string` 的 `+` 操作符重载。`"Hello, "` 是 `const char*`（C 风格字符串），它不支持 `+`。必须通过构造 `string("world")` 让一侧变成 `string`。
>
> - ✅ 正确：`s1 + "world"` 或 `"Hello" + s2` 或 `s1 + s2`
> - ❌ 错误：`"Hello, " + "world"` → 编译错误
>
> **`.size()` 返回字符串中的字符个数**。`"world"` 的 `size()` 是 5，不是 6——C++ 的 `string` 内部管理 `\0`，你不用担心它。这一点和 C 语言的 `strlen` 返回值相同。

### 3.3 装框输出 — 综合练习

> 这个练习把前面学的所有 `string` 操作综合运用。目标：输入一个名字，输出带框的问候语。
>
> ```
> ************
> * Hello, Alice! *
> ************
> ```
>
> **关键挑战：** 框的宽度取决于名字的长度——名字越长，框就越宽。这需要**动态计算**每一行的长度，然后用 `string` 的填充构造函数来生成相应数量的空格和星号。

```cpp
string name;
cin >> name;

// 构建问候语
const string greeting = "Hello, " + name + "!";

// 构建框框
const string spaces(greeting.size(), ' ');
const string second = "* " + spaces + " *";
const string first(second.size(), '*');

cout << first << endl;
cout << "* " << greeting << " *" << endl;
cout << first << endl;
```

> **逐行解释构建逻辑：**
>
> **① `const string greeting = "Hello, " + name + "!";`** — `const` 表示问候语一旦生成就不应该被修改。`const` 是 C++ 中的一种"契约"：告诉编译器和读者"这个值只读"。如果后续代码试图修改 `greeting`，编译器会报错。这是一个良好的编程习惯——能用 `const` 的尽量用 `const`。
>
> **② `const string spaces(greeting.size(), ' ');`** — 使用了 `string` 的**填充构造函数**：`string(count, char)` 创建一个包含 `count` 个重复字符的字符串。这里创建了和 `greeting` 等长（字符个数相同）的空格串。这种构造方式比手动 for 循环拼接更简洁、更高效。
>
> **③ `const string second = "* " + spaces + " *";`** — 构建"上边距"行：一个星号、一个空格、一段空格、一个空格、一个星号。注意 `"* "` 和 `" *"` 是 `const char*` 类型，但因为和 `string` 类型的 `spaces` 用 `+` 连接，C++ 会自动触发从 `const char*` 到 `string` 的类型转换。
>
> **④ `const string first(second.size(), '*');`** — 最外框线和 `second` 等长，全用 `*` 填充。因为框的宽度是由问候语长度决定的，而 `second` 已经算好了宽度，直接用它的长度即可。
>
> **⑤ 最终输出顺序**：上框线 → 上边距行 → 问候语 → 下边距行 → 下框线。

### 3.4 `string` 常用操作汇总

| 操作 | 说明 |
|---|---|
| `string s` | 定义空字符串 |
| `string s = "hello"` | 用 C 字符串初始化 |
| `string s(n, c)` | 用 n 个字符 c 初始化 |
| `os << s` | 输出 |
| `is >> s` | 读入（跳过空白，读到下一个空白停止） |
| `s + t` | 连接两个字符串 |
| `s.size()` | 返回字符个数 |
| `s[i]` | 访问第 i 个字符（从 0 开始） |

`★ Insight ─────────────────────────────────────`
`const string spaces(greeting.size(), ' ');` 使用了**构造函数**来创建对象。`string(count, char)` 构造包含 `count` 个 `char` 的字符串。C++ 标准库中的类型通过多种构造函数提供了灵活的初始化方式——这被称为**构造函数重载**。
`─────────────────────────────────────────────────`

> **关于构造函数重载的理解：** `string s;`（默认构造）、`string s("hello");`（C 字符串构造）、`string s(n, c);`（填充构造）——这是三个不同的构造函数，名字相同但参数不同。编译器根据你提供的参数数量和类型自动匹配合适的版本。这种机制叫作**函数重载**（overload），它不仅适用于构造函数，也适用于普通函数（第二章会详细讲）。

## 四、批量数据处理 — `vector` 容器

### 4.1 问题：计算学生成绩

> **为什么需要 `vector`？**
>
> 假设一名学生的作业次数未知——可能是 5 次，也可能是 15 次。如果用固定数组 `double homework[100]`：开太小会不够用（程序崩溃），开太大会浪费内存。`vector` 是**动态数组**——它自动管理内存，按需扩容。你只需要不断往尾部追加元素，不用关心容量问题。`vector` 是 C++ 最常用的容器，**没有之一**。

场景：期末考试成绩占 40%，期中 20%，**作业中值**占 40%。需要收集所有作业成绩，排序后取中值。

```cpp
// vector：动态数组，自动管理大小
vector<double> homework;

double midterm = 85, final = 90;

// 模拟读入作业成绩
double grades[] = {95, 88, 92, 90, 87, 93};
for (double g : grades) {
    homework.push_back(g);  // 向 vector 尾部添加元素
}

// 排序
sort(homework.begin(), homework.end());

// 计算中值
typedef vector<double>::size_type vec_sz;
vec_sz size = homework.size();
vec_sz mid = size / 2;
double median = (size % 2 == 0)
    ? (homework[mid] + homework[mid-1]) / 2
    : homework[mid];

// 计算最终成绩（期中20% + 期末40% + 作业中值40%）
double final_grade = 0.2 * midterm + 0.4 * final + 0.4 * median;
```

> **逐点解释上述代码的关键行：**
>
> **① `vector<double> homework;`** — 声明一个存储 `double` 类型元素的动态数组。`<double>` 是**模板参数**：`vector` 是一个"类型工厂"，`vector<double>` 和 `vector<int>` 和 `vector<Student_info>` 是三个不同的类型。你用尖括号告诉 `vector`"我要存什么"，编译器就为你生成对应的容器代码。
>
> **② `homework.push_back(g);`** — 在 vector 的**尾部**追加一个元素。为什么叫 `push_back`？`push` = 推入，`back` = 尾部——形象地描述了这个动作。注意 vector 没有 `push_front`——在头部插入需要移动所有已有元素，效率很低。
>
> **③ `sort(homework.begin(), homework.end());`** — `sort` 对区间 `[begin, end)` 内的元素排序。注意区间约定：`begin()` 指向第一个元素，`end()` 指向**最后一个元素之后**（不包含最后一个）。这个 `[begin, end)` 半开区间约定贯穿整个 C++ 标准库。
>
> **④ `typedef vector<double>::size_type vec_sz;`** — 为什么不用 `int`？因为 `vector::size()` 返回的是 `size_type`（通常是 `size_t`），用 `int` 存会导致类型不匹配的警告，且在 64 位系统上 `int`（4 字节）可能不够大。`typedef` 给这个长长的类型名起了个别名 `vec_sz`，方便书写。C++11 也提供了 `using vec_sz = vector<double>::size_type;` 的等价写法。
>
> **⑤ 中值逻辑**：`size % 2 == 0` 判断奇偶。偶数和奇数情况处理不同：
> - 偶数个元素（如 6 个）：取中间两个 `homework[2]` 和 `homework[3]` 的平均值
> - 奇数个元素（如 5 个）：取中间那个 `homework[2]`
>
> **⑥ 成绩权重公式**：`0.2 * midterm + 0.4 * final + 0.4 * median`。0.2 + 0.4 + 0.4 = 1.0，权重百分比总和为 100%。

### 4.2 流程控制：检测输入结束

> **核心问题：** 用户会输入多少个成绩？没人知道。如何让程序自动判断输入结束？
>
> 答案：用 `cin >> x` 本身作为循环条件。这是 C++ 中最常用的"不确定数量读取"模式。

```cpp
vector<double> numbers;
double x;
while (cin >> x) {     // 读取成功 → 循环继续
    numbers.push_back(x);
}                      // 读取失败（EOF 或非法输入）→ 退出
```

> **为什么 `while (cin >> x)` 能判断输入结束？**
>
> ① `cin >> x` 尝试读取一个 `double`。如果读取成功，它返回 `cin` 对象本身。
> ② `while` 需要布尔条件时，C++ 会通过 `istream` 的**类型转换函数**将 `cin` 转换为布尔值：流状态正常 → `true`；遇到错误或 EOF → `false`。
>
> **哪些情况会触发"读取失败"？**
>
> | 触发条件 | 说明 | 处理方式 |
> |---|---|---|
> | **EOF（文件结束）** | 所有数据已读完 | Windows: Ctrl+Z + Enter；Mac/Linux: Ctrl+D |
> | **类型不匹配** | 程序期望 `double` 但输入了 `abc` | 流进入错误状态，后续读取全失效 |
> | **流硬件错误** | 磁盘故障、网络断开 | 不常见 |
>
> ❌ **常见错误：** 输入了非数字内容（如 `abc`）后，流进入错误状态，所有后续 `cin >> x` 操作都会立即返回 `false`——循环直接退出，但 `abc` 还留在缓冲区中。你需要 `cin.clear()` 清除错误状态，再用 `cin.ignore(...)` 跳过非法字符。

> **EOF 触发方式（重要！）：** **Windows: Ctrl+Z**，**Mac/Linux: Ctrl+D**

### 4.3 `vector` 操作汇总

| 操作 | 说明 |
|---|---|
| `vector<T> v` | 创建空的 `vector` |
| `v.push_back(e)` | 在末尾添加元素 e |
| `v.size()` | 返回元素个数 |
| `v.empty()` | 检查是否为空 |
| `v[i]` | 访问第 i 个元素（不检查越界） |
| `v.begin()` | 返回指向第一个元素的迭代器 |
| `v.end()` | 返回指向最后一个元素**之后**的迭代器 |

> **`v[i]` 的越界问题：** vector 的 `[]` 操作符**不检查索引是否越界**——这和 C 数组的 `[]` 行为一致。如果索引超出范围，你读取的是无效内存，结果未定义（可能崩溃，可能读到垃圾值）。安全访问应该用 `v.at(i)`——它在越界时会抛出 `out_of_range` 异常。但也因此比 `[]` 稍慢。

### 4.4 输出精度控制

> 默认情况下，`cout` 以**有效数字位数**来显示浮点数。`setprecision(3)` 让 `3.14159` 显示为 `3.14`（3 位有效数字）。但注意：对于 `1234.56`，`setprecision(3)` 会显示为 `1.23e+03`（科学计数法，因为 3 位有效数字无法表示 4 位数）。
>
> `fixed` 修饰符的作用是：**强制使用固定小数点模式**。此时 `setprecision` 控制的是**小数位数**而不是有效数字位数——行为更符合直觉。

```cpp
double pi = 3.14159265358979;

// 设置精度
cout << setprecision(3) << pi << endl;
cout << fixed << setprecision(2) << pi << endl;

// 保存和恢复精度
streamsize prec = cout.precision();  // 获取当前精度
cout << setprecision(2) << pi << endl;
cout << setprecision(prec) << pi << endl;
```

> **为什么需要保存和恢复精度？**
>
> `setprecision` 有**持久性副作用**——一旦设置，会影响后续所有输出，直到下次修改。如果你的函数修改了精度但忘记恢复，调用者的输出格式就会被意外改变。**保存-设置-恢复**是一种重要的防御性编程模式：
>
> 1. `streamsize prec = cout.precision();` — 保存当前精度值
> 2. 设置新精度并输出
> 3. `cout << setprecision(prec);` — 恢复原精度
>
> 这个模式不仅适用于精度控制，也适用于文件流、格式化标志等的配置变更。

| 操作 | 说明 |
|---|---|
| `setprecision(n)` | 设置输出精度为 n |
| `cout.precision()` | 返回当前精度值 |
| `streamsize` | `setprecision` 所期望值的类型 |
| `fixed` | 切换为定点小数模式（控制小数位数而非有效数字） |

## 五、完整的成绩计算程序

> 现在把本章学的所有概念组合成一个完整程序：`string` 处理姓名、`vector` 存储成绩、`sort` 排序、中值计算、精度控制。与之前的片段相比，完整程序加入了**错误检查**——如果学生没有提交作业，程序应友好提示而非产生未定义行为。

```cpp
// 用字符串流模拟输入（实际使用中替换为 cin）
istringstream iss("Alice 85 90 95 88 92 90 87 93");

string name;
iss >> name;

double midterm, final;
iss >> midterm >> final;

vector<double> homework;
double x;
while (iss >> x)
    homework.push_back(x);

typedef vector<double>::size_type vec_sz;
vec_sz size = homework.size();
if (size == 0) {
    cout << "错误：没有录入作业成绩！" << endl;
}

sort(homework.begin(), homework.end());

vec_sz mid = size / 2;
double median = (size % 2 == 0)
    ? (homework[mid] + homework[mid-1]) / 2
    : homework[mid];

// 计算并输出最终成绩（期中20% + 期末40% + 作业中值40%）
streamsize prec = cout.precision();
cout << "最终成绩: " << setprecision(3)
     << 0.2 * midterm + 0.4 * final + 0.4 * median
     << setprecision(prec) << endl;
```

> **程序中几个关键设计点：**
>
> **① `if (size == 0)` 检查** — 如果 `homework` 为空（用户没有输入任何成绩），代码不应急于计算中值——对空容器计算中值会触发除零错误或未定义行为。此处简单输出错误信息；在第二章中，我们将学习用**异常处理**来更优雅地处理这类情况。
>
> **② `while (iss >> x)` + `push_back` 组合** — 这构成了 C++ 中"读取不确定数量输入"的标准惯用法。不需要事前知道有多少个成绩——循环自动处理到输入流结束为止。
>
> **③ 精度保持** — 输出前保存 `cout` 的当前精度，设置 3 位有效数字输出成绩，然后立即恢复。**一个函数不应该污染调用者的状态**——这是重要的模块化原则。
>
> **④ `istringstream` 的用途** — 本章用 `istringstream` 模拟输入，方便在 MPE 中直接运行演示。编译运行实际程序时，将 `iss` 替换为 `cin` 即可。`istringstream` 和 `cin` 都是 `istream` 的子类，使用方式完全相同。
