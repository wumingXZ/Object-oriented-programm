## 〇、C 语言回顾：struct 的局限性

> C 语言的 struct 只是数据的"打包"——它把零散的变量聚集到了一个名字下，仅此而已。但数据和操作这些数据的函数是完全分离的，任何人都能直接修改 struct 的内部字段，没有任何保护。

```c
// C 语言方式
struct Student {
    char name[50];
    double midterm, final;
    double homework[20];
    int hw_count;
};
```

> **三个关键问题**：

| 问题 | 表现 | 后果 |
|------|------|------|
| ① 数据与函数分离 | `read_student()`、`grade_student()` 是独立函数 | 代码难以组织，无法直观看出一个学生有哪些操作 |
| ② 无访问控制 | 任何人都能写 `s.midterm = 999` | 数据一致性无法保证 |
| ③ 无初始化保证 | struct 变量创建后字段是未初始化的 | 必须手动调初始化函数，容易遗忘 |

```c
// 使用时数据和处理数据的函数是分离的
void read_student(struct Student* s) { ... }    // 函数和结构体分离
double grade_student(struct Student* s) { ... } // 没有封装，任何人都能直接修改 s->midterm

// 问题：
// 1. 数据和处理数据的函数分离
// 2. 任何人都能直接修改内部数据（无保护）
// 3. 无法保证数据有效性（如 hw_count 和 homework 数组可能不一致）
```

> C++ 的 `class` 通过三个机制解决了这些问题：**将数据和操作数据的方法捆绑在一起**（成员函数）、**访问控制**（`public`/`private`）、**自动初始化**（构造函数）。

<a id="一从-struct-到-class"></a>
## 一、从 `struct` 到 `class`

### 1.1 C 风格 struct

> 下面是一个典型的 C 风格 struct。它把学生信息暴露给所有代码——任何人都可以读写任意的字段。这种模式下，一个 `=` 号就能让成绩变成 -100 或 999，不会有任何阻止。

```cpp
// C 风格：裸 struct，数据暴露在外
struct Student_info_C {
    string name;
    double midterm, final;
    vector<double> homework;
};

// 全局函数操作 struct
istream& read_C(istream& is, Student_info_C& s) {
    is >> s.name >> s.midterm >> s.final;  // 需要手动操作每个成员
    double x;
    while (is >> x) s.homework.push_back(x);
    is.clear();
    return is;
}

// 使用示例
Student_info_C s1 = {"Alice", 85, 90, {95, 88, 92}};  // 直接访问
s1.midterm = 999;  // 任何人都能改！可能破坏数据一致性
```

> **问题**：任何人都能直接读写 `s1.midterm`，可能被错误修改。更重要的是，不存在"初始化"的概念——忘记初始化，字段就是随机的垃圾值。

### 1.2 C++ class：封装

> C++ 的 `class` 引入了**封装**的概念。`public` 部分是类对外承诺的固定接口；`private` 部分是隐藏的实现细节——**外部代码无法直接访问它们**。任何尝试写 `s.midterm` 的代码都会被编译器拦住。
>
> 注意下面的代码中有几个关键的新语法点：

```cpp
class Student_info {
public:   // ===== 公有接口 =====
    // 构造函数（对象创建时自动调用）
    Student_info() : midterm(0), final(0) {}
    Student_info(istream& is) { read(is); }

    // 成员函数：通过对象隐式调用
    istream& read(istream& in) {
        in >> n >> midterm >> final;
        double x;
        homework.clear();
        while (in >> x) homework.push_back(x);
        in.clear();
        return in;
    }

    double grade() const {  // const：此函数不修改对象
        if (homework.empty())
            throw domain_error("no homework");
        double sum = 0;
        for (double h : homework) sum += h;
        double avg = sum / homework.size();
        return 0.2 * midterm + 0.4 * final + 0.4 * avg;
    }

    // 访问器（accessor）：以只读方式暴露数据
    string name() const { return n; }
    bool valid() const { return !homework.empty(); }

private:  // ===== 私有实现细节 =====
    string n;
    double midterm, final;
    vector<double> homework;
};

// compare 是非成员函数（它不修改对象，且操作对称）
bool compare(const Student_info& x, const Student_info& y) {
    return x.name() < y.name();
}

// 使用示例
Student_info s;
istringstream iss("Alice 85 90 95 88 92 90 87");
s.read(iss);

// s.midterm = 999;  // ❌ 编译错误！midterm 是 private
// s.n = "hack";     // ❌ 编译错误！n 是 private
```

> **逐点解释上述代码中的关键设计**：
>
> **① `public:` 和 `private:` — 访问标签。** 类可以有多组访问标签，每个标签之后的成员具有对应的访问级别，直到遇到下一个标签。`public` 成员可以被任何代码访问（类的"接口"）；`private` 成员只能被类自身的成员函数访问（类的"实现细节"）。C++ 的 `struct` 默认是 `public`，`class` 默认是 `private`——**这是二者唯一的本质区别**。
>
> **② 构造函数 `Student_info() : midterm(0), final(0) {}` — 自动初始化。** 构造函数的名字和类名相同，没有返回类型。它在对象创建时**自动调用**——不需要手动调一个 `init()` 函数。`:` 后面的部分是**初始化列表**（见下一节），在构造函数体执行之前初始化成员。
>
> **③ 为什么 `compare()` 是**非成员函数**而不是成员函数？** 因为 `compare(s1, s2)` 需要对称地操作两个 `Student_info` 对象——它不修改任何一个，只是读取。如果它是成员函数，调用时必须是 `s1.compare(s2)`，这样就隐含地不对称（一个是隐式 `this`，一个是显式参数）。**经验法则**：如果需要修改对象状态→成员函数；如果操作是对称的→非成员函数；如果只读访问隐藏数据→const 成员函数（访问器）。
>
> **④ 访问器函数 `name()` 和 `valid()` 暴露了哪些信息？** 只暴露了必须的信息——名字和一个"是否有作业"的布尔值。外界无法知道 `n` 的名字是 `string` 还是 `char*`，无法知道 `homework` 是 `vector<double>` 还是 `list<double>`——这些实现细节可以在不破坏外界代码的前提下自由改变。**这就是封装的本质：接口稳定，实现自由。**

`★ Insight ─────────────────────────────────────`
**封装（Encapsulation）**是将接口与实现分离的过程。接口（`public` 部分）是类对外承诺的契约，一旦稳定就不轻易改变；实现（`private` 部分）可以随时优化改良，不影响使用该类的代码。这正是面向对象的四大支柱之一：**抽象、封装、继承、多态**。
`─────────────────────────────────────────────────`

<a id="二struct-vs-class"></a>
## 二、`struct` vs `class`

> `struct` 和 `class` 在 C++ 中几乎是完全相同的——**唯一的区别是默认访问级别**。但它们的惯用场景有很强的约定。下面的代码展示了这个区别，但请注意这不仅仅是语法差异，更是**设计意图的信号**。

```cpp
// struct：默认 public
struct Point_S {
    int x, y;  // public（默认）
    void print() const { cout << "(" << x << "," << y << ")"; }
};

// class：默认 private
class Point_C {
    int x, y;  // private（默认）！
public:
    Point_C(int a, int b) : x(a), y(b) {}
    void print() const { cout << "(" << x << "," << y << ")"; }
};

// 使用对比
Point_S ps = {10, 20};
ps.x = 30;  // ✅ struct 默认可以访问

Point_C pc(10, 20);
// pc.x = 30;  // ❌ class 默认不可访问

// 惯例：
// struct → 简单数据类型，成员直接暴露
// class  → 需要封装保护的复杂类型
```

> **为什么 C++ 保留了 `struct`？** 为了和 C 兼容。但 C++ 中的 `struct` 远不止 C 的 struct——它可以有构造函数、成员函数、继承、访问标签。那么什么时候用 `struct` 什么时候用 `class`？看看惯例对比表：

| | `struct` | `class` |
|---|---|---|
| 默认访问级别 | `public` | `private` |
| 惯例用途 | 简单数据聚合（POD类型） | 需要封装和行为的复杂类型 |
| 成员函数使用 | 偶尔（但完全可以有） | 常规 |
| 建议 | 仅当"数据直接暴露"也是设计意图时用 | 绝大多数情况用 class |
| 都可以有构造函数 | ✅ | ✅ |
| 都可以有继承 | ✅ | ✅ |

> **如果你不确定，就用 `class` 然后显式写 `public:`。** 这样更安全，也更能清晰地表达设计意图。`struct` 更适合"只是一个数据容器"的场景——比如坐标、颜色等只有几个字段、不需要行为保护的简单类型。

<a id="三构造函数"></a>
## 三、构造函数

> 构造函数是对象创建时**自动调用**的特殊成员函数。它是"确保对象被正确初始化"的保障。C 语言中你可能会写 `init_student(&s)` 然后祈祷不要忘了调它——C++ 的构造函数让你无法忘记。

```cpp
class Student {
public:
    // 默认构造函数：没有参数
    Student() : name_(""), score_(0) {
        cout << "默认构造: " << name_ << endl;
    }

    // 带参数的构造函数
    Student(const string& n, double s) : name_(n), score_(s) {
        cout << "参数构造: " << name_ << " (" << score_ << ")" << endl;
    }

    // 从输入流构造
    Student(istream& is) {
        is >> name_ >> score_;
        cout << "流构造: " << name_ << " (" << score_ << ")" << endl;
    }

    string name() const { return name_; }
    double score() const { return score_; }

private:
    string name_;
    double score_;
};

// 使用示例
Student s1;                            // 默认构造函数
Student s2("Alice", 85);              // 带参数构造
Student s3(cin);                      // 流构造（测试用：输入"Bob 92"）
```

> **构造函数的核心规则**：
>
> ① **自动调用**：你不需要（也无法）显式调用构造函数——它在对象创建时由编译器自动执行。`Student s1;` 一行代码，编译器在栈上分配了空间，然后调用了 `Student()`。
>
> ② **可以重载**：一个类可以有多个构造函数，只要参数列表不同。C++ 根据创建时的参数决定调用哪个版本。
>
> ③ **没有返回类型**：构造函数不写 `void` 也不写任何返回类型。这和普通函数完全不同。
>
> ④ **如果不写任何构造函数，编译器会自动生成一个默认构造函数**——但这个默认构造函数做什么？**对于内置类型（如 `int`、`double`、指针）不做任何初始化**（垃圾值），对于类类型成员（如 `string`、`vector`）调用它们的默认构造函数。**这意味着**：如果你有一个 `int` 成员但忘记在构造函数中初始化它，它的值将是未定义的（可能是 0，也可能是 42，也可能是一个随机数）。

### 构造函数的初始化列表

> 这是初学者最容易困惑的地方。为什么不能直接在构造函数体里赋值？为什么需要初始化列表？**核心原因**：成员在构造函数体**执行之前**就已经被初始化了。初始化列表控制的是"如何初始化"；构造函数体控制的是"初始化之后做什么操作"。

```cpp
class Example {
    const int ID;      // const 成员：不可修改——必须立即给出值
    string& ref;       // 引用成员：必须绑定到某个对象——也必须立即给出
    int normal;        // 普通 int：可以在体内赋值

public:
    // ✅ 正确：用初始化列表
    Example(int id, string& r, int n)
        : ID(id), ref(r), normal(n) {}

    // ❌ 不能这样写（const 和引用不能赋值）：
    // Example(int id, string& r, int n) {
    //     ID = id;   // 错误：const 成员不可赋值
    //     ref = r;   // 错误：引用不可重新绑定
    // }

    void show() const {
        cout << "ID=" << ID << ", ref=" << ref
             << ", normal=" << normal << endl;
    }
};

// 使用示例
string str = "hello";
Example e(42, str, 100);
```

> **为什么 `const` 和引用成员必须用初始化列表？**
>
> C++ 中初始化和赋值是两个完全不同的概念：
>
> - **初始化**：创建变量时赋予初始值（`int x = 5;`）
> - **赋值**：销毁旧值、赋予新值（`x = 10;`）
>
> `const int ID` 一旦创建就不能修改——所以它必须在创建时被初始化。构造函数体是在对象创建**之后**执行的，那时 `ID` 已经存在（但值是垃圾）。如果在体内写 `ID = id`，那是在"赋值"——但对 const 对象赋值是非法的。
>
> 同理，引用必须在创建时就绑定到某个对象——它在初始化后无法重新绑定。在体内 `ref = r` 不是重新绑定引用，而是**通过引用修改它指向的对象的值**，这是个更大的误解。
>
> **经验法则**：**尽可能使用初始化列表。** 对于所有成员（包括简单的 `int` 和 `double`），用初始化列表比在体内赋值更高效——它避免了"先默认构造、再赋值"的两步操作。

### 对象创建过程

> 理解对象创建的完整流程，可以帮助你理解为什么初始化列表如此重要。

```
1. 系统分配内存空间（栈或堆）
2. 按初始化列表初始化成员（按声明顺序，不是列表顺序！）
3. 执行构造函数体
```

> **关键注意点：成员按声明顺序初始化，不是列表顺序！**
>
> ```cpp
> class Bad {
>     int a;  // 先声明
>     int b;  // 后声明
> public:
>     Bad() : b(10), a(b) {}  // 危险！初始化按声明顺序：a 先初始化，那时 b 还是垃圾值！
> };
> ```
>
> 上述代码中 `a` 先被初始化（传入了 `b` 的值，但 `b` 还是未初始化的垃圾值），然后 `b` 才被初始化为 10。结果 `a` 得到垃圾值。**结论**：初始化列表的顺序不重要——编译器永远按声明顺序执行。

<a id="四const-成员函数"></a>
## 四、`const` 成员函数

> `const` 成员函数是 C++ 中一个极其重要的设计机制。它不是一个"可选"的装饰——它是**契约**：向调用者承诺"调用这个函数不会修改对象"。编译器会强制检查这个承诺是否被遵守。

```cpp
class Person {
    string name_;
    int age_;
public:
    Person(const string& n, int a) : name_(n), age_(a) {}

    // const 成员函数：承诺不修改对象
    string getName() const { return name_; }
    int getAge() const { return age_; }

    // 非 const 成员函数：可能修改对象
    void birthday() { ++age_; }  // 修改了 age_
};

// 使用示例
Person alice("Alice", 20);
const Person bob("Bob", 25);  // const 对象

// 非 const 对象可以调用所有函数
alice.birthday();

// const 对象只能调用 const 成员函数
// bob.birthday();  // ❌ 编译错误！const 对象不能调用非 const 函数
```

> **为什么需要 `const` 成员函数？**
>
> ① **让 const 对象可用**：如果一个对象被声明为 `const`（如 `const Person bob`），它只能调用 `const` 成员函数。如果没有 `const` 版本的 `getName()`，那么连 `bob.getName()` 都是编译错误。
>
> ② **通过引用/指针传递时保护数据**：函数的形参如果是 `const Person& p`，那么函数体内只能调用 `p` 的 `const` 成员函数。这保证了函数不会意外修改传入的对象。
>
> ③ **编译器替你检查**：如果在 `const` 成员函数中写了 `age_++`，编译器直接报错——不需要等到运行时才发现。
>
> **规则**：「把你**不修改对象**的成员函数都标记为 `const`」——让别人放心用，也让编译器帮你检查。这是 C++ 代码的重要习惯。

> **常见误解：`const` 成员函数不能修改任何成员？**
>
> 不完全正确。有 `mutable` 关键字可以让某个成员即使在 `const` 函数中也能被修改（常用于缓存计数、调试统计等），但这在课程范围内不常用。

<a id="五内联函数"></a>
## 五、内联函数

> 函数的调用是有开销的：参数压栈、跳转到函数地址、执行、返回。对于小而频繁调用的函数（比如返回 `x` 的坐标），这个开销甚至可能超过函数体本身的执行时间。**内联函数的思路就是：把函数体的代码直接"粘贴"到调用处，省去函数调用的开销。**

```cpp
class Point {
    double x, y;
public:
    Point(double a, double b) : x(a), y(b) {}

    // 定义在类内的函数默认是内联的
    double getX() const { return x; }  // 内联
    double getY() const { return y; }  // 内联

    // 类外定义，但用 inline 关键字
    double distance() const;
};

inline double Point::distance() const {
    // inline: 编译器将函数体直接替换到调用处，避免函数调用开销
    return sqrt(x * x + y * y);
}

> 短小、频繁调用的函数适合内联。长函数内联会导致代码膨胀。

```

> **重要事实**：
>
> ① `inline` 对编译器是**请求**而非命令。编译器可以选择忽略它（比如函数太长或太复杂时）。现代编译器甚至能自动对短函数进行内联——即使没有写 `inline`。
>
> ② 定义在类定义体内的成员函数**隐式是内联的**，不需要额外写 `inline`。类外定义的函数才需要显式 `inline` 关键字。
>
> ③ 内联函数通常在头文件中定义（而不是 `.cpp`），因为编译器需要在调用处看到函数体才能进行内联替换。

<a id="六完整示例学生成绩管理系统"></a>
## 六、完整示例：学生成绩管理系统

> 将前面学到的知识整合：封装、构造函数、const 成员函数、访问器。注意**类设计者的每个决策都有原因**——为什么要用初始化列表？为什么 `grade()` 是 `const`？为什么 `read()` 不是 `const`？为什么有一些是非成员函数？

```cpp
class Student_info {
public:
    // 构造函数
    Student_info() : midterm(0), final(0) {}
    Student_info(istream& is) { read(is); }

    // 成员函数
    istream& read(istream& in) {
        in >> n >> midterm >> final;
        homework.clear();
        double x;
        while (in >> x) homework.push_back(x);
        in.clear();
        return in;
    }

    double grade() const {
        if (homework.empty())
            throw domain_error("student has done no homework");
        double sum = 0;
        for (double h : homework) sum += h;
        return 0.2 * midterm + 0.4 * final
             + 0.4 * sum / homework.size();
    }

    // 访问器
    string name() const { return n; }
    bool valid() const { return !homework.empty(); }

private:
    string n;
    double midterm, final;
    vector<double> homework;
};

// 非成员函数
bool compare(const Student_info& x, const Student_info& y) {
    return x.name() < y.name();
}
```

> **设计决策详解**：
>
> | 决策 | 原因 |
> |------|------|
> | `midterm(0), final(0)` 用初始化列表而不是体内赋值 | 避免先默认初始化再赋值的两步操作——更高效，且如果成员是 const 或引用则必须用 |
> | `read()` 不是 `const` | 它会修改对象（读入数据到成员变量）——const 函数不能修改对象 |
> | `grade()` 是 `const` | 它只读取数据、计算成绩，不修改任何成员——const 让调用者放心 |
> | `compare()` 是非成员函数 | 操作对称（比较两个对象），不修改任何一个——放在类外更符合逻辑 |
> | 访问器 `name()` 返回 `string` 而非引用 | 返回值的拷贝而不是内部成员的引用——这样外界无法通过返回值修改内部数据（可以改成 `const string&` 以避免拷贝开销，但这会暴露数据位置） |

<a id="七总结"></a>
## 七、总结

| 知识点 | 说明 | C 语言中 |
|---|---|---|
| `class` vs `struct` | `class` 默认 private，`struct` 默认 public | `struct` 只有公开数据 |
| `public:` | 公共接口，所有人可访问 | （不存在） |
| `private:` | 私有实现，仅类内可访问 | （不存在） |
| 构造函数 | 创建对象时自动调用的初始化函数 | 手动写 `init()` 函数 |
| 初始化列表 | 在构造函数体执行前初始化成员 | 不存在，只能在函数体内赋值 |
| 初始化顺序 | 按**声明顺序**而非列表顺序 | （无此概念） |
| const/引用成员 | **必须用初始化列表** | （C 不支持 const/引用成员） |
| `const` 成员函数 | 承诺不修改对象状态 | （不存在） |
| `inline` | 函数体直接替换到调用处 | `#define` 宏（但不安全） |
| 访问器函数 | 以只读方式暴露内部数据 | 直接读成员 |

### 成员函数归属判断口诀

```
要修改对象状态？   → 成员函数
不修改、操作对称？ → 非成员函数（如 compare, operator+）
只读访问隐藏数据？ → 访问器成员函数（const）
```

> **课后练习**：将你的 `Student_info` 从 `struct` 改写为 `class`，添加构造函数、私有数据成员和公共访问器函数。确保 extern 函数 `compare` 仍然能正常工作。
