## 一、为什么要学复杂度？

你已经学过 `vector` 和 `list`，知道它们的差别：

| 操作 | `vector` | `list` |
|---|---|---|
| 取第 i 个元素 `v[i]` | 瞬间 | 做不到 |
| 在中间插入 | 慢（要挪动后面所有元素） | 快 |

"瞬间"和"慢"到底差多少？当数据量从 100 变成 100 万时，差距是 1 毫秒还是 1 小时？**复杂度就是用数学描述这个差距的。**

---

## 二、核心思想：数"基本操作"的次数

我们不关心计算机的快慢（CPU 型号、内存大小），只关心**算法执行的基本操作次数**如何随**输入规模 n** 增长。

> **输入规模 n**：比如一个 vector 里有 100 个元素，n = 100。
>
> **基本操作**：一次比较、一次赋值、一次加法——取你关心的那个操作。

### 例子：在 vector 里找最大值

```cpp
int find_max(const vector<int> &v) {
    int max_val = v[0];          // 1 次赋值
    for (int i = 1; i < v.size(); ++i) {  // 循环 n-1 次
        if (v[i] > max_val)      // 每次 1 次比较
            max_val = v[i];      // 最多 n-1 次赋值
    }
    return max_val;
}
```

n 个元素 → 大约 n 次比较。我们说这个算法的时间复杂度是 **O(n)**。

## 三、Big O 是什么？

Big O 描述的是**增长趋势**——当 n 变得非常大时，运行时间按什么规律增长。它忽略常数系数和低阶项，只保留**增长最快的那一项**。

> **通俗理解：** Big O 回答一个问题——"数据量翻 100 倍，运行时间大概翻多少倍？"

### 3.1 最常见的五种复杂度

```
O(1)      —— 常数时间    n 变多大都不影响，一次操作搞定
O(log n)  —— 对数时间    每步排除一半选项，100 万只需约 20 步
O(n)      —— 线性时间    n 翻倍，时间也翻倍
O(n log n)—— 线性对数    比 O(n) 稍差，很多排序算法是这个级别
O(n²)     —— 平方时间    n 翻 10 倍，时间翻 100 倍！
```

### 3.2 直观感受：处理 100 万元素时各需要多少步？

| 复杂度 | n=100 万时的操作次数 | 打个比方 |
|---|---|---|
| O(1) | 1 | 不管书多厚，翻到第 1 页只要 1 秒 |
| O(log n) | ≈ 20 | 在 100 万页的字典里查一个词（二分查找）|
| O(n) | 1,000,000 | 把整本书逐页翻一遍 |
| O(n log n) | ≈ 20,000,000 | 把字典里每个词都排好序 |
| O(n²) | 1,000,000,000,000 | 把整本书抄写 100 万遍 |

### 3.3 图示理解

```
操作次数
  │
  │                                          ╱ O(n²)
  │                                     ╱
  │                               ╱╱
  │                          ╱╱
  │                     ╱╱╱
  │                ╱╱╱          ╱ O(n log n)
  │           ╱╱╱          ╱╱╱
  │      ╱╱╱         ╱╱╱╱╱╱╱╱╱╱╱╱
  │ ╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱╱ O(n)
  │                            ╱
  │                       ╱╱╱╱ O(log n)
  │╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺╺ O(1)
  └──────────────────────────────────→ n
```

> O(1) 是平的（不随 n 变化），O(n) 是斜线，O(n²) 是抛物线——n 越大，差距越悬殊。

## 四、用你已经学过的容器来理解

### 4.1 为什么 `vector` 取元素是 O(1)？

`vector` 的元素在内存里连续存放。要取第 i 个元素，只需要：
```
地址 = 起始地址 + i × 每个元素的大小
```
不管 i 是 3 还是 300 万，都是一次乘法+一次加法。**O(1)**。

### 4.2 为什么 `vector` 中间插入是 O(n)？

```cpp
vector<int> v{1, 2, 3, 4, 5};
v.insert(v.begin() + 2, 99);  // 在位置 2 插入 99
// 原来：1 2 3 4 5
// 变成：1 2 99 3 4 5
//             ↑ 3 4 5 全部要往后挪一位！
```

最坏情况下（插在开头），所有 n 个元素都要挪。**O(n)**。

### 4.3 为什么 `list` 插入是 O(1)？

链表每个节点存着"下一个节点在哪"，插入只需改两个指针：

```
插入前：A → B → C
插入后：A → X → B → C     （只改了 A 和 X 的指针，B、C 不用动）
```

不管 list 有多长，改指针的次数是一样的。**O(1)**。

### 4.4 为什么 `map` 查找是 O(log n)？

`map` 底层是**平衡二叉搜索树**（红黑树）。查找时，每次比较都能排除一半的候选元素：

```
找 42：
          50
         /  \
       30    70
      /  \   / \
     20  40 60  80
     
42 > 50？ → 否，走左边
42 > 30？ → 是，走右边  
42 > 40？ → 是，找到了！

3 步找到（树高 ≈ log₂(8) = 3）
```

n 个元素 → 比较约 log₂(n) 次。**O(log n)**。100 万元素只需约 20 次比较。

### 4.5 为什么 `unordered_map` 查找是 O(1)？

`unordered_map` 用**哈希表**：把键通过哈希函数直接算出一个位置，然后直接跳到那个位置检查。
- 理想情况：一次计算+一次比较，**O(1)**
- 最坏情况：所有键碰巧算到同一个位置（哈希冲突），退化为 **O(n)**

## 五、容器操作复杂度速查表

| 容器 | 按索引访问 | 搜索 | 头部插入 | 尾部插入 | 中间插入 |
|---|---|---|---|---|---|
| `vector` | **O(1)** | O(n) | O(n) | **O(1)*** | O(n) |
| `list` | — | O(n) | **O(1)** | **O(1)** | **O(1)** |
| `deque` | **O(1)** | O(n) | **O(1)** | **O(1)** | O(n) |
| `map` | — | **O(log n)** | — | **O(log n)** | **O(log n)** |
| `unordered_map` | — | **O(1)†** | — | **O(1)†** | — |
| `set` | — | **O(log n)** | — | **O(log n)** | **O(log n)** |

> \* 均摊 O(1)：偶尔扩容时是 O(n)，但平均下来是 O(1)
>
> † 平均情况；最坏 O(n)

### 选择口诀

```
需要索引访问？→ vector（除非要在中间频繁插入）
频繁在任意位置插入删除？→ list
需要按键快速查找 + 有序遍历？→ map
需要按键最快查找 + 不关心顺序？→ unordered_map
后进先出？→ stack    先进先出？→ queue    按优先级？→ priority_queue
```

## 六、常见算法复杂度速查

| 算法 | 复杂度 | 一句话解释 |
|---|---|---|
| 线性搜索 `find` | O(n) | 最坏要翻遍整个容器 |
| 二分搜索 `binary_search` | O(log n) | 前提：已排序。每次排除一半 |
| 快速排序 `sort` | O(n log n) | 分治法：分 log n 层，每层处理 n 个元素 |
| 遍历所有元素 `for (auto x : v)` | O(n) | 每个元素访问一次 |
| 嵌套循环 | O(n²) | 两层循环各 n 次 → n×n |
| `count_if` | O(n) | 遍历一次，数符合条件的 |
| `find_if` + `sort` | O(n log n) | sort 主导（更慢的那一步决定总复杂度） |

## 七、三个实用技巧

### 1. 只关注最大项

```
O(n² + n + 100) → 写作 O(n²)  （当 n 很大时，n² 项碾压其他）
```

### 2. 忽略常数系数

```
O(2n)  → 写作 O(n)     （2 倍差距在算法分析中不算大事）
O(3n²) → 写作 O(n²)    （常数在 n 很大时不改变数量级）
```

### 3. 取最差那一步

当你串联多个操作时，复杂度由最慢的一步决定：
```
sort(v)    // O(n log n)
find(v, x) // O(n)
总复杂度 → O(n log n)   （sort 主导）
```

## 八、总结

> **复杂度告诉你：当数据量变大时，程序的运行时间会如何变化。**
>
> - O(1) 最好，n 变化不影响它
> - O(n) 还行，线性增长
> - O(n²) 危险，数据翻 10 倍它就慢 100 倍
> - 选容器的第一步：想清楚你最常做的是什么操作，查速查表挑复杂度最低的那个
