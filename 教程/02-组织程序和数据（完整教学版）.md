## 一、用函数组织计算

### 1.1 为什么需要函数？

> 把一段计算逻辑封装成一个函数，不是为了"炫技"，而是为了解决三个实际问题：**避免重复代码**（同样的成绩计算写 10 次）、**提高可读性**（函数名说清意图）、**便于修改**（改一处全项目生效）。

之前我们把计算逻辑直接写在 `main` 中：

```cpp
streamsize prec = cout.precision();
cout << "Your final grade is " << setprecision(3)
     << 0.2 * midterm + 0.4 * final + 0.4 * median
     << setprecision(prec) << endl;
```

用一个函数封装后：

```cpp
cout << "Your final grade is " << setprecision(3)
     << grade(midterm, final, median)
     << setprecision(prec) << endl;
```

更清晰，更易复用。

> **封装的好处**：`grade(midterm, final, median)` 用**函数名代替了具体计算公式**。读代码的人一眼就知道"哦，这里在算成绩"，而不用逐字分析那个数学表达式。如果将来成绩计算公式变了（比如期中占比改为 30%），只需要改 `grade` 函数一处地方。这就是"不要重复自己"（Don't Repeat Yourself, DRY）原则的体现。

### 1.2 运行示例：计算成绩的函数

```cpp
// 根据期中、期末和作业成绩计算最终成绩
double grade(double midterm, double final, double homework) {
    return 0.2 * midterm + 0.4 * final + 0.4 * homework;
}
```

> **这是最简单的函数形式：按值传参 + 返回计算结果。**
>
> ① **参数列表 `(double midterm, double final, double homework)`** — 声明了三个 `double` 类型的参数，调用者需要提供三个 `double` 值。参数名只在函数体内有效，不影响调用者的变量名。
>
> ② **按值传递的含义**：`midterm`、`final`、`homework` 是调用时传入的**实参的副本**。函数内部修改这些参数不会影响调用者的原始变量。这里没有修改需求，所以用按值传递是合理的。
>
> ③ **`return` 语句**：将计算结果返回给调用者。`return` 后函数立即结束——`return` 之后的代码不会执行。

<a id="13-查找中值的函数"></a>
### 1.3 查找中值的函数

> 这个函数引入了两个新概念：一是 `throw` 异常来处理错误情况（空容器），二是**按值传递的副作用**——函数内 `sort` 操作的是副本。

```cpp
// 计算 vector 的中值
// 注意：参数按值传递，函数内对 vec 的排序不影响调用者的原始数据
double median(vector<double> vec) {
    typedef vector<double>::size_type vec_sz;
    vec_sz size = vec.size();

    if (size == 0)
        throw domain_error("median of an empty vector");

    sort(vec.begin(), vec.end());
    vec_sz mid = size / 2;
    return (size % 2 == 0)
        ? (vec[mid] + vec[mid-1]) / 2
        : vec[mid];
}
```

`★ Insight ─────────────────────────────────────`
注意 `median` 的参数是 `vector<double> vec`（**按值传递**），不是引用。这意味着函数内对 `vec` 的 `sort()` 操作的是**拷贝**，不影响调用者的原始数据。三种函数参数形式的选择原则：
1. **按值传递 `T`** — 需要拷贝，不改变实参
2. **const 引用 `const T&`** — 不拷贝，不改变实参
3. **非 const 引用 `T&`** — 不拷贝，可改变实参
`─────────────────────────────────────────────────`

> **关于 `median` 函数的几个关键决策：**
>
> **为什么按值传递？** 因为我们需要在函数内对 `vec` 排序——但又不希望排序影响调用者的原始数据。按值传递自动拷贝一份，函数内随便排序，调用者的 vector 不受影响。代价是拷贝整个 vector 有性能开销（元素越多越明显）。如果数据量很大又不想拷贝，可以用另一种方式：传 `const` 引用，然后不排序直接计算中值（用 `nth_element` 算法）——但这个方案超出了本章范围。
>
> **为什么用 `throw` 而不是 `return` 一个特殊值（如 -1）？**
>
> | 方案 | 缺点 |
> |---|---|
> | `return -1` 表示错误 | 成绩可能是负数吗？无法区分"错误"和"合法负数" |
> | 设置全局错误标志 | 调用者可能忘记检查，错误被悄悄忽略 |
> | `throw` 异常 | **强制**调用者处理错误（否则程序终止），不污染返回值 |
>
> 异常的核心优势是：**错误处理不能被忽略**。如果 `median` 被调用时传入空 vector，没有 `try-catch` 包裹的话，程序会直接终止——好过带着错误数据继续运行产生错误结果。
>
> **`throw domain_error(...)` 的含义**：`domain_error`（定义在 `<stdexcept>` 中）表示"函数的输入参数不在合法范围内"。这里的意思是：空 vector 无法计算中值，属于"输入非法"。`what()` 成员函数返回你传入的描述字符串。

## 二、异常处理 `try-catch`

> 异常处理是 C++ 的错误报告机制。上一节的 `median` 函数用 `throw` 检测到错误并**抛出**，这一节用 `try-catch` 来**捕获**并处理它。异常的好处是：它像一根"电话线"，可以直接从出错的函数一路传到有能力处理错误的地方，跳过中间不需要关心错误的所有函数。

```cpp
vector<double> empty_vec;

// 捕获 domain_error 异常
try {
    if (empty_vec.empty())
        throw domain_error("vector is empty!");
    cout << "这行不会执行" << endl;  // throw 之后的代码永远不会运行
} catch (const domain_error& e) {
    cout << "捕获到异常: " << e.what() << endl;
}
```

> **异常的工作流程（逐点分析）：**
>
> ① **`try` 块开始**："我准备尝试执行一段可能出错的代码"。`try` 块中的代码正常执行——直到遇到 `throw` 或正常结束。
>
> ② **`throw domain_error("vector is empty!");`** ：抛出异常。这一行之后的 `try` 块内代码**全部跳过**——程序立即开始查找匹配的 `catch` 子句。这就是异常传播（exception propagation）。
>
> ③ **`catch (const domain_error& e)`** ：捕获匹配类型的异常。这里用 `const` 引用接收异常对象——避免多余的拷贝，同时 `what()` 返回的描述字符串是只读的。
>
> ④ **`e.what()`** ：返回 `throw` 时传入的字符串（这里是 `"vector is empty!"`）。`what()` 是 `std::exception` 定义的虚函数，所有标准异常类都实现了它。
>
> **如果没有 `try-catch` 包裹会怎样？**
> 异常会一直往上传播，直到 `main` 函数——如果 `main` 也没有 `catch`，程序调用 `std::terminate()` 直接终止。在调试器中会看到"Unhandled exception"或"terminate called after throwing an instance of..."。所以：**要么用 `try-catch` 处理异常，要么让程序终止**——没有"悄悄忽略"的选项。

| 关键字 | 说明 |
|---|---|
| `throw` | 抛出异常对象，程序停止在 throw 处 |
| `try { }` | 尝试执行可能产生异常的代码 |
| `catch(type e) { }` | 捕获特定类型的异常并处理 |
| `e.what()` | 获取异常的描述字符串 |

> **常见异常类型（来自 `<stdexcept>`）：**
>
> | 异常类型 | 含义 | 使用场景 |
> |---|---|---|
> | `domain_error` | 输入参数不在合法范围内 | 空容器求中值 |
> | `invalid_argument` | 参数值无效 | 传入负数给只能接受正数的函数 |
> | `out_of_range` | 索引越界 | `v.at(100)` 但 vector 只有 10 个元素 |
> | `runtime_error` | 运行时错误，无法归类到以上 | 文件打不开、网络连接失败 |
>
> 所有这些异常都继承自 `std::exception`，所以 `catch (const exception& e)` 可以捕获所有标准异常。

## 三、引用（Reference）

### 3.1 引用的基本概念

> 引用是一个变量的**别名**。它不是独立的对象——不分配独立的内存空间，**和被引用的变量共享同一块内存**。理解引用是理解后续引用参数、引用返回的基础。

```cpp
int original = 42;
int& ref = original;  // ref 是 original 的引用（别名）

ref = 100;  // 通过引用修改
original = 200;  // 通过原始变量修改
```

> **引用初始化（Reference Initialization）**：给引用"绑定"一个对象，让引用成为它的别名。**引用的初始化发生在定义的那一刻，且一生只能这一次。**
>
> ```cpp
> int a = 42;
> int& ref = a;    // ✅ 初始化：ref 绑定到 a，此后 ref 就是 a 的别名
>
> int& bad;        // ❌ 编译错误：引用必须初始化！没有"空引用"这种东西
> ```
>
> **什么可以初始化引用？什么不可以？**
>
> | 初始化值 | `T&`（非 const） | `const T&` |
> |---------|:---:|:---:|
> | 普通变量（左值）`int x = 5; int& r = x;` | ✅ | ✅ |
> | 字面量 `int& r = 42;` | ❌ | ✅ |
> | 表达式结果 `int& r = a + b;` | ❌ | ✅ |
> | 函数返回值 `int& r = f();` | ❌（除非 f 返回引用） | ✅ |
> | 不同类型 `double d = 3.14; int& r = d;` | ❌ | ✅ |
>
> **关键规则**：非 `const` 引用只能绑定到**左值**（有名字、有地址、能出现在赋值号左边的对象）。`const` 引用更宽容——可以绑定到临时对象。当 `const int& r = 42;` 时，编译器在幕后创建了一个隐藏的临时 `int` 变量（值为 42），然后把 `r` 绑定到它。
>
> ```cpp
> // const 引用的"魔法"：可以绑定临时对象
> const int& r1 = 42;               // ✅ 编译器创建临时 int(42)
> const string& r2 = "hello";       // ✅ 编译器创建临时 string("hello")
> const double& r3 = someInt + 3;   // ✅ 绑定到表达式结果的临时对象
> // 上面的代码本质上等价于：
> //   int __temp1 = 42;         const int& r1 = __temp1;
> //   string __temp2("hello");  const string& r2 = __temp2;
> ```
>
> **为什么引用必须初始化？** 因为引用不是独立对象——它不拥有自己的内存。引用本质上是它绑定的对象的另一个名字。就像一个人的绰号不能脱离这个人而存在，引用也不能脱离被引用的对象而存在。指针则不同：指针是独立对象，有自己的内存地址，所以可以先声明后赋值。
>
> **引用有三个关键规则：**
>
> ① **定义时必须初始化**：`int& ref;` 是编译错误——引用必须"认准"一个对象后才能存在。指针可以后来才赋值，但引用不行。
>
> ② **一旦绑定，不能改绑**：`int& ref = a; ref = b;` 不是让 `ref` 改绑到 `b`，而是把 `b` 的值赋给 `a`（通过 `ref` 这个别名）。引用从一而终。
>
> ③ **引用本身不占额外内存**：`ref` 和 `original` 在内存中是同一个地址。`&ref` 和 `&original` 得到相同的地址值。

### 3.2 引用作为函数参数

> 这是引用**最常用、最重要的场景**。引用参数可以避免拷贝大对象的开销，同时允许函数修改实参。这三种传参方式必须熟练掌握。

```cpp
// 引用参数：不复制 but 可以修改实参
void addOne(vector<int>& v) {
    for (auto& x : v) x += 1;
}

// const 引用参数：不复制，也不能修改
void print(const vector<int>& v) {
    for (auto x : v) cout << x << " ";
    cout << endl;
}
```

> **两种引用参数的区别：**
>
> **① `vector<int>& v` — 非 const 引用：不拷贝，可修改实参。** 适用于需要修改调用者数据的场景，如 `addOne` 要修改 vector 中的每个元素。**注意：调用者必须能接受"我的数据可能在函数里被改掉"这个事实。**
>
> **② `const vector<int>& v` — const 引用：不拷贝，不可修改实参。** 适用于"只读"场景，如 `print` 只需要查看元素。`const` 的保护让调用者放心：传给函数的 vector 不会被意外修改。
>
> ❌ **常见错误：给 const 引用传值但忘记了 `const`。** 如果你写 `void print(vector<int>& v)` 且只是打印，但调用时传了一个常量：`const vector<int> cv = {1,2,3}; print(cv);`——编译器会报错，因为非常量引用不能绑定到常量对象。正确的做法是用 `const vector<int>& v`。

### 3.3 返回引用的函数

> 返回引用的函数有一个独特的性质：**函数调用可以出现在赋值号的左边**。这称为"左值"（lvalue）返回。

```cpp
// 返回数组中第 index 个元素的引用
int& element(int a[], int index) {
    return a[index];  // 返回引用，不是值的拷贝！
}

int arr[] = {0, 2, 4, 6, 8};
element(arr, 3) = 22;  // 赋值给引用 = 直接修改数组元素！
```

`★ Insight ─────────────────────────────────────`
返回引用的函数让函数调用可以出现在**赋值号的左边**——`element(arr, 3) = 22` 直接修改了数组元素。但**绝对不能返回局部变量的引用**：函数返回后局部变量已销毁，引用将悬空（dangling reference）。
`─────────────────────────────────────────────────`

> **为什么 `element(arr, 3) = 22` 可以工作？**
> `element(arr, 3)` 返回的是 `a[3]` 的引用（即 `arr[3]` 的别名）。`= 22` 通过这个引用修改了 `arr[3]`。所以最终 `arr[3]` 从 6 变成了 22。
>
> **绝对不能做的事：返回局部变量的引用。**
>
> ```cpp
> int& bad_function() {
>     int local = 42;
>     return local;  // ❌ 危险！local 在函数退出时就被销毁了
> }                  // 返回的引用指向已释放的内存（悬空引用）
>
> int& ref = bad_function();
> cout << ref;  // 未定义行为：可能打印 42，可能打印垃圾值，可能崩溃
> ```
>
> **安全的返回引用场景：**
> - 返回通过**参数传入**的对象的引用（如 `element` 返回数组元素）
> - 返回类的数据成员的引用（后续章节的类设计中常见）
> - 返回全局变量或静态变量的引用

### 3.4 引用 vs 指针

> 引用和指针都提供了"间接访问"的能力，但语言设计哲学不同。引用是"安全的别名"，指针是"灵活但危险的地址"。

| | 引用 `T&` | 指针 `T*` |
|---|---|---|
| 初始化 | **必须**在定义时初始化 | 可以后赋值 |
| 重新绑定 | 不能 | 可以 |
| 空值 | 不存在空引用 | 有 `nullptr` |
| 语法 | 像普通变量 | 需要 `*p` 解引用 |
| 引用的引用 | 没有 | 有 `T**` |

> **引用 vs 指针的选择原则：**
>
> - **能用引用的地方就用引用**——语法更简洁，没有空值风险，更安全。
> - **需要"可空"语义时用指针**——比如函数的参数可以是"可选"的，传入 `nullptr` 表示"没有"。
> - **需要重新绑定时用指针**——引用从一而终，指针可以随时指向不同对象。
> - **实现动态多态**（后续章节）——用指针对容器存储多态对象，引用在函数参数中传递多态对象。
>
> 总的来说：引用是"语法糖"更浓的指针——C++ 底层用指针实现引用，但编译器替你做了 nullptr 检查和自动解引用。

## 四、函数重载（Overload）

> **名字相同，参数不同——编译器根据实参自动选择正确的版本。** 函数重载让同一个操作名可以作用于不同类型的参数，代码更自然。比如 `grade` 函数可以接受一个作业值或一组作业值，但都叫 `grade`，调用时根据参数判断用哪个版本。

```cpp
// 重载版本1：传入单个 homework 值
double grade(double midterm, double final, double homework) {
    return 0.2 * midterm + 0.4 * final + 0.4 * homework;
}

// 重载版本2：传入 homework 的 vector
double grade(double midterm, double final, const vector<double>& hw) {
    if (hw.empty())
        throw domain_error("student has done no homework");
    // 计算平均值
    double sum = 0;
    for (double x : hw) sum += x;
    return grade(midterm, final, sum / hw.size());  // 调用版本1
}
```

> 函数重载：**名字相同，参数不同**（个数或类型）。编译器根据调用时的实参自动选择正确的版本。

> **为什么这个例子选择重载而非不同名字？**
> 如果起不同名字：`grade_with_one_score` 和 `grade_with_vector`——调用者需要记住两个函数名，而且意图（"算成绩"）是相同的。用重载，调用者只需要记住 `grade` 这一个名字，编译器根据传递的参数决定用哪个版本。
>
> **重载的匹配规则：**
>
> | 调用方式 | 匹配哪个版本 | 理由 |
> |---|---|---|
> | `grade(mid, fin, 90.0)` | 版本 1 | 三个 `double` 参数 |
> | `grade(mid, fin, homework_vec)` | 版本 2 | 第三个参数是 `vector<double>` |
>
> **版本 2 内部调用了版本 1**：`return grade(midterm, final, sum / hw.size());`——`sum / hw.size()` 是 `double` 类型，所以匹配到版本 1。这是重载的常见模式：一个"高级"版本做一些预处理后调用"低级"版本。
>
> **重载不能通过返回类型区分**：下面的代码会编译失败——
> ```cpp
> int foo();
> double foo();  // ❌ 错误：重载不能只靠返回类型区分
> ```
> 编译器只看参数列表（个数、类型、顺序）来判断是否重载。返回类型不算。

## 五、结构体：组织相关数据

> 在之前，一个学生的信息分散在多个变量中——`name`、`midterm`、`final`、`homework` 是独立的。如果有 10 个学生，就用 10 组变量——很快会混乱。**结构体（`struct`）** 将这些相关的数据聚合为一个**用户自定义的类型**，代表一个"学生"的整体概念。

```cpp
// 将学生的所有相关数据组织在一起
struct Student_info {
    string name;
    double midterm, final;
    vector<double> homework;
};

Student_info s;
s.name = "Alice";
s.midterm = 85;
s.final = 90;
s.homework = {95, 88, 92, 90, 87};

// 结构体数组
vector<Student_info> students;
students.push_back(s);

Student_info s2 = {"Bob", 78, 85, {80, 82, 88}};
students.push_back(s2);
```

> **`struct` 解决了什么问题？**
>
> ① **数据打包**：以前是 4 个独立变量 `name`、`midterm`、`final`、`homework`，现在是 1 个 `Student_info` 对象。函数只需要传一个参数就能传递学生的所有信息。
>
> ② **批量管理**：`vector<Student_info>` 可以存储任意数量的学生——这在之前是不可想象的。
>
> **结构体的初始化方式总结：**
>
> | 方式 | 示例 | 说明 |
> |---|---|---|
> | 成员赋值 | `s.name = "Alice";` | 逐个赋值 |
> | 花括号初始化（聚合初始化） | `Student_info s2 = {"Bob", 78, 85, {80, 82, 88}};` | 按成员声明顺序一一对应 |
>
> **为什么不直接用四个数组（`string names[]` + `double midterms[]` + ...）？**
> 因为这需要维护**四个数组的索引一致性**——删除第 3 个学生，要删四个数组的第 3 个元素。`Student_info` 把数据合在一起，vector 中删除一个元素即可，不会有"索引对不齐"的问题。

## 六、分文件编译

### 6.1 为什么要分文件？

> 随着程序变大，把所有代码塞进一个 `main.cpp` 会变得难以管理。分文件编译的核心理念是**分离接口与实现**：头文件（`.h`）放声明——告诉别人"我能做什么"；源文件（`.cpp`）放实现——包含"具体怎么做"。

- 每个文件可以**独立编译**，修改一个模块不需要重编译全部
- 接口（`.h` 头文件）与实现（`.cpp` 源文件）**分离**
- 大型程序组织的基础

> **编译过程简要说：**
>
> ```
> 预编译 → 编译（每个 .cpp 独立编译为 .o 文件）→ 链接（合并所有 .o 文件为可执行文件）
> ```
>
> 分文件编译的核心优势在于：如果你只改了一个 `.cpp` 文件，只需要重新编译那个文件，然后重新链接即可。对于有几十、几百个源文件的项目，这能节省大量时间。

### 6.2 运行示例：三个文件协同工作

> 下面演示的是**分文件最基本的形态**：一个函数（`median`）被分离到头文件和源文件中，`main` 只包含头文件就能调用它。

以下是一个完整的分文件编译示例。在 MPE 中，我们可以将多个文件的内容合并在一个代码块中编译运行：

```cpp
// ===== median.h =====
#ifndef GUARD_median_h
#define GUARD_median_h
double median(vector<double> vec);
#endif

// ===== median.cpp =====
double median(vector<double> vec) {
    typedef vector<double>::size_type vec_sz;
    vec_sz size = vec.size();
    if (size == 0)
        throw domain_error("median of an empty vector");
    sort(vec.begin(), vec.end());
    vec_sz mid = size / 2;
    return (size % 2 == 0)
        ? (vec[mid] + vec[mid-1]) / 2
        : vec[mid];
}
```

> **头文件（`.h`）只放声明，不放实现**——这是一个重要的规则。`median.h` 只有一行 `double median(vector<double> vec);`，告诉编译器"存在一个叫 `median` 的函数，接受 `vector<double>`，返回 `double`"。编译器看到这个声明就知道怎么调用它了，不需要看到具体实现。
>
> **源文件（`.cpp`）包含实现，同时也要包含自己的头文件**——这确保头文件中的声明和源文件中的实现签名一致。如果改了参数类型但忘了更新头文件，编译器会报不匹配的错误——这是一个重要的安全检查。

### 6.3 头文件保护符

> 头文件保护符防止"同一个头文件被多次包含"——这是分文件编译中最容易忽视但又至关重要的细节。

```cpp
#ifndef GUARD_median_h  // 如果 GUARD_median_h 未定义
#define GUARD_median_h  // 就定义它

// 头文件内容 ...

#endif  // 结束条件编译
```

> **为什么需要头文件保护符？**
>
> 考虑这个场景：
> - `grade.h` 中 `#include "median.h"`（因为 `grade` 函数需要调用 `median`）
> - `main.cpp` 中同时 `#include "grade.h"` 和 `#include "median.h"`
>
> 没有头文件保护，`median.h` 的内容会被展开**两次**——重复声明 `median` 函数会导致编译错误。保护符确保：第二次遇到 `#ifndef GUARD_median_h` 时，`GUARD_median_h` 已经定义过了，跳过整个文件内容。
>
> **本项目约定格式为 `GUARD_xxx_h`**（如 `GUARD_CORE`、`GUARD_Student_info`）。

### 6.4 文件清单

> 在实际项目中，把所有 `.cpp` 文件一起编译：

```bash
# 列出所有 .cpp 文件一起编译
g++ main.cpp Student_info.cpp median.cpp grade.cpp -o student.exe
```

> **为什么只编译 `.cpp` 文件，不编译 `.h` 文件？** 因为 `.h` 文件的内容通过 `#include` 被展开到 `.cpp` 文件中——编译 `.cpp` 时已经把需要的 `.h` 都处理了。`.h` 文件是"被包含的"，不是"被编译的"。
>
> **如果项目有 100 个源文件，每次都这样敲一遍？**
> 不会——实际项目使用**构建工具**（Makefile、CMake、IDE 的构建系统）来自动管理编译依赖和增量编译。但原理都是一样的：列出所有 `.cpp` 文件，分别编译为 `.o` 目标文件，然后链接为可执行文件。

项目文件组织：

| 文件 | 角色 |
|---|---|
| `median.h` | 声明 `median()` 函数 |
| `median.cpp` | 实现 `median()` 函数 |
| `Student_info.h` | 声明 `Student_info` 结构体和相关函数 |
| `Student_info.cpp` | 实现 `read()`、`compare()` 等函数 |
| `grade.h` | 声明 `grade()` 函数系列 |
| `grade.cpp` | 实现各重载版本 |
| `main.cpp` | 主程序入口 |

## 七、第二周总结

| 知识点 | 说明 |
|---|---|
| **函数** | 封装逻辑，复用代码 |
| **`throw` / `try` / `catch`** | 异常处理机制 |
| **引用 `T&`** | 别名，不拷贝，可修改原始对象 |
| **`const T&`** | 不拷贝，也不可修改——高效的只读传参 |
| **函数重载** | 同名不同参，编译器自动匹配 |
| **`struct`** | 组织相关数据为用户自定义类型 |
| **头文件 `.h`** | 声明接口；用 `#ifndef` 守卫防止重复包含 |
| **源文件 `.cpp`** | 包含实现，独立编译 |

### 三种函数形参模式速查

| 形参 | 拷贝？ | 修改实参？ | 适用场景 |
|---|---|---|---|
| `T param` | ✓ | ✗ | 小对象，需要在函数内修改副本 |
| `const T& param` | ✗ | ✗ | 大对象，只读访问（最常用） |
| `T& param` | ✗ | ✓ | 需要修改实参，或作为"输出"参数 |

> **选择口诀**：
> - **小且简单**（`int`、`double`、`char`）：按值传 `T`
> - **大且只读**（`vector`、`string`）：`const T&`
> - **需修改实参**：`T&`
>
> 记住：**传 `const T&` 是最"安全"的只读传参——既避免了拷贝开销，又保证了数据不被修改。**
